## 2. Current state snapshot

- `main`: editor codebase (Tauri 2 + TypeScript + TipTap), version 0.2.0. R-C3 holds on every exit path; R-C2 holds across ten list shapes with one recorded exception; R-C13 is uniform — a bare URL stays text whether pasted, typed or opened from a file; links are created only through explicit UI, with schemes allow-listed on both creation and following.
- **The image area is closed for now.** `assets/` is created by the save flow (#45); consent is asked once per folder and only an agreement is remembered (#66); a document just given a destination says once that it is waiting for a save (#48); identity is content, never name (#52); one gesture asks once and inserts all of its images, in order (#68), up to **128 MB** of source bytes (#71). Every exit of an insert reports **one outcome** (#61), a cancellation the user made being a different kind from a refusal the application made — the distinction the gesture loop turns on. What remains open in the area is small and narrow: #65, #51, #46, #58.
- **R-C14 does not exist in the build.** `saveMarkdown` writes unconditionally — no `mtime`, no hash, no prompt — while REQUIREMENTS, CLAUDE.md and CONTRIBUTING.md all state it as an invariant, the last of those telling outside contributors that a PR violating it will not merge. Filed as **#55**, blocking for publication, and now the top of the agenda.
- **Drag & drop has never worked on the Windows build** (#65). `dragDropEnabled` has never been set in `tauri.conf.json` and Tauri v2 defaults it to `true`, so Tauri replaces WebView2's drag-drop handler and the webview receives no HTML5 `drop` event. Not a regression, invisible to every test since it works on the web build. **Standing consequence**: every image change since #63 is verified on Windows through paste only, and the drop half of each stays unverified until #65 lands.
- Statusbar shows all three counts (R-C12); **About** reports version and build commit (Q5), matching the artifact it was built from.
- CI: `ci.yml` (Linux checks, Windows build, docs-only path gating, `pipeline-ok`, Windows installer as a 7-day PR artifact), `nightly.yml` (Windows-only, activity guard), `release.yml` (`v*` tags, full matrix incl. macOS). Measured installer size: **2.57 MB**, inside Q1. Five known gaps: no timeouts (#47), no cache `restore-keys` (#53), `vite.config.ts` anchored to the working directory (#41), a docs-only merge still running the full build on `main` (#57), and a PR artifact named after the merge commit while WORKFLOW.md says that means it is the wrong build (#64).
- **`CONTRIBUTING.md`, `SECURITY.md`, `LICENSE` and `.github/FUNDING.yml` all exist** — confirmed against the tree on 2026-08-19, having been assumed absent in planning until then.
- **The README is inaccurate in three places** and needs a pass before anyone reads it: the reset note points at issue #5 for a conversion that landed on 2026-08-14 via #7 and #10; *"Coming next"* lists predictable paste, shipped in #21; and Prerequisites ask for Node 22 while CI validates on Node 20.
- Branch protection: `protect-main` — PR-only, squash-only, restrict deletions, block force pushes, head branches auto-deleted, **`Pipeline OK` required** (confirmed against the active ruleset, 2026-08-19). Whether the ruleset behaves as intended against a **fork** pull request once the repository is public is a separate, open question — #20 §F.
- Working model: owner (decisions, testing, releases) + AMP (requirements, issues, review, this file) + DEV (Claude Code sessions). No dedicated OPS role — §5, 2026-08-15. English for everything on GitHub.
- History: pre-reset history in the private `agented-archive`; `git bundle` backup taken 2026-08-14.

## 4. Decision debt / open items

- **Multi-tab editing — four questions, none technical, all blocking the issue.**
  1. **Tabs or windows?** R-C8 already promises multiple isolated windows. Tabs are a second model of multiplicity on top of the first: do they coexist, or replace it?
  2. **Is the unsaved-changes gate per tab or global?** Closing a window with three tabs, two modified — one question or two?
  3. **What is a session?** Do tabs reopen on launch? If so, that is the first state AgentEd persists about the user's work, which touches the "no vault, no account" promise directly.
  4. **Does the sidebar follow the active tab**, or stay on the folder that was opened?
- **#51 — is `assets/` consent per document, or per folder for as long as the app is open?** Both are defensible and only one is written down. If per folder wins, R-C5 says so and #51 closes without code.
- **#65 — which shape.** Disabling Tauri's native drag-drop hands the gesture to the existing, tested plugin for one line of configuration; listening to `onDragDropEvent` gives real filesystem paths but adds a second insert entry point and puts OS integration in front of a flow that has none, which the parked PWA target would have to route around. DEV's to argue, with the effect on macOS and Linux checked rather than assumed.
- **Who tests an outside contributor's PR** — #20 §G, to be decided at the gate rather than now.
- **Image naming for files that arrive with a name**: kept as-is (sanitized) by R-C5. The owner may still prefer document-derived names for everything — a one-line change.
- **#4** — unreproducible on the post-reset build; closes at the gate as resolved-by-removal unless it reappears.
- **Retry versus fast failure on `apt-get`** — DEV's judgement in #47, now with a third option: stop depending on the mirror that fails.
- Release numbering at first public release: continue 0.2.x or restart at 1.0.
- `.github/ISSUE_TEMPLATE/` and CODE_OF_CONDUCT — #20 §D.

## 5. Milestone log (newest first)

- **2026-08-20 — A gesture is bounded (#74, closing #71), and the scope correction that came with it matters more.**
  The fix: 128 MB of source bytes per gesture, what fits lands, the rest is refused with a message naming both counts. Worth keeping is that DEV **measured the premise instead of inheriting it** — the "an image costs about twice its size" claim had sat in a comment since before the reset and nobody had checked it; it came out at 1.94×–2.18× across three gesture shapes. And 128 rather than a rounder number for a concrete reason: five files at the per-file cap are 125 MB, so at 128 the two bounds agree instead of contradicting each other.
  **The correction.** One real defect (#68) produced three issues, and two of them — **#73** (progress feedback) and **#75** (a document-level ceiling) — were written from possibilities rather than observations. Both closed as out of scope on the owner's call. A gesture large enough for either to matter is not a use a markdown editor serves; and since the gate decision made issues public, a list full of speculative memory deliberations reads as misplaced priorities rather than as rigour — especially beside #55, which has been sitting untouched.
  **The rule that follows, and it binds the next session**: an observation becomes an issue only when an ordinary user meets it on an ordinary path, or when it breaks a promise this project has written down. Everything else is a note in the handover file, not a public thread. AMP treated *"I noticed something"* as *"something must be opened"* three times in one hour.
  Also recorded: **#74's manual pass was skipped**, by owner decision, on the grounds that the scenario it exercises is outside the product's utility. The ordinary paths the same code touches — a single paste, three images — are covered by the suite and by everyday use. Noted here rather than left to memory, because the first question after any future defect in this area is whether a human ever exercised the build.
- **2026-08-19 — One gesture, all of its images (#70, closing #68).** Both handlers hand the whole gesture to `insertImageGesture`, which awaits each insert in turn: the first file settles the destination and the folder consent, and the rest find both already answered.
  **The design argument was better than the one the brief asked for.** Sequencing beat pre-settling the consent because the **destination picker has the same shape one step earlier**, so one `await` fixes both. And the loop needed no new vocabulary: a cancellation the *user* made ends the gesture, a refusal the *application* made concerns one file — already two kinds on the #61 contract.
  **Three things came free**: the `requestSaveAs` question was **dissolved rather than deferred** (exactly one Save As per gesture); **#52's deduplication now works inside a gesture**, where two concurrent inserts of the same picture each checked the registry before the other had registered; and images land in gesture order. Also named in review: a thrown error now ends the gesture rather than one file.
- **2026-08-19 — Cancel means "not this image" (#67, closing #66) — and the measurement taken alongside it was worth more than the fix.** A refusal is no longer remembered; the agreement still is, and R-C5 gives the reason for the asymmetry so nobody restores the symmetry later as a tidy-up.
  **The finding.** DEV measured the multi-image gesture on `main` first and then on the branch — identical numbers, which is what makes "not a regression" a fact — and both were worse than predicted. `showConfirmDialog` refuses a concurrent dialog and returns `null`, which `confirmAssetsDir` cannot tell from a user pressing Cancel, so images two and three of a paste were dropped **whichever button the user pressed** and reported as `cancelled` — the one outcome the app layer is deliberately quiet about. **AMP's reading was wrong in its prediction and right in its target**: it had said the gesture would ask *several times*. Recorded rather than quietly edited away.
- **2026-08-19 — An insert now reports one outcome for every exit (#63, closing #61).** The contract lives in `src/editor/image-insert-outcome.ts`, the words in `src/app/image-insert-report.ts`, and the silence on a user cancellation is a branch with its reasoning in it rather than an omission. The outcome is **pushed, not returned**, because `void handleImageFile(...)` is where a returned value dies, and the parameter is **required**, which turned "should report" into "cannot compile without reporting".
  **Then the Windows pass earned its place again**, with two findings neither reachable by CI: drag & drop has never worked on Windows (#65), and a cancelled `assets/` folder disabled images for the rest of the document (#66).
- **2026-08-19 — The silence around a refused image insert, decided as one thing** (#61). Three issues filed from three separate investigations described one structural gap: `handleImageFile` had a declared success channel and no failure channel, so three unrelated causes left through a single silent `return`. Decided: one outcome per insert, distinguishing a cancellation the *user* made from a refusal the *application* made. Rejected: fixing the message inside each issue, and a shared message module with the control flow unchanged — a branch that calls nothing is still silent by omission.
  **Also decided: an unreadable `assets/` folder refuses the insert** rather than proceeding with a name it cannot verify. R-C5 gains its clause in #58's own PR.
- **2026-08-19 — Identity is content, never name (#56, closing #52).** The same picture inserted twice is stored once and referenced twice; two different pictures that want one name are both kept, the second suffixed.
  **The risk was never the feature.** A deduplication keyed on names destroys one of two different pictures, silently, and the tests for that row were written before the code. The review went looking for the one asymmetry that would have been fatal: a deliberately case-insensitive comparison whose older counterpart, had it stayed case-sensitive, would have let Windows merge `Diagram.png` and `diagram.png`. That case is **unreachable by CI**, which runs on a case-sensitive filesystem. DEV also caught a fixture this change would have quietly drained.
- **2026-08-19 — The gate audited against the tree, and three of its statements were wrong.** `CONTRIBUTING.md`, `SECURITY.md`, `LICENSE` and `FUNDING.yml` all already exist — including an item AMP had added to #20 that same morning asking for `CONTRIBUTING.md` to be written, added without looking at the repository.
  **The finding that matters is #55.** R-C14 is asserted in REQUIREMENTS, in CLAUDE.md's non-negotiable list, and in CONTRIBUTING.md's quality bars. `saveMarkdown` writes unconditionally.
- **2026-08-19 — A named destination now says it is not yet a save (#50, closing #48).** The debt #45 contracted: before it, choosing a destination produced at least an `assets/` folder, and removing that left the insert flow with no visible feedback at all.
