## 2. Current state snapshot

- `main`: editor codebase (Tauri 2 + TypeScript + TipTap), version 0.2.0. R-C3 holds on every exit path; R-C2 holds across ten list shapes with **fourteen recorded exceptions** (loose lists; single-tilde strikethrough; unsafe link destinations; mixed line endings; a blank line at either end of the document; five table spellings AgentEd cannot hold; soft line breaks; backslash hard breaks; a fence's trailing blank line, and the same reading where that blank line is the whole content; an escape the file did not have, added at a text-node boundary; a code span's delimiter run written at the shortest width that still closes it; two overlapping marks having exactly one nesting; a redundant escape not preserved where AgentEd no longer writes one; a number that opens an *inline element* at the start of a heading or a cell keeping its backslash) and **one difference tracked as an issue rather than accepted**, measured: a list item whose whole body is a block loses its bullet (#110). R-C13 is uniform.
- **A fence alone in a container survives too** (#104, merged as #109). A container holding nothing but a blank child is blank itself, so the blank rule replaced the whole of it and the blockquote or list item left the file with the fence. The lever the issue proposed was **measured and found closed** — turndown's `meaningfulWhenBlank` is a module-private array, not exported and not on the service — so the fix rests on something else: `replacementForNode` **processes a node's children before it consults the rule for the node**, so a blank container arrives with its content already written. One condition over that: a blank container whose children wrote nothing keeps the empty string; one whose children wrote something is handed to the rule that would have written it had it never been blank. **Every container delegates** — turndown's own `blockquote` and `list`, this repository's `listItem` and `taskListItem` — and the split between the two list-item rules has to be made by hand, because rule precedence is what keeps their filters apart and a blank node never reaches the rule array. **It does not multiply with nesting**: one delegation per level, no recursion. The condition is written about the **content** rather than about the fence, which is the general statement of the defect.
- **The editor-level round-trip guard exists** (#84, merged as #107), and it is the standing regression net the blind spot had been asking for since #42. `src/editor/roundtrip.test.ts` runs every shape the pair-level suite covers, plus the nine #84 owned, through `createEditor` + `setMarkdown` + `getMarkdown`, and the **twelve markdown documents of this repository through the real save assembly**. Its form is argued: plain byte equality cannot work while recorded exceptions exist, so **fixtures** carry exact expected bytes plus the exception they belong to — failing on a regression *and* on an unannounced fix — while **documents** are held to #96's property unconditionally and what the first save may change must be erasable by one of a few **named normalisers**, one per recorded exception; a difference no normaliser can erase **fails and prints itself**. Two floors, the visible text and the list of link destinations, are asserted independently, which caught a normaliser drawn too widely during development. **Proven to fail three ways**, not only to pass. **Its blind spot is now named**: it watches bytes, so configuration, chrome and anything that never reaches the file are outside it by construction.
- **A code span no longer cancels a mark** (#84, merged as #107). The shipped `code` mark carries `excludes: '_'`, so a text node could not hold `code` and any other mark: a bold run was split around a span in the document model before turndown existed, and a mark whose whole extent was the span was **dropped** — ``[`c`](url)`` lost its destination out of the file, a visible loss rather than a respelling. Narrowing `excludes` alone was measured and rejected, because `code` then outranked `italic`, `strike` and `underline` and those marks landed *inside* the backticks, where tildes stop being markup; so the mark is also ranked innermost. **The link half is not fixed and is recorded**: ProseMirror's marks are flat, two overlapping marks have exactly one nesting, and changing the rank moves which spelling survives rather than making room for both.
- **A fenced block with nothing in it survives the save** (#94, merged as #103). It used to be removed — opening fence, closing fence and language with it — while the block stayed on screen and nothing reported anything, so the user found out on the next open. **`addRule` cannot reach it**: turndown replaces every blank node before it consults a rule, which is why the levers that fixed #85 and #97 were unavailable and `blankReplacement` is the hook, documented, and effective only when passed at construction. The override is narrow **structurally**: everything that is not a fenced block is handed to turndown's own default blank rule, read off a service of its making rather than restated. **The layer was established by measurement before any code** — TipTap keeps the block and its language, so nothing was lost upstream. **It is kept wherever the block is reached, and it is not reached when its whole container is blank** — #104.
- **A table is written the way the file wrote it** (#93, merged as #101). `formatMarkdownTable` used to pad every cell out to a uniform width whatever the file used — 628 of the 631 bytes by which an untouched save grew `README.md`, and all 488 of `WORKFLOW.md`. Minimal cells everywhere would have removed those bytes and moved the same exception onto every hand-aligned table, so the spelling is **preserved**: read from the raw markdown on open, because `marked` trims every cell before the HTML exists, and carried **per table, on the table node** rather than on `DocumentBundle` — so Save As, `resetDocument` and copy-paste need no wiring and nothing can be half-wired. **A carried width is a floor, not a size**: an edited cell widens its column, an added column takes the width its content needs. Three decisions on measurements: per table over per document (91% of 1628 tables byte-exact against 76%); **hugged cells as the default**, which overturned the assumption in the issue body that padded is what most tooling produces (86% of the corpus); and refusal of a corrupt style **per table, not per column**, because a bad separator says nothing about whether the widths beside it are right and the widths are what alignment is made of.
- **A numbered heading no longer gains a backslash** (#97, merged as #99). Turndown's escape table holds `[/^(\d+)\. /g, '$1\\. ']`, so `## 1. Product statement` was written back as `## 1\. Product statement` on every save; `REQUIREMENTS.md`, which has **ten** numbered headings, came back with ten escaped full stops it never had. **The escape matters exactly where a list can begin**: a heading and a GFM table cell take inline content only, so the backslash there is noise, while a paragraph, a blockquote body and a list-item body host block content and without it `1990. It was a good year.` comes back as an ordered list starting at 1990. The fix is therefore at the **heading rule** — delegating to turndown's built-in one, so `headingStyle` and everything else stay turndown's business — and at **`cellContent`**, whose recursive call serializes a cell as a paragraph. `escape.ts` is untouched: it is handed a string and no node, and for the same reason a pass over the finished markdown cannot tell a heading's `1\.` from a paragraph's.
- **The residue is recorded, with its constraint named.** A number that opens an *inline element* at the start of a heading or a cell keeps its backslash — `## **1. Bold** thing`, emphasis and links alike, and the same shapes inside a cell. The escape can only be withheld at the **start of the content**, because that is where turndown's rule puts it; reaching further in would mean rewriting `N\.` anywhere in the assembled string, which would corrupt the one place those two characters are the user's own — inside a code span. Recorded rather than opened as an issue (§0): rendering is identical, nothing is lost, the file holds still after the first save. **`options.rules` is undocumented where `escape` is not**, and turndown ships no types, so `BuiltinRules.heading` is declared optional and the delegation is guarded — a future shape change fails at module load with a named cause rather than as a blank application.
- **Intraword underscores are no longer escaped** (#90, merged as #96). `turndown.escape` is overridden by assignment — a public method, so no internals are touched — withholding `_` runs that have word characters on both sides via a Private Use Area sentinel and delegating everything else to the original method, which stays the authority on every other character. One sentinel per character, so length and offsets survive turndown's `^`-anchored rules; a document already holding the sentinel makes the narrowing step aside entirely. **`*` is deliberately not treated the same way**: CommonMark *allows* intraword emphasis with it, so that escape is load-bearing where the `_` one is noise.
- **A soft line break is a space, never nothing** (#89, merged as #92). Between two text characters a break always collapsed to a space; between two inline *elements* it was **deleted**, and ProseMirror then merged the adjacent text carrying identical marks. `setMarkdown` now parses the HTML with ProseMirror's own `DOMParser` and hands `setContent` a `Node`, which it returns untouched — TipTap's `elementFromString`, whose `removeWhitespaces` strips any text node that is exactly a newline at every depth, is off the open path for good. **The open path and the paste path share the DOM parser but not the markdown reading**: `breaks: true` for paste, `false` for open, deliberately, and the call site says so — pasted lines are the only structure the user copied, while a file's author chose where the paragraphs are.
- **Strikethrough survives the save** (#85, merged as #88). One turndown rule for `s`/`del`/`strike`; single-tilde `~x~` is written back as `~~x~~` and R-C2 says so. Three strike-plus-other-mark shapes re-nest through the editor and are pinned as #84's.
- **Line conventions are preserved** (#79, merged as #86). How a file's lines end and whether its last line is terminated are read from the text on disk — before any splitting, the same text the R-C14 baseline comes from — carried on the document, and re-applied once to the assembled text in `saveMarkdown`; that text is what is written *and* what becomes the next baseline, so a second save raises no dialog. Out of serialization entirely. Conventions belong to the document, not the path: kept through Save As, reset by `resetDocument`. **Owner decisions**: a document never read from disk is written `\n` with a final newline; an empty document is an empty file.
- **Relative links exist** (#42, merged as #83). The link dialog accepts a relative path and stores every scheme-less address **exactly as typed** — the implied `https://` from #40 is gone, because `README.md` and a web host are the same shape. `Link.configure({ isAllowedUri })` shares the classification with the dialog, so `parseHTML`, `renderHTML` and `setLink` agree; it widens TipTap's allow-list by relative paths and narrows it by nothing, delegating to `defaultValidate` for the rest. For `data:` and `blob:` hrefs that delegation is the **only** thing that drops the mark — DOMPurify admits both through the parse regex — which is now recorded in R-C2 as a deliberate exception and pinned in `link-relative.test.ts`.
- **R-C14 exists** (#55, merged as #77). Before overwriting a file the editor already knows, AgentEd compares its **whole text** against what it last read from it or wrote to it, and on a mismatch asks **reload / overwrite / save-as**. `PlatformIO` gained `readSnapshot`, answering `file` / `absent` / `unreadable` as three different things — *"I could not tell"* is never delivered as *"nothing changed"*. The web build makes the same promise.
- **All three image routes exist** (#65, merged as #80). Drag & drop had never worked on Windows: `dragDropEnabled` was never set, Tauri v2 defaults it to `true` and registers its own drag-drop target over the webview, so no HTML5 `drop` event was delivered. One line of window configuration hands the gesture to the plugin the web build already used. A `src-tauri` test pins that line, since a JSON file cannot carry a comment and its removal fails silently on a target CI cannot exercise.
- **The window never navigates away from the document.** With drops reaching the webview, a drop the page does not handle is a **navigation** — the application replaced by the contents of a dropped `.zip`, unsaved work gone, no gate in front of it (R-C3). `src/app/drop-guard.ts` arranges the nothing rather than inheriting it: `defaultPrevented` is the whole protocol, so it never inspects a payload, never stops propagation, and cannot take a drop from a handler that wanted it — including one not yet written. Installed on both targets, because the hazard is the webview's.
- **Images are otherwise settled.** `assets/` is created by the save flow (#45); consent is asked once per folder, and **that agreement belongs to the folder rather than to the document it was won in** — it outlives an Open and a New and ends with the window (#51, merged as #115); only an agreement is remembered, never a refusal (#66); a destination says once that it is waiting for a save (#48); identity is content, never name (#52); one gesture asks once and inserts all of its images in order (#68), up to 128 MB (#71). Every exit of an insert reports **one outcome** (#61), and since #46 there are **four kinds**: a fourth, `unavailable`, **speaks** like a refusal because nobody has told the user anything, and **ends the gesture** like a cancellation because the cause belongs to the document and its environment rather than to one file. Since #125 closed #58, nothing in the image area is open.
- **A document the guard reads now starts the job that runs it** (#118, merged as #120, proven on #121). `src/editor/roundtrip.test.ts` runs the repository's own documents through the real save assembly, so **documentation is part of the code test surface** — and the path filter from #113, an allow-list of code paths, had no way to know. A second filter output, `guarded_docs`, names the eight documents that live outside `src/` and widens the gate on the **frontend job only**: nothing a document changes can reach Rust or Windows, so the saving #113 measured stays where it was expensive. Named one by one rather than as `docs/**`, because **five of the eight are at the repository root** and a directory pattern reaches neither them nor only them. The two lists cannot be derived from one another — one is TypeScript raw imports inside a test module, the other is YAML read by an action before that code exists — so `.github/workflows/ci.test.ts` reads **both** and fails when they disagree in either direction, and fails when its own parse of the guard finds nothing, which is the mutation that matters most: without it a rename would make every other assertion pass over an empty list.
- **The web build can hold images too** (#46, merged as #123). The destination step is offered on every platform, and on web that step is what *grants* the folder access, so offering it is what makes the rest possible — `pickSavePath` calls the directory picker straight after the save picker. `PlatformIO.canWriteCompanions(documentPath)` answers whether a companion can be written **right now**, which `supportsMultiFile` could not: that one is a constant, `true` in both implementations. It takes the document path because **only the platform knows what its own paths look like** — a bare name is malformed on desktop and ordinary on web — so the two rejections `resolveAssetsDir` used to make moved into `TauriIO` rather than vanishing, and the app layer never branches on `isTauri`. It is asked **after** the destination step in all three call sites, since asking earlier would answer about an access the step is about to grant. **The browser requirement is in §7 of REQUIREMENTS**, not in R-C5: `openFile` and `pickSavePath` rest on the same API, so it belongs to the whole web build rather than to images.
- **A folder that cannot be read is not an empty folder** (#58, merged as #125). `takenNames` caught a failed `listDir`, warned to the console and returned only this session's claims, so `buildImageName` handed back a name a file on disk already held and the save wrote over it — **one failed read producing both wrong answers**, *no file has this name* and *no file holds these bytes*, about a folder nobody read. The failed read is now settled by a **second question** rather than by reading the error: `listDir` failed, `exists` says whether the folder is nonetheless there, which is the two-step `readSnapshot` has used since #55 and a fact `resolveAssetsDir` was already computing one call earlier and discarding. That choice is what makes the part nobody could test harmless — on the desktop build the error text is written by the operating system and translated into its language, so a check that parsed it would work in one locale and fail silently in the next. **The defect was reproduced on Windows, in the shipping product**, by an accidental pass of the manual script on the pre-fix build: with `assets/` denied a read, images were inserted with **no message at all** and written into the folder the application could not read, under names it had never checked.
- **And the same change made the opposite promise fail one layer over, for one hour** (#126, merged as #129). `WebIO.exists` answered a boolean, and #58 leaned it toward *something may be there* so that an unreadable `assets/` folder could not pass for an empty one. That was right for one caller out of **five**, and the wrong direction for the three that read the same primitive as a **positive assertion**: with a revoked grant the indicator named **six** canonical context files that are not there, and opening one handed the editor the document already open under the invented name. **The direction was never the defect; having a direction at all was.** `entryPresence` replaces it with `present` / `absent` / `unknown` and **never rejects**, so a failure is one of its answers and no caller can be written that forgets to handle it. **Replacing the name rather than adding a method beside it is load-bearing**, and was argued from a measurement rather than from taste: a three-state answer left under `exists` would keep `if (await io.exists(p))` compiling and permanently true — a non-empty string is truthy — at exactly the two call sites the review had missed by reading one module instead of searching. Removing the name is what puts the question to every caller, and `tsc` clean is the proof that none was left compensating. It also closed two silent exits nobody had filed: on the desktop build `exists` was `fsExists` with nothing around it and neither `resolveAssetsDir` nor `shouldShowSidebar` caught anything, so a raising probe took the whole insert out through the `void` call in the drop and paste plugins. **#127 is untouched by design.**

- **A read that did not happen no longer answers with the open document** (#127, merged as #134). `readText` and `readBinary` both fell back to the handle of the document already open whenever `resolveFileHandle` answered `null` — which it does on **every** failure, not only on not-found — so `applyBundle` set `filePath` and the R-C14 baseline from another file, and the user was looking at their own document under an invented name. **R-C14 was not the mitigation the issue implied**: it asks in two branches of three, and the branch with **no** dialog — the file genuinely gone, which is the ordinary sync-client case — wrote a new file under the invented name holding another document, with nothing asked anywhere. Where it did ask, it asserted a history that never happened and offered three buttons none of which can be read from where the user stands; that goes by construction, since it said the wrong thing because the identity was wrong. **The rule was already in the file twice and both copies were wrong in the same way**: they compared basenames, so `assets/notes.md` matched a document called `notes.md` — the clobber one of them has a comment claiming to prevent, unreachable only because a guard elsewhere refuses a path with a folder in it. `grantedFileFor` compares the whole path and all four sites delegate to it. Web-only, established by search: `TauriIO` holds no instance state to fall back to.
