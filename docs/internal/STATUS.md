## 2. Current state snapshot

- `main`: editor codebase (Tauri 2 + TypeScript + TipTap), version 0.2.0. R-C3 holds on every exit path; R-C2 holds across ten list shapes with **six recorded exceptions** (loose lists; single-tilde strikethrough; unsafe link destinations; mixed line endings; trailing blank lines; table padding) and **three unrecorded ones**, all measured: inline marks are re-nested around links and split around inline code (#84); a soft line break between two inline elements is deleted, and soft line breaks in general are written as spaces (#89); `_` and backticks are escaped where CommonMark needs no escape (#90); R-C13 is uniform.
- **Strikethrough survives the save** (#85, merged as #88). One turndown rule for `s`/`del`/`strike`; single-tilde `~x~` is written back as `~~x~~` and R-C2 says so. Three strike-plus-other-mark shapes re-nest through the editor and are pinned as #84's.
- **Line conventions are preserved** (#79, merged as #86). How a file's lines end and whether its last line is terminated are read from the text on disk — before any splitting, the same text the R-C14 baseline comes from — carried on the document, and re-applied once to the assembled text in `saveMarkdown`; that text is what is written *and* what becomes the next baseline, so a second save raises no dialog. Out of serialization entirely. Conventions belong to the document, not the path: kept through Save As, reset by `resetDocument`. **Owner decisions**: a document never read from disk is written `\n` with a final newline; an empty document is an empty file.
- **Relative links exist** (#42, merged as #83). The link dialog accepts a relative path and stores every scheme-less address **exactly as typed** — the implied `https://` from #40 is gone, because `README.md` and a web host are the same shape. `Link.configure({ isAllowedUri })` shares the classification with the dialog, so `parseHTML`, `renderHTML` and `setLink` agree; it widens TipTap's allow-list by relative paths and narrows it by nothing, delegating to `defaultValidate` for the rest. For `data:` and `blob:` hrefs that delegation is the **only** thing that drops the mark — DOMPurify admits both through the parse regex — which is now recorded in R-C2 as a deliberate exception and pinned in `link-relative.test.ts`.
- **R-C14 exists** (#55, merged as #77). Before overwriting a file the editor already knows, AgentEd compares its **whole text** against what it last read from it or wrote to it, and on a mismatch asks **reload / overwrite / save-as**. `PlatformIO` gained `readSnapshot`, answering `file` / `absent` / `unreadable` as three different things — *"I could not tell"* is never delivered as *"nothing changed"*. The web build makes the same promise.
- **All three image routes exist** (#65, merged as #80). Drag & drop had never worked on Windows: `dragDropEnabled` was never set, Tauri v2 defaults it to `true` and registers its own drag-drop target over the webview, so no HTML5 `drop` event was delivered. One line of window configuration hands the gesture to the plugin the web build already used. A `src-tauri` test pins that line, since a JSON file cannot carry a comment and its removal fails silently on a target CI cannot exercise.
- **The window never navigates away from the document.** With drops reaching the webview, a drop the page does not handle is a **navigation** — the application replaced by the contents of a dropped `.zip`, unsaved work gone, no gate in front of it (R-C3). `src/app/drop-guard.ts` arranges the nothing rather than inheriting it: `defaultPrevented` is the whole protocol, so it never inspects a payload, never stops propagation, and cannot take a drop from a handler that wanted it — including one not yet written. Installed on both targets, because the hazard is the webview's.
- **Images are otherwise settled.** `assets/` is created by the save flow (#45); consent is asked once per folder and only an agreement is remembered (#66); a destination says once that it is waiting for a save (#48); identity is content, never name (#52); one gesture asks once and inserts all of its images in order (#68), up to 128 MB (#71). Every exit of an insert reports **one outcome** (#61). What remains open is narrow: #51, #46, #58.
- Statusbar shows all three counts (R-C12); **About** reports version and build commit (Q5).
- CI: `ci.yml` (Linux checks, Windows build, docs-only path gating, `pipeline-ok`, Windows installer as a 7-day PR artifact), `nightly.yml`, `release.yml`. Measured installer size: **2.57 MB**, inside Q1. - **2026-08-20 — #42 re-read before briefing, and it was not the issue it had been five days earlier.** Two things had moved. First, the body's criterion *"`notes.md` is written unchanged"* collided with the courtesy #40 had meanwhile added — a bare host gets `https://` — and `README.md` is indistinguishable from a host by shape (`.md` is a real TLD), so the most common relative link in this repository would have become `https://README.md`, silently. **Owner decision: an address with no scheme is written exactly as typed.** No implied `https://`, ever; a `www.`-only exception was considered and rejected as a second rule rather than a convenience. The courtesy was an implementer's choice in #40, not an owner request, so nothing is reversed.
  Second, **a defect found by measurement**: `@tiptap/extension-link` 2.27.2 builds its `isAllowedUri` regex in a template literal, where `\-` is not an escape, so `[^a-z+.-:]` contains the range `.-:` — which covers `/`. Any scheme-less link whose first label is followed by `/` (`docs/guide.md`, `docs/ADR/…`) is refused at parse, render and `setLink`. Reproduced with a real `Editor` built from the same extension: open a file containing `[here](docs/guide.md)`, save it unedited, and the destination is gone. An R-C2 violation on an ordinary path — `CLAUDE.md` has such links — and the second undocumented exception after #79. It escaped the suite because the round-trip tests bypass TipTap and every editor-level link test uses `https://`. **Folded into #42 rather than split** (the #74 rule): one configuration point, `Link.configure({ isAllowedUri })`, fixes both halves, and widening the dialog without it would have produced a new silence — `setLink` returning `false` after the dialog closed. - **2026-08-20 — Drop works on Windows (#80, closing #65), and R-C5's three routes all exist for the first time.** `dragDropEnabled` had never been set; Tauri v2 defaults it to `true` and registers its own drag-drop target over the webview, so no HTML5 `drop` event had ever been delivered and the plugin #63 and #70 both drive in tests could not fire. The frontend was correct all along — which is why the web build worked and no test ever saw it. **The test surface and the shipped target disagreed, and only a human on Windows could tell.**
  **The fix is one line; the work was everything around it.** With drops finally reaching the webview, **a drop the page does not handle is a navigation** — the window replaced by the contents of a dropped `.zip`, an unsaved document gone, no gate in front of it (R-C3). Two independent gaps allowed it, both in the DOM rather than in our code: outside the editing surface nothing cancels `dragover`, so no drop is dispatched at all; on it, prosemirror-view's fallback gives up *without* cancelling, because `parseFromClipboard` answers `null` for a transfer carrying neither text nor HTML. So *"a non-image drop does nothing"* stopped being the status quo and became something the code has to arrange.
  `drop-guard.ts` arranges it, and the design property is worth keeping: **`defaultPrevented` is the entire protocol.** The guard listens on the window in the bubble phase, reads that flag, never inspects the payload and never stops propagation — so it is structurally incapable of taking a drop away from a handler that wanted it, including one nobody has written yet. A guard that sniffed file types would need editing the day a dropped `.md` becomes a feature.
  **DEV broke an acceptance criterion deliberately and was right.** *"The web build is unchanged"* was AMP's wording; installing the guard on both targets breaks it. The hazard belongs to the webview, not the desktop shell, and a platform branch would have meant knowingly leaving one build able to lose an unsaved document to a stray drag. Flagged in the PR rather than quietly satisfied — the behaviour wanted from a DEV session, and better than shipping the worse product the criterion asked for.
  The cross-platform claim was read from the pinned sources and then **verified independently in review** against neighbouring versions: the handler always returns `true`, which on macOS means `Bool::YES` instead of forwarding to `super`, on Linux stops the GTK signal emission, and on Windows pairs `SetAllowExternalDrop(false)` with `RegisterDragDrop`.
  **A debt settled**: every image change since #63 had been verified on Windows through paste only. This pass exercised the drop half of #52, #63, #67, #70 and #74 for the first time.
  **Looked at and decided against**: `dragover` is cancelled window-wide, so a file dragged over the header or sidebar shows a copy cursor and dropping there does nothing. Confirmed by the owner on the pass and judged not worth acting on — the failure is self-correcting, unlike the silences #13 legislated against: the user drags again, slightly inward, and it works. The better answer, if it ever matters, is not an honest cursor but a window-wide drop that inserts; that is a product change, not a cursor tweak.
