## 2. Current state snapshot

- `main`: editor codebase (Tauri 2 + TypeScript + TipTap), version 0.2.0. R-C3 holds on every exit path; R-C2 holds across ten list shapes with one recorded exception and one **unrecorded** one (#79); R-C13 is uniform.
- **R-C14 exists** (#55, merged as #77). Before overwriting a file the editor already knows, AgentEd compares its **whole text** against what it last read from it or wrote to it, and on a mismatch asks **reload / overwrite / save-as**. `PlatformIO` gained `readSnapshot`, answering `file` / `absent` / `unreadable` as three different things — *"I could not tell"* is never delivered as *"nothing changed"*. The web build makes the same promise.
- **All three image routes exist** (#65, merged as #80). Drag & drop had never worked on Windows: `dragDropEnabled` was never set, Tauri v2 defaults it to `true` and registers its own drag-drop target over the webview, so no HTML5 `drop` event was delivered. One line of window configuration hands the gesture to the plugin the web build already used. A `src-tauri` test pins that line, since a JSON file cannot carry a comment and its removal fails silently on a target CI cannot exercise.
- **The window never navigates away from the document.** With drops reaching the webview, a drop the page does not handle is a **navigation** — the application replaced by the contents of a dropped `.zip`, unsaved work gone, no gate in front of it (R-C3). `src/app/drop-guard.ts` arranges the nothing rather than inheriting it: `defaultPrevented` is the whole protocol, so it never inspects a payload, never stops propagation, and cannot take a drop from a handler that wanted it — including one not yet written. Installed on both targets, because the hazard is the webview's.
- **Images are otherwise settled.** `assets/` is created by the save flow (#45); consent is asked once per folder and only an agreement is remembered (#66); a destination says once that it is waiting for a save (#48); identity is content, never name (#52); one gesture asks once and inserts all of its images in order (#68), up to 128 MB (#71). Every exit of an insert reports **one outcome** (#61). What remains open is narrow: #51, #46, #58.
- Statusbar shows all three counts (R-C12); **About** reports version and build commit (Q5).
- CI: `ci.yml` (Linux checks, Windows build, docs-only path gating, `pipeline-ok`, Windows installer as a 7-day PR artifact), `nightly.yml`, `release.yml`. Measured installer size: **2.57 MB**, inside Q1. Five known gaps: no timeouts (#47), no cache `restore-keys` (#53), `vite.config.ts` anchored to the working directory (#41), a docs-only merge still running the full build on `main` (#57), and a PR artifact named after the merge commit while WORKFLOW.md says that means it is the wrong build (#64).
- **Third-party licences audited 2026-08-20** (recorded on #20): 77 npm packages and 402 Rust crates resolved and read. No GPL, nothing that touches the MIT licence on our own code. The obligation that stands is attribution — licence notices must accompany the binary — and a licence check in CI would make it a standing guard rather than a snapshot.

- **The README is inaccurate in three places** and needs a pass before anyone reads it: the reset note points at issue #5 for a conversion that landed via #7 and #10; *"Coming next"* lists predictable paste, shipped in #21; and Prerequisites ask for Node 22 while CI validates on Node 20.

## 5. Milestone log (newest first)

- **2026-08-20 — Drop works on Windows (#80, closing #65), and R-C5's three routes all exist for the first time.** `dragDropEnabled` had never been set; Tauri v2 defaults it to `true` and registers its own drag-drop target over the webview, so no HTML5 `drop` event had ever been delivered and the plugin #63 and #70 both drive in tests could not fire. The frontend was correct all along — which is why the web build worked and no test ever saw it. **The test surface and the shipped target disagreed, and only a human on Windows could tell.**
  **The fix is one line; the work was everything around it.** With drops finally reaching the webview, **a drop the page does not handle is a navigation** — the window replaced by the contents of a dropped `.zip`, an unsaved document gone, no gate in front of it (R-C3). Two independent gaps allowed it, both in the DOM rather than in our code: outside the editing surface nothing cancels `dragover`, so no drop is dispatched at all; on it, prosemirror-view's fallback gives up *without* cancelling, because `parseFromClipboard` answers `null` for a transfer carrying neither text nor HTML. So *"a non-image drop does nothing"* stopped being the status quo and became something the code has to arrange.
  `drop-guard.ts` arranges it, and the design property is worth keeping: **`defaultPrevented` is the entire protocol.** The guard listens on the window in the bubble phase, reads that flag, never inspects the payload and never stops propagation — so it is structurally incapable of taking a drop away from a handler that wanted it, including one nobody has written yet. A guard that sniffed file types would need editing the day a dropped `.md` becomes a feature.
  **DEV broke an acceptance criterion deliberately and was right.** *"The web build is unchanged"* was AMP's wording; installing the guard on both targets breaks it. The hazard belongs to the webview, not the desktop shell, and a platform branch would have meant knowingly leaving one build able to lose an unsaved document to a stray drag. Flagged in the PR rather than quietly satisfied — the behaviour wanted from a DEV session, and better than shipping the worse product the criterion asked for.
  The cross-platform claim was read from the pinned sources and then **verified independently in review** against neighbouring versions: the handler always returns `true`, which on macOS means `Bool::YES` instead of forwarding to `super`, on Linux stops the GTK signal emission, and on Windows pairs `SetAllowExternalDrop(false)` with `RegisterDragDrop`.
  **A debt settled**: every image change since #63 had been verified on Windows through paste only. This pass exercised the drop half of #52, #63, #67, #70 and #74 for the first time.
  **Looked at and decided against**: `dragover` is cancelled window-wide, so a file dragged over the header or sidebar shows a copy cursor and dropping there does nothing. Confirmed by the owner on the pass and judged not worth acting on — the failure is self-correcting, unlike the silences #13 legislated against: the user drags again, slightly inward, and it works. The better answer, if it ever matters, is not an honest cursor but a window-wide drop that inserts; that is a product change, not a cursor tweak.
- **2026-08-20 — R-C14 exists (#77, closing #55), and the gate loses its only non-deferrable blocker.** Before overwriting a file it already knows, AgentEd compares the file's **whole text** against what it last read or wrote, and asks reload / overwrite / save-as. Three documents that promised this now describe the product.
  It began with a **platform primitive**, because `PlatformIO` could not observe a file's state at all: `readSnapshot` answers `file` / `absent` / `unreadable` as three different things.
  **Content over `mtime`, decided by the false-positive direction.** The obvious argument is that a timestamp misses a change made by a tool that preserves it. The argument that decides is the other one: a timestamp **invents** conflicts for a sync client that rewrote identical bytes — and this dialog is met on the ordinary path, on every save.
  **The reload/gate loop was resolved as one dialog** that names what each button costs, with R-C14 amended in the same PR. Two things worth keeping: the baseline is the text that was *read*, never one re-derived from the parsed bundle — `splitFrontmatter` + `assembleMarkdown` is not byte-exact for a CRLF document with frontmatter, so a re-derived baseline would have put the dialog in front of the user's very first save, found by making the code re-derive and watching the test fail. And the close path stays safe only because `createDiscardGate` ends with `return !ctx.state.modified` instead of trusting the `handleSave` it just called — a pre-existing decision now load-bearing for a feature written months later, which a future *"handleSave should return a boolean"* tidy-up would quietly remove.
- **2026-08-20 — A gesture is bounded (#74, closing #71), and the scope correction that came with it matters more.** 128 MB of source bytes per gesture; DEV **measured the premise instead of inheriting it**, and 128 was chosen so the gesture bound and the per-file cap stop contradicting each other.
  **The correction.** One real defect (#68) produced three issues, and two — #73 and #75 — were written from possibilities rather than observations. Both closed as out of scope. **The rule that follows**: an observation becomes an issue only when an ordinary user meets it on an ordinary path, or when it breaks a promise this project has written down. Everything else is a note in the handover file. Also recorded: #74's manual pass was skipped by owner decision.
- **2026-08-19 — One gesture, all of its images (#70, closing #68).** Sequencing beat pre-settling the consent because the **destination picker has the same shape one step earlier**. The loop needed no new vocabulary: a cancellation the *user* made ends the gesture, a refusal the *application* made concerns one file — already two kinds on the #61 contract. Three things came free: the `requestSaveAs` question dissolved rather than deferred, **#52's deduplication now works inside a gesture**, and images land in gesture order.
- **2026-08-19 — Cancel means "not this image" (#67, closing #66) — and the measurement taken alongside it was worth more than the fix.** DEV measured on `main` first and then on the branch — identical numbers, which is what makes "not a regression" a fact — and found that `showConfirmDialog` refuses a concurrent dialog and returns `null`, indistinguishable from a user pressing Cancel, so images two and three of a paste were dropped **whichever button the user pressed**. **AMP's reading was wrong in its prediction and right in its target**; recorded rather than quietly edited away.
