## 2. Current state snapshot

- `main`: editor codebase (Tauri 2 + TypeScript + TipTap), version 0.2.0. R-C3 holds on every exit path; R-C2 holds across ten list shapes with one recorded exception and one **unrecorded** one — see §4; R-C13 is uniform.
- **R-C14 exists** (#55, merged as #77). Before overwriting a file the editor already knows, AgentEd compares its **whole text** against what it last read from it or wrote to it, and on a mismatch asks **reload / overwrite / save-as**. `PlatformIO` gained `readSnapshot`, which answers `file` / `absent` / `unreadable` as three different things — *"I could not tell"* is never delivered as *"nothing changed"*. The web build makes the same promise, not a lesser one.
- **The image area is closed for now.** `assets/` is created by the save flow (#45); consent is asked once per folder and only an agreement is remembered (#66); a destination says once that it is waiting for a save (#48); identity is content, never name (#52); one gesture asks once and inserts all of its images in order (#68), up to 128 MB (#71). Every exit of an insert reports **one outcome** (#61). What remains open is narrow: #65, #51, #46, #58.
- **Drag & drop has never worked on the Windows build** (#65). `dragDropEnabled` has never been set in `tauri.conf.json` and Tauri v2 defaults it to `true`, so Tauri replaces WebView2's drag-drop handler and the webview receives no HTML5 `drop` event. Not a regression, invisible to every test since it works on the web build. **Standing consequence**: every image change since #63 is verified on Windows through paste only, and the drop half of each stays unverified until this lands.

Measured installer size: **2.57 MB**, inside Q1. Five known gaps: no timeouts (#47), no cache `restore-keys` (#53), `vite.config.ts` anchored to the working directory (#41), a docs-only merge still running the full build on `main` (#57), and a PR artifact named after the merge commit while WORKFLOW.md says that means it is the wrong build (#64).
- **Third-party licences audited 2026-08-20** (recorded on #20): 77 npm packages and 402 Rust crates resolved and read. No GPL, nothing that touches the MIT licence on our own code. The obligation that stands is attribution — licence notices must accompany the binary — and a licence check in CI would make it a standing guard rather than a snapshot. ## 4. Decision debt / open items

- **The CRLF exception.** Opening a **CRLF document that has frontmatter** and saving it with no edits rewrites its fence line endings to LF (`splitFrontmatter` drops the `\r`, `assembleMarkdown` re-emits `\n`). Reported by #77, pre-existing and unrelated to it. REQUIREMENTS is explicit that *"an undocumented exception is a defect"*, so this is either fixed or recorded as a known exception — **owner's call whether it becomes an issue.** A Windows user editing a file made by a Windows tool is the ordinary case.
- **Multi-tab editing — four questions, none technical, all blocking the issue.**
  1. **Tabs or windows?** R-C8 already promises multiple isolated windows. Do they coexist, or replace it?
  2. **Is the unsaved-changes gate per tab or global?** Closing a window with three tabs, two modified — one question or two?
  3. **What is a session?** Do tabs reopen on launch? That would be the first state AgentEd persists about the user's work, which touches the "no vault, no account" promise.
  4. **Does the sidebar follow the active tab**, or stay on the folder that was opened?
- **#51 — is `assets/` consent per document, or per folder for as long as the app is open?** If per folder wins, R-C5 says so and #51 closes without code.
- **#65 — which shape.** One line of window configuration hands the gesture to the existing, tested plugin; `onDragDropEvent` gives real filesystem paths but adds a second insert entry point and puts OS integration in front of a flow that has none, which the parked PWA target would have to route around.
- **Third-party licence notices** — bundled with the installer or kept in the repository and linked from About; Q1 is the trade-off. #20.
- **Who tests an outside contributor's PR** — #20 §G, at the gate.
- **Image naming for files that arrive with a name**: kept as-is (sanitized) by R-C5; the owner may still prefer document-derived names for everything.
- **#4** — unreproducible on the post-reset build; closes at the gate as resolved-by-removal unless it reappears.
- **Retry versus fast failure on `apt-get`** — DEV's judgement in #47.
- Release numbering at first public release: continue 0.2.x or restart at 1.0.

## 5. Milestone log (newest first)

- **2026-08-20 — R-C14 exists (#77, closing #55), and the gate loses its only non-deferrable blocker.** Before overwriting a file it already knows, AgentEd compares the file's **whole text** against what it last read or wrote, and asks reload / overwrite / save-as. Three documents that promised this — REQUIREMENTS, CLAUDE.md's invariants, and CONTRIBUTING.md's quality bars, which tell outside contributors a PR violating it will not merge — now describe the product rather than an intention.
  It began with a **platform primitive**, because `PlatformIO` could not observe a file's state at all: `readSnapshot` answers `file` / `absent` / `unreadable` as three different things, so *"I could not tell"* is never delivered as *"nothing changed"*.
  **Content over `mtime`, decided by the false-positive direction.** The obvious argument is that a timestamp misses a change made by a tool that preserves it. The argument that decides is the other one: a timestamp **invents** conflicts for a sync client that rewrote identical bytes or merely touched the file — and this dialog is met on the ordinary path, on every save. A prompt that is wrong once a day would make the feature hated in a week.
  **The reload/gate loop was resolved as one dialog** that names what each button costs, because the gate's Save returns to the conflict that raised it and its Discard asks the same question in vaguer words. R-C14 was amended in the same PR to say so — the requirement moving with the code that changed it.
  **Two things worth keeping.** The baseline is the text that was *read*, never one re-derived from the parsed bundle: `splitFrontmatter` + `assembleMarkdown` is not byte-exact for a CRLF document with frontmatter, so a re-derived baseline would have put this dialog in front of the user's very first save — found by making the code re-derive and watching the test fail, rather than by arguing. And the close path stays safe only because `createDiscardGate` ends with `return !ctx.state.modified` instead of trusting the `handleSave` it just called; that pre-existing decision is now load-bearing for a feature written months later, and a future *"handleSave should return a boolean"* tidy-up would quietly remove it.
- **2026-08-20 — A gesture is bounded (#74, closing #71), and the scope correction that came with it matters more.** 128 MB of source bytes per gesture, what fits lands, the rest is refused with a message naming both counts. DEV **measured the premise instead of inheriting it** — the "an image costs about twice its size" claim had sat in a comment since before the reset — and 128 was chosen so the gesture bound and the per-file cap stop contradicting each other.
  **The correction.** One real defect (#68) produced three issues, and two of them — #73 and #75 — were written from possibilities rather than observations. Both closed as out of scope. **The rule that follows, and it binds the next session**: an observation becomes an issue only when an ordinary user meets it on an ordinary path, or when it breaks a promise this project has written down. Everything else is a note in the handover file. Also recorded: #74's manual pass was skipped by owner decision, on the grounds that the scenario it exercises is outside the product's utility.
- **2026-08-19 — One gesture, all of its images (#70, closing #68).** Both handlers hand the whole gesture to `insertImageGesture`, which awaits each insert in turn. Sequencing beat pre-settling the consent because the **destination picker has the same shape one step earlier**, so one `await` fixes both. The loop needed no new vocabulary: a cancellation the *user* made ends the gesture, a refusal the *application* made concerns one file — already two kinds on the #61 contract. Three things came free: the `requestSaveAs` question dissolved rather than deferred, **#52's deduplication now works inside a gesture**, and images land in gesture order.
- **2026-08-19 — Cancel means "not this image" (#67, closing #66) — and the measurement taken alongside it was worth more than the fix.** DEV measured the multi-image gesture on `main` first and then on the branch — identical numbers, which is what makes "not a regression" a fact — and found that `showConfirmDialog` refuses a concurrent dialog and returns `null`, which `confirmAssetsDir` could not tell from a user pressing Cancel. Images two and three of a paste were dropped **whichever button the user pressed**. **AMP's reading was wrong in its prediction and right in its target**; recorded rather than quietly edited away.
- **2026-08-19 — An insert now reports one outcome for every exit (#63, closing #61).** The contract lives in `src/editor/image-insert-outcome.ts`, the words in `src/app/image-insert-report.ts`, and the silence on a user cancellation is a branch with its reasoning in it rather than an omission. The outcome is **pushed, not returned**, because `void handleImageFile(...)` is where a returned value dies, and the parameter is **required**.
  **Then the Windows pass earned its place again**, with two findings neither reachable by CI: drag & drop has never worked on Windows (#65), and a cancelled `assets/` folder disabled images for the rest of the document (#66).
- **2026-08-19 — The silence around a refused image insert, decided as one thing** (#61). Three issues from three separate investigations described one structural gap: a declared success channel and no failure channel, so three unrelated causes left through a single silent `return`. Decided: one outcome per insert, distinguishing a cancellation the *user* made from a refusal the *application* made. Also decided: an unreadable `assets/` folder refuses the insert rather than proceeding with a name it cannot verify.
- **2026-08-19 — Identity is content, never name (#56, closing #52).** The review went looking for the one asymmetry that would have been fatal: a deliberately case-insensitive comparison whose older counterpart, had it stayed case-sensitive, would have let Windows merge `Diagram.png` and `diagram.png`. That case is **unreachable by CI**, which runs on a case-sensitive filesystem.
