# AgentEd — Product Requirements

**Version**: 1.0 — approved by the owner on 2026-08-14. This document defines the simplified AgentEd after the August 2026 reset; any future change goes through a PR on this file.
**Supersedes**: all prior requirement documents, ADR-001..034 (archived in the private `agented-archive` repository).

---

## 1. Product statement

AgentEd is an **easy-to-use WYSIWYG markdown editor**. Open any `.md` file and edit it the way you'd expect in 2026 — no syntax in your face, no vault, no account, no cloud. A small, fast, native binary that respects your files and never claims ownership of your folders.

Quietly, in the background, AgentEd also acknowledges that a growing share of markdown is read by AI models before it is read by people — and offers lightweight instrumentation for that: a live token count.

**Priority order when requirements conflict**: (1) ease of use → (2) speed & lightness → (3) AI-era instrumentation.

## 2. Core requirements — the editor

- **R-C1 WYSIWYG editing.** Inline formatting with no visible markdown syntax; floating toolbar on selection; markdown input rules (`#`+space → heading, `-`+space → list, ``` followed by a space or Enter → code block — optionally with a language between them, `[ ]` → task list, etc.); tables, task lists, code blocks and images edited visually. Numbered lists must number correctly across the document (see D1 in §10). **Links are made explicitly** — floating-toolbar button, `Ctrl+K`, or pasting a URL over a selection — with the same dialog changing or removing an existing one; `Ctrl`/`Cmd`+click follows a link in the system browser, while a plain click places the caret, because clicking inside a document you are editing must stay safe. **A link address is a web address (`http`, `https`, `mailto`) or a relative path to a neighbouring file (`./notes.md`, `docs/guide.md`, `#section`), and it is written exactly as typed** (#42) — no scheme is ever implied, because a bare host and a neighbouring file are indistinguishable by shape and the common case in a markdown editor is the file; a relative link is never handed to the operating system. **An inline mark and a code span coexist** (#84): a mark may span a code span, cover one exactly, or cover part of one — a file may spell all three, so the editor holds all three. Covering *part* of a span is the one shape CommonMark cannot write as a single span, so it is written as adjacent spans instead (`` `c`**`od`**`e` ``): nothing is lost, re-reading gives the same document, and the file holds still afterwards. **Owner decision, 2026-08-24**, taken on the #84 branch build with the gesture in front of him: the gesture stays available rather than being refused in the editor — it is reachable only by selecting inside a span deliberately, and refusing it would cost a rule to explain for a case that already behaves. Pinned by `NAMED CASE` in `src/editor/mark-nesting.test.ts`. **The shape of a table is edited from the Table section of the menu** (#292): a row is added above or below the caret or deleted, a column is added before or after it or deleted, and the whole table is removed — seven routes, and which seven was decided by what a GFM table can spell and read back rather than by what the extension offers. **A column takes its alignment and its padded width with it**, so a column inserted or deleted no longer changes what the columns beside it mean — measured before it: `addColumnBefore` at the first column of a table written `| :--- | :---: | ---: |` wrote `| :--- | :---: | ---: | --- |`, the file holding still while it rendered differently. The one table this does not reach is one that has **no spelling of its own** and inherits a neighbour's, where the alignment still shifts; it is recorded on #292 rather than repaired here, because moving it means writing an attribute onto a table the file never spelled. **A row is not added above the header row and the header row is not deleted**, and both entries are greyed there: GFM requires a header, so the file would otherwise be given the new row *as* its header, or promote the first body row — in both cases a document the editor never showed. Inside a table in a cell that refusal is stricter than it needs to be, which is accepted rather than special-cased (**owner decision, 2026-09-17**). **Merging and splitting cells, turning a header row, column or cell on and off, and column widths are not offered at all**: GFM spells none of them, and the three header toggles were measured being discarded in silence — the editor shows the change, the file keeps what was removed. **An entry with nothing to do is greyed rather than silent**, and which ones are is computed from the document rather than from `editor.can()`, which answers `true` on the last row and the last column where the command then refuses. **A selection can be a node rather than a stretch of text** — an image or a horizontal rule, the two a click can select — **and two commands refuse one**: inline code and the fenced block (#427, owner decision of 2026-09-23). Measured on `8934c82`, each took a selected image out of the document in one press: inline code wrote the image markdown as literal text inside a code span and the fenced block left an empty fence, by five routes between them — the two toolbar buttons, `Ctrl+E`, `Ctrl+Shift+K` and **Edit** → **Insert Code Block**. So the refusal is at the two commands rather than at the bar, since hiding the buttons alone would have left the chords and the menu entry doing it with no visible control left to connect the loss to. The bar then **does not draw those two for a node selection** and the menu entry greys, the rule it already keeps for a control that cannot act — cosmetic agreement once the commands refuse, rather than the repair. Every other control stays drawn: what they write around an image is a legitimate change, and nothing else was measured taking the picture out.
- **R-C2 Clean round-trip.** Bidirectional serialization: the file saved is plain, portable markdown; open→save with no edits must not alter the file. **A round trip is the document, not only the file: a save followed by an open gives back the same constructs in the same places. A file that holds still while a construct turns into its own text breaks this promise as much as a file that moves** (#300). **A file's line conventions are part of that promise** (#79): how its lines end (`\r\n` or `\n`) and whether the last line is terminated are properties of the file, read when AgentEd opens it and re-applied to the whole text when AgentEd writes it — a document written on Windows stays a Windows file, and a file that ended with a newline still does. **A byte order mark is a property of the file in exactly the same way** (#259): a file that began with one is written back with it, a file that did not is never given one, and neither is a choice the user is asked to make. It is carried rather than recorded as an exception below, because it is read and re-applied at the same boundary the line conventions are and it never enters the document model — so it costs none of what the exceptions cost. A document that was never read from disk — **New**, or **New from Template** — is written with `\n` and a final newline. **A list keeps the spacing the file gave it** (#28): a loose list — blank lines between its items, bullet, ordered or task alike — is written back loose, and a tight one tight, per list rather than per document. The spelling is read from the raw markdown on open, because `marked` answers CommonMark's question rather than the file's — it wraps an item body in `<p>` both when blank lines separate the items and when any one item holds more than one block — and it rides on the list node, so it survives editing, Save As and copy-paste. A list created in the editor is tight. **A list also keeps the marker the file wrote it with** (#431): `*`, `+` or `-` for a bullet list, `.` or `)` after the number for an ordered one, carried on the list node the way its spacing is and read from the same token. Before this, every list was written back with `-` or with `.` from one serializer option, so `* one` came back `- one` and `1) one` came back `1. one` on every save, with nothing recorded about either. **For two lists side by side that lost a document rather than a spelling**: a marker change is the one thing in markdown that keeps two adjacent lists of the same kind apart, so writing both with `-` made them one list, and the blank line between them then made it one *loose* list, so the second save wrote four items a blank line apart and the file settled only on the third - which is the one thing every recorded exception here does not do. A list the editor creates carries no marker and is written exactly as it always was. This was the first exception recorded here and it is now repaired; what it used to hide is recorded below. **An HTML comment is kept as the bytes the file used** (#245): `marked` reads a comment and DOMPurify removes it, so the text left the file on the first save — measured at the editor level, `one <!-- note --> two` written back as `one two` and a document holding only a comment written back as nothing. The bytes now ride on an inert node inside the text, and a comment the file put on its own line keeps that line; a comment inside a fenced block stays what it always was, which is code. **The editor draws a muted mark where each one is, and hovering it shows the note** — owner decision, 2026-09-07: a comment is hidden by every renderer and AgentEd hides it too, but a node that a keystroke can remove with nothing changing on screen is a document surviving as bytes rather than as a document, and one comment in eight of a measured corpus is five lines or more. The mark is drawn by the editing view alone, so it reaches no file. **AgentEd does not offer to write one**, which is why R-C1 says nothing about comments. Any *new* exception to R-C2 must be recorded here in the same PR that introduces it — an undocumented exception is a defect.
  - **Known exception — single-tilde strikethrough.** GFM spells strikethrough with one tilde or two (`~gone~`, `~~gone~~`); `marked` parses both into the same mark, and the mark carries no memory of which delimiter the file used, so a single-tilde strike is written back with two. Same rendering everywhere, different bytes — and nothing non-standard is written. Measured in #85, pinned by tests in `src/editor/markdown/roundtrip.test.ts` and `src/editor/strikethrough.test.ts`. Preserving the single tilde would mean carrying the delimiter on the mark through the editor's document model, which is a change in serialization this exception does not justify; if the owner decides otherwise it is its own issue.
  - **Known exception — a horizontal rule is written with three hyphens.** CommonMark spells a rule with three or more hyphens, asterisks or underscores, spaced or not, indented by up to three spaces; `marked` reads every spelling into the same node, and the node carries no memory of which one the file used, so a rule written `***`, `___`, `* * *`, `- - -`, `_ _ _`, `-----`, `*****` or indented is written back as `---`. Same rendering everywhere, different bytes, and the file holds still afterwards: the same shape and the same cause as the single-tilde strikethrough above. A rule inside a table cell is the stated position of #282 and is written as HTML. Measured on `e566993`, where it was recorded nowhere (#304). **One rule is written otherwise, on purpose** (#304): where a document has no metadata block and the text it is about to be written as would be read as one, its first rule is written `***`, so that the file reads back as the document it was rather than as metadata — the exception below that concerns a file that opens with two rules says what this reaches and what it does not. Whether the text would be read as a block is asked of the function that reads blocks, so the two cannot disagree. Preserving the spelling of every rule would mean carrying it on the node, the shape #93 uses for a table's spelling. Pinned by tests in `src/app/metadata-split.test.ts` and `src/formats/frontmatter.test.ts`.
  - **Known exception — unsafe link destinations.** A link whose destination AgentEd will not carry — `javascript:`, `vbscript:`, `file:`, `data:`, `blob:` — loses that destination on open; the link text stays. Deliberate, and not tracked for a fix: such an address is never allowed into the document, so it cannot be written back out of it. Measured in #84; pinned by a test in `src/editor/link-relative.test.ts`. For `data:` and `blob:` the editor's link allow-list is the only layer that drops it — the parser admits both for images — so that allow-list is not to be replaced with a hand-written one. **Narrowed by #343, and the narrowing is exactly as wide as the figures**: *on open* is the whole of the promise, and the file is a different question. Where such a link sits inside a raw HTML table kept as its own bytes (#283), those bytes are written back unchanged, so the destination **is still in the file** after an untouched open and save — measured at `c0bf9de` on a table holding a `javascript:` and a `data:` link, which round-trips byte for byte. The document never holds it either way: neither link carries a link mark, so nothing in the editor can follow one, and AgentEd does not put an address there that the file did not already have. The exception reasserts itself the moment that table is edited — one character typed in a cell rewrites it as GFM and both destinations are gone, the link text left as text. **A destination that names such a scheme only behind a character reference is text, and stays text** (#447): an anchor whose `href` spells `javascript&amp;colon;alert(1)` is the relative path `javascript&colon;alert(1)`, and it used to be written back as markdown with the reference bare, which every CommonMark reader decodes into a `javascript:` link — measured on #20 for the raw anchor and the link dialog alike, and AgentEd itself dropped the destination on the next open. An ampersand in a link or image destination that would begin a reference is now written `&amp;`, so the next reader keeps the text the editor held; `?a=1&b=2` begins none and is written as before. The backslash CommonMark also allows was measured and not taken: `marked` 15 drops it and writes the ampersand bare into the `href`, and GitHub drops the link. Pinned by `src/editor/inert-stays-inert.test.ts`.
  - **Known exception — mixed line endings.** A file whose lines do not all end the same way is written back with the terminator its **first** line used, throughout. Measured in #79: preserving a per-line mix would mean carrying a terminator per line through the editor's document model, which is a change in serialization this defect does not justify. Pinned by a test in `src/app/save-line-conventions.test.ts`.
  - **Known exception — a run of blank lines is written back as one, and a blank line at either end of the document is not kept.** A file ending in a run of blank lines is written back with exactly one final newline, and **a blank line between a metadata block and the document body is not kept either**: `---`⏎`title: x`⏎`---`⏎⏎`# Untitled` comes back as `---`⏎`title: x`⏎`---`⏎`# Untitled`. One cause at both ends — **the editor has no node for a blank line**, so the run is gone before the text is assembled; at the top, `splitFrontmatter` hands the body its leading newline and `assembleMarkdown` writes the closing `---` with a single newline after it. The single final newline the file had is preserved; the empty lines above it are not, and neither is the one below the metadata block. Rendering is identical at both ends and the file holds still after the first save. Measured at the end in #79 and at the top in #84, where the editor-level guard reached the templates for the first time; pinned by tests in `src/app/save-line-conventions.test.ts` and by **positioned** rules in `src/editor/roundtrip.test.ts`. **A run of two or more blank lines between two blocks is the third face of the same cause** (#424, owner decision of 2026-09-23): `A.`⏎⏎⏎`B.` comes back `A.`⏎⏎`B.`, and so does every pair measured — two paragraphs, a heading and a paragraph, a paragraph and a fenced block, a table or a blockquote on either side, and a run of blank quote lines inside a blockquote. It is recorded rather than repaired because the run has no node to ride on: `marked` does put it in a token, whose raw is `"\n\n\n"` for two blank lines, but that token renders to nothing and the run sits *between* two blocks rather than inside one, so carrying it would mean an attribute on whichever block follows — **ten node types can sit at the top level here**, each written by its own renderer, with two further contexts nested inside a blockquote and a list item, and after a heading there is no such token at all, the run being swallowed into the heading's own raw. That is an attribute per block type rather than one at one address, which is what the list spacing of #28 and the footnote gap of #423 each cost. **The note R-C17 carries about two or more blank lines between footnote definitions is the same cause reaching a different outcome**, not a separate fact and not the same figure: there the run comes back as **no** blank line rather than one, because the gap is read off the definition's own raw. Measured on both sides rather than assumed alike. Measured over the markdown under `/home/cata`: of the owner's own 365 project documents, **2 hold the shape** — 5 occurrences, both hand-written task briefs — and this repository holds none, which is why the guard had never met one. **What the positioned rules see, stated exactly**: one claims a blank line only directly below a closing `---` that opens the file; the other claims a region in which every removed line is empty **and one blank line survived immediately above it**, which is what a collapsing run looks like. A lone blank line lost where the file had exactly one is claimed by neither and still fails the suite — pinned by a row that builds that region rather than waiting to meet one.
  - **Known exception — a file that opens with a rule and holds a second line of three hyphens is read as metadata** (#304). A file holding `---`, a blank line, `Words`, a blank line, `---`, a blank line and `After` is a rule, a paragraph, a rule and a paragraph to a markdown parser and a metadata block to a front-matter reader, and AgentEd reads it as metadata: `Words` opens in the metadata panel rather than in the document, and the blank line below the second rule is lost on the first save, as the blank-line exception above records, after which the file holds still. `gray-matter` and remark's front-matter extension read that file the same way, measured on #304. **What AgentEd writes no longer takes this shape**: the first rule of such a document is written `***`, as the rule-spelling exception above records, so a document typed as rule, words, rule, words reopens as the document it was. **A file already on disk in this shape is not reached by that** — written by hand, by another tool, or by AgentEd before #304 — and is still read as metadata. **Where that second line is inside a fenced block** (#314), the file is read without the block: the rule opens a metadata block holding the text above the fence and the fence's opening line, the fence's own line of three hyphens closes it, and the text after the fence opens as code. **The first unedited save appends a fence line**, which closes that code block — a 31-byte file is written back as the same 31 bytes followed by four more — and the file then holds still. No byte of the file is lost; what is lost is the document. A markdown parser reads the saved file as the document it was, followed by an empty code block at its end, and a front-matter reader reads it as it did before the save. The typed route does not reach this, because the first rule of such a document is written `***`. #314 is closed as covered by this exception rather than as a defect of its own. Pinned by tests in `src/app/metadata-split.test.ts`.
  - **Known exception — five table spellings AgentEd cannot hold.** Since #93 a table is written the way the file wrote it: hugged cells (`| a | b |`) or columns padded to the file's own widths — including widths wider than the content needs — with the separator row kept exactly as it was spelled, spaced or tight, three dashes or filled, filled short, alignment colons and all. `README.md` and `docs/internal/WORKFLOW.md` each round-trip with **zero** bytes attributable to tables, where an untouched save used to add 628 and 488. The spelling is read from the raw markdown on open — `marked` trims every cell, so it exists nowhere else — and rides on the table node itself, so it survives editing, Save As and copy-paste, and a table the user creates takes the spelling of the first table in the document, or hugged cells if the document has none. **Five shapes are still normalised, once, and then hold still**, re-measured after review over 1500 files, 377 of which hold a table: a table written **without outer pipes** (`a | b`) gains them; an **indented** table is written at the margin; cells written with **no spaces at all** (`|a|b|`) get one each side; a column whose rows **disagree with each other** — hand-aligned, then edited elsewhere without re-aligning — is hugged (7 files); and a column **aligned by display width rather than character count** — an `✅` or a CJK glyph padded as if it were two columns wide — is hugged (2 files), because a display width depends on the font and on Unicode tables the file does not carry, while a character count is in the file itself. The first three are what the editor's document model can represent at all; the last two are where the file's own measure and this one disagree, and preserving either would mean carrying each row's padding rather than the column's. Together they are **11 of the 377** files with tables (3%), and none of them loses anything a reader can see. Measured in #93; pinned by tests in `src/editor/markdown/table-style.test.ts`, `src/editor/markdown/roundtrip.test.ts`, `src/editor/table-style.test.ts` and `src/app/table-style-flow.test.ts` — including a **property** test, that every style the detector can produce the validator accepts, which is what a case-by-case test missed before review.
  - **Stated position — a table inside a table cell is written as inline HTML** (#278). GFM gives a cell one line of inline content, so it has no spelling for a table inside one — yet the editor can hold one, because a cell takes any block, and a file can put one there: an HTML table in a GFM cell is read as a nested table. Until #278 the serializer tore such a table apart on save. Its rows were written as rows of the table around it and its cells as extra columns, so a two-by-two table holding a three-by-three one was saved as eleven columns and five rows, a file holding one was rewritten by an untouched save with the inner text written three times, and neither read back the same. The work also grew threefold with each level of nesting — measured on the build before #278, a file nesting eight tables in a cell took three seconds to save and wrote 83 KB, and one nesting nine ran out of memory — and it now grows with the depth instead. **It is now written on the cell's one line as inline HTML** — `<table>`, then `<tr>` rows of `<th>` and `<td>` cells, and nothing else — which CommonMark admits, GitHub draws, and `marked` reads back as the table it was; it is the answer #27 gave an image size, which markdown cannot spell either. A file that spells it that way round-trips byte-identically, with a header row, empty cells, inline markdown, an escaped pipe, text beside it in the same cell, or a second level of nesting. **Two spellings are normalised, once, and then hold still**: an inner table written with `<thead>`, `<tbody>` or `<tfoot>` loses those wrappers, and one carrying attributes such as `border="1"` loses them; neither changes what a reader sees. **Past sixteen levels of nesting, a table's cells are written as their text** — the bound that keeps the writer's recursion finite whatever a file holds — so a table nested inside one of those cells does lose its structure. The Table entry under Insert no longer builds a table inside a cell at all: pressed inside a table, it inserts the new table after it. Measured in #278; pinned by tests in `src/editor/roundtrip.test.ts` and `src/editor/insert-table.test.ts`.
  - **Stated position — a horizontal rule inside a table cell is written as inline HTML** (#282). A cell takes any block and a rule is a block, so the editor holds one; GFM gives a cell one line of inline content, so it cannot spell one. Until #282 the rule was written as the three characters `---` and flattened into the cell, where they read back as text: **the construct was gone after one save**, and the file took a second save to settle — a cell holding only a rule was written `| --- |` and then escaped to `| \--- |`. It is now written `<hr>` on the cell line, which DOMPurify keeps and `marked` reads back as a rule, measured on the installed versions for `<hr>`, `<hr />` and `<hr/>` alike. **It is written with no space on either side**, which is the opposite of the table answer above and is measured rather than chosen: a table is written with an opening and a closing tag and the text beside it survives the trim, while a space after a void element stays in the text of the block that follows — `| x <hr> y |` reads back with the paragraph ` y`, and `| x<hr>y |` with `y`. A rule **outside** a cell is untouched and still written `---`. The same rule fires at any cell depth, so a rule inside a table nested in a cell is written the same way and survives too. Two routes the editor owns reach this — the Horizontal Rule entry under Insert and the `---` input rule, both measured to work with the caret in a cell — so it is not a shape only a file can hold. Owner decision of 2026-09-12; pinned by tests in `src/editor/roundtrip.test.ts` and `src/editor/insert-blocks.test.ts`.
  - **Stated position — a block inside a table cell is written as inline HTML** (#300). A cell takes a heading, a list, a task list, a blockquote, a fenced block, a second paragraph and a hard break from the keyboard, the Insert entries and paste, and GFM gives a cell one line of inline content. Each is written on the cell line as its HTML element, with its inline content still markdown, a code block with its text as HTML entities, a second paragraph as `<p>` and a break as `<br>`: the answer #278 gave a table and #282 a rule. Until #300 each was flattened into its own text and was gone on the next open, and an ordered list did so without moving a byte. **The whole family is one position**: a heading as `<h1>` to `<h6>`; a bullet or ordered list as `<ul>` or `<ol>` with its `start`, nested lists included; a task item as a list item opening with a checkbox, ticked or not; a blockquote as `<blockquote>`; a fenced block as `<pre><code>` with its language as the `language-` class. Measured before it shipped, every one of them comes back as the node it was, and GitHub and Obsidian both render each as the construct, GitHub without the checkbox and without highlighting. **The characters of a code block written as entities are a list**, and the list is witnessed by a sweep of every printable ASCII character through a code block in a cell; characters outside ASCII were not swept. A cell of paragraphs, rules and tables in the shapes #278 and #282 describe is written as before. **What an earlier save flattened stays text**: a cell that reads `## Title` is a paragraph by the time it is opened, and nothing can tell it was a heading. Owner decision of 2026-09-14; pinned by tests in `src/editor/cell-blocks.test.ts` and `src/editor/insert-blocks.test.ts`.
  - **Stated position — a table the file wrote as raw HTML is written back as its own bytes until it is edited** (#283). GFM has one spelling for a table, and it holds less than HTML does. Until #283 a `<table>` written as a block of its own was read into an ordinary table and written as GFM by a save that changed nothing, and measured on `2bf4f1a` that cost more than bytes: a `colspan` was flattened into an empty cell, a `rowspan` moved a value into another column, alignment by attribute or by style and the table's own attributes were gone, a `<caption>` became an invented first row, a cell holding two paragraphs or a list was flattened and then moved again on the second save, and even the simplest table turned its first data cell into a header. **Such a table now keeps the bytes the file used, and is written back with them for as long as it is not edited.** Every construct above round-trips byte-identically, and so do a table that is not rectangular — a caption above two columns, rows of different lengths, a span reaching past the table — a header row in `<thead>`, a `<tfoot>`, a comment, entities, an image with a size, a table inside a cell, and the same table in capitals or indented. What is kept is the file's own bytes, including markup the editor does not show, such as a `<script>` that DOMPurify removes from the view. **Whether it was edited is decided at save, not tracked**: the bytes are read again through the route a load takes, including the repair the table plugin makes straight after a load to a table that is not rectangular, and if the table they become is not exactly the table the editor holds, the table counts as edited. So no edit route can be missed, and **an edit that is undone gives the bytes back**. **Once edited, the table is written as GFM, as every table was before**: what GFM cannot hold is lost at that moment, in the losses listed above, and a table with no GFM spelling of its own takes the spelling of the first table in the document, the rule from #93. Rebuilding HTML from the edited table was considered and not built: it would keep `colspan` and `rowspan` but still lose alignment, the caption and the table attributes, which never reach the editor. **The bytes leave the editor only through a save.** A copy of the table carries none, and a table pasted as rich HTML is written as GFM, as before, even when the page it came from spells the attribute the bytes ride on. A GFM table is untouched by any of this and is written exactly as #93 writes it, beside an HTML table or not, in every spelling that exception names. This rule was chosen over keeping only the tables GFM cannot hold, which was measured beside it. That line is drawn by a list of constructs, so one the list does not name would still convert on an untouched save; this rule has no list. Where it does not reach is the Known exception below. Owner decision of 2026-09-13; pinned by tests in `src/editor/roundtrip.test.ts`, `src/editor/kept-html-table.test.ts`, `src/editor/markdown/table-html-source.test.ts` and `src/editor/table-style.test.ts`.
  - **Known exception — raw HTML that is not one whole table at the top level is written as markdown** (#283). A list the file wrote as raw HTML is read into an ordinary list and written back as one: `<ul><li>a</li><li>b</li></ul>` as `- a`⏎`- b`, and `<ol>` as `1. a`⏎`2. b`. Measured on `2bf4f1a`, content and nesting as tried are kept, and the file holds still after the first save. The editor keeps no memory that the list was HTML, and **the owner decided on 2026-09-13 to leave it so** rather than extend the table rule above to lists. A raw HTML table the rule does not reach is written the same way, as GFM. That is a table with **a blank line inside it** or **text on the line directly after `</table>`**, because `marked` then ends the HTML block before the table ends and there is no whole table to keep. It is a table **inside a blockquote, a list item or a task item**, because the decision covered the document level; with the rule reaching into those containers, the shapes tried on #283 held, and extending it is a question of its own. And it is a table **inside another element**, such as a `<div>`, which is lost with it. A table with no cells, whether `<table></table>` or rows holding none, has nothing the editor can hold and is removed.   - **Known exception — a raw `style`, `script`, `title` or `noscript` block is lost** (#343). A file holding one of those four as raw HTML loses it on an untouched open and save. - **R-C3 File operations & the no-silent-write invariant.** New, Open, Save, Save As, Close — every destructive path routes through the unsaved-changes safety gate, **explicitly including window close and app quit**. The editor **never writes to disk without an explicit user save decision**: closing with unsaved changes always asks (save / discard / cancel). **A save that does not happen says so** (#171): where the document could not be written — the file held open by another program, a read-only file, a full or disconnected volume — AgentEd reports it in a modal that names the operating system's own reason and the steps measured to work from there, and the document stays **modified**, so the unsaved-changes gate stays in front of work that reached no disk. **The mark follows the saved state** (#441, owner decision of 2026-09-26): the document is modified exactly when its content or its metadata differs from what was last saved or opened, or a save left images unwritten. So an undo or a hand edit back to the saved state clears the mark and the gate stops asking, images a save could not write keep it on through any undo, and a keystroke that lands while a save is being written is not counted as saved. **The silence belongs to the save that succeeded**: a save that worked shows nothing at all, which is what lets the report mean something. See D3 in §10 for the currently observed violation. **AgentEd reads and writes UTF-8, and a file that is not valid UTF-8 does not open** (#259): the document is left alone and AgentEd says, in plain words, that it cannot read the file and why. There is no encoding selector, no detection menu and no per-file setting — those are the modes §1 refuses — and no offer to convert anything, because rescuing a legacy encoding is a different product from this one. The refusal is what keeps the no-data-loss promise reachable: measured before it existed, such a file opened with its unreadable characters replaced on screen, and saving wrote those replacements over the original, with opening and saving enough to do it and no edit required. The cost is accepted rather than hidden: a folder of legacy notes is a folder AgentEd will not show, which is a real loss against the fast-viewer promise in Q2 and the reason the message has to explain itself rather than merely refuse. **The File menu remembers the ten documents most recently opened** (#381, owner decision of 2026-09-19), which reverses what AgentEd said about itself until then, that it does not remember which document you had open. **Open Recent**, below Open, shows them as a card beside the menu, newest first, each by its name and as much of its folder as tells it from the others, with the full path on hover; a file opened again moves to the top rather than appearing twice, and a Windows path is compared without regard to capitals, so one file spelled two ways is one entry. Every open enters the list, whether from the picker, the files panel or the command line, and so does a document written with Save As. **Choosing one goes through the unsaved-changes gate like any other open.** A file whose folder is there and which is not leaves the list with a sentence saying so, and is looked for before the gate asks anything, so nobody is asked about their changes for a file that is gone; one that could not be reached for another reason, a disconnected drive, stays. **Clear recent files**, at the end of the card, empties the list where it is stored and not only on screen. The list stays on this machine and is sent nowhere (Q3), and nothing is reopened on launch. **The web build has no list**: there a path names a handle whose grant ends with the session, so a stored one would reach nothing, or a same-named neighbour. Each window is its own process writing the same list, which is read afresh each time it is shown; what two windows open at once do to it is not observable in the test harness.
- **R-C4 Find & Replace.** Inline panel (`Ctrl+F`/`Ctrl+H`), match case / whole word / regex with safe-parse, `F3` navigation, Replace All confirmation above 50 matches. **Whole word means a word of any script** (#393): a match is whole when neither side of it touches a letter or a mark of any writing system, a digit, or an underscore — so `școală`, `мир` and `über` are found whole, and `cas` is not found inside `casă`. A letter written as its own accent, where the letter and the mark are two characters, is held together by the same rule. Until #393 the boundary was JavaScript's `\b`, which knows only A to Z, digits and underscore whatever flags it is given: a word with an accent at either edge was never found, a query stopping before such a letter was found inside a longer word, and a script without A to Z letters, Cyrillic and Greek among them, never matched at all. **A boundary the person types with the regex toggle on is theirs** and is left as JavaScript reads it, because that pattern is the person's own; Whole word is where the rule above applies. What a search in one spelling of a text finds in the other spelling is not this promise: a query typed with its accents composed finds nothing in a document that spells them apart, Whole word on or off. Header 🔍 button and Edit-menu entries stay. **The header 🔍 button is a toggle, lit while the panel is open, and `Ctrl+F` is not** (#312): the chord and the Edit-menu entries keep opening the panel and returning to the find field, because at the keyboard Escape already closes it, while a pointer otherwise has only the close cross, at the far end of the panel from the button that opened it. **A closed panel means the search is over** (#384, owner decision of 2026-09-19): closing it by any route, the cross, Escape in either field or the header button, clears the highlights. The text of both fields stays, so the panel opened again searches with it, and `F3` or `Shift+F3` with the panel closed opens it again and moves to the next or previous match from the one it was on; Find Next and Find Previous in the Edit menu do the same. With the find field empty they do nothing.
- **R-C5 Images.** Paste / drop / Insert → Media → `assets/` folder next to the file; standard `![alt](path)` references. **An image carries a description, and there is a route to write it** (#291): it is what a reader with a screen reader is given instead of the picture, and what a renderer shows where the image cannot be loaded. **Until it is set it is the name of the file the image came from**, which is a poor answer to both and no answer at all for a pasted `image.png`, whose file on disk is named after the document instead — so the description and the file no longer even agree. It is written from the **Image description** dialog, reached two ways: a button on the floating toolbar, drawn only with an image selected, and an entry in the Edit menu, greyed when no image is selected. **An empty description is accepted** — it is the correct answer for a decorative image and CommonMark spells it — and the dialog carries one plain line saying what the field is for, because a door nobody understands is not a door (**owner decisions, 2026-09-17**). **An image the file wrote as inline HTML takes a new description inside its own bytes** and keeps the rest of that spelling exactly, which is what the #27 position requires; the write goes through the command rather than the serializer, so an image nobody edited is never re-spelled. **Drop is a route in, and nothing more** (#65): a drag carrying images inserts them exactly as a paste of the same files would — same consent, same naming, same order, same budget — and a drag carrying anything else does nothing at all. *Nothing* is arranged rather than assumed: an unhandled drop never navigates the window away from the document it is holding, whatever was dragged onto it. **Confirmation and creation happen at different moments, deliberately**: the first insertion asks, before the image is placed, and cancelling cancels the insert — but the folder itself is only created when the document is first saved, so an image put into a document that never reaches disk leaves nothing behind (#14). **Because nothing appears on disk at that moment, the document says so** (#48): once the first image lands, AgentEd states plainly that the document and its images are waiting for a save. Once per document — the point is to explain the silence, not to nag. The question is asked **once per folder**, not once per image: every image inserted before that first save is covered by the same answer, and it is asked again if a Save As moves the document somewhere the user has not agreed to. **The agreement belongs to the folder, not to the document** (#51): once the user has agreed to an `assets/` folder, every document edited in that folder in the same window inserts into it without asking again — the folder is what was agreed to, and re-asking for the file beside it reads as the application forgetting what it was told. It does not outlive the window, since R-C8 gives each window its own state, and nothing about it is written to disk. **One gesture inserts all of its images, up to a budget** (#68, #71): a paste or drop carrying three files asks once — for the destination and for the folder — and lands all three, in the order the gesture carried them. **The budget is counted in bytes, never in files** (#71): an inserted image is held in memory at roughly twice its size until the document is saved, so one gesture may carry up to **128 MB** of images — beyond that, the images that fit land in order and the rest are refused, with a message naming how many landed, how many did not, and the limit. Nothing that landed is taken back, and the user can paste the rest. A count of files was rejected as the unit because it fails in both directions: twenty screenshots refused for nothing, twenty files at the per-file cap allowed through and fatal. The two answers apply to the gesture, not to its first file: a refusal the *application* makes about one image, such as one over the size cap, concerns that image alone and the rest still land, while a cancellation the *user* makes ends the gesture, because asking the files behind it is asking the same question again. **An agreement is remembered for the folder; a refusal is not** (#66) — it cancels the gesture it was asked about, and the next one asks again, exactly as cancelling the destination picker one gesture earlier does. The asymmetry is deliberate: remembering a *yes* spares the user a repeated dialog, while remembering a *no* silently disabled images for the rest of the document, with nothing on screen and no way to change the answer. If the folder cannot be created at save time, the document is still saved and the failure is reported: AgentEd does not discard a written document for the sake of its images. **The document then stays modified until its images land** — not all of it reached the disk, so the unsaved-changes gate (R-C3) stays in front of image data that exists only in memory, and saving again retries it. Relative `assets/` paths are standard portable markdown — GitHub and every mainstream renderer resolve them (e.g. in a repo README) as long as the folder travels with the file; this is a general convention, not an AgentEd-local format. **On the web build the same flow is offered, and the same flow is what grants it what it needs** (#46): inserting an image into a document with nowhere to live asks where that document should go, and on this platform that question also acquires access to the folder — so the image lands in `assets/` beside it exactly as on the desktop. Where that access is not there, AgentEd **says so, in words that name the step that would give it** — one message per gesture, not one per image — rather than dropping the insert in the silence a user's own cancellation is entitled to. The browser requirement underneath that is stated in §7, because it belongs to the whole web build rather than to images. **A folder that cannot be read is not an empty folder** (#58): where `assets/` exists and AgentEd cannot list it, the insert is refused rather than served with a name that may already be taken — the names on disk are the only thing standing between a new image and one already there, so a failed read is not permission to guess. It speaks once for the gesture, like every cause that belongs to the document and its environment rather than to one file. A folder that does not exist **yet** is not this case: it is the ordinary state of every never-saved document since #14 and #45, and it stays silent and successful. **There is no "image document" mode**: any document can receive images at any time, with no upfront choice at creation. The first insertion triggers the flow above; an already-existing `assets/` folder is simply used — never a warning, never a block. **Naming: human-readable, never hashes.** Files that already have a name (Media under Insert, drag & drop) keep it, sanitized for portability (diacritics → ASCII, spaces → hyphens); clipboard images with no name get one derived from the document (`<document-name>-01.png`, `-02`, …). **Identity is content, never name** (#52): two *different* images that want the same name are both kept, the second gaining a numeric suffix (`diagram-2.png`) — nothing is ever overwritten — while an image whose bytes are already in `assets/` is referenced a second time instead of copied. One file, two references; replacing that file on disk later therefore changes both places it appears, which is what a shared file does. AgentEd never creates `assets/` preemptively and never deletes it — not even when the document no longer references images, **and since #249 that is what the build can do rather than what it undertakes**: the deletion capability the frontend could reach was granted to no caller and has been removed, so the promise is now mechanical. **An image can be resized with the mouse, and that size is written as inline HTML** (#27): selecting an image shows corner handles, dragging one resizes it with the aspect ratio locked — a modifier frees it — and the size is written into the file in pixels, width alone while the ratio is unchanged, so the file carries one number rather than two that can disagree. There is a minimum an image cannot be dragged past and a way back to its natural size, and a resize is **one** entry in the undo stack rather than one per pointer-move (R-C16). What this does to every image the user did **not** resize is R-C2 business and is stated there: nothing. The «Images» badge (R-C12) is derived from content and appears/disappears by itself.
- **R-C6 Sidebar.** Recursive tree when the document has **an `assets/` folder beside it and references at least one image**, which is where image paste writes (R-C5) and, since #402, the only folder rule AgentEd keeps — and **in the browser, only once a folder has been granted**, since without one AgentEd cannot see what sits beside the document at all; where that is why the tree is missing, the panel says so and offers to ask for a folder, and where a granted folder simply holds nothing adjacent it stays silent — unless the user has just asked, when the answer is given rather than withheld. **A document with a folder of its own named after it no longer shows that folder** (#402, owner decision F1): a `chapter.md` beside a `chapter/` folder used to root the panel at that folder, and it was the only way the panel ever showed a folder of documents. That trigger is gone, and the panel now appears for an `assets/` folder and for nothing else — **on both platforms alike**, including a document at the root of a granted folder in the browser, where the `assets/` folder had never been looked for at all until #402 repaired it. **The folder is not enough on its own: the document must use it** (#402, owner decision of 2026-09-21). An `assets/` folder beside a document that references no image is somebody else's folder, so it raises nothing on a document switch and answers **No related files or folders** when the panel is opened by hand. This is the line R-C12 already draws for the «Images» badge, which withdraws in exactly that state because a badge derived from the directory would describe the folder rather than the document; the panel now draws it too, so the two controls cannot answer one document differently. **The cost is named rather than hidden**: a document being written *towards* an `assets/` folder — the folder made, the first image not yet inserted — no longer raises the panel, and is reached by opening it by hand. **A root a click entered is not subject to this** (#178): it is a place the user asked to be rather than a claim about the document. **Two acts ask: accepting the folder offer, and opening the panel by hand** (#354). **Silent when nobody asked, an answer when someone pressed**: a panel drawn because a document arrived stays quiet whatever it finds, because a document with nothing beside it was never a question and speaking would put a message in front of every plain document; an act that puts the question gets the answer, once per act and never once per read. Silence belongs to what the user already knows, not to what they asked — the same line R-C5 draws between a cancellation and a refusal. So a panel opened by hand is drawn again for the document on screen, every time, and is never an empty card: the tree, the offer, **No related files or folders**, or — on the desktop, where the folder beside the document could not be read — **This folder could not be read**. A document switch into either of the last two states stays silent, as before. A read that takes longer than about 200 ms shows a small turning mark while it runs, and a read that lands after the panel was closed again draws nothing; markdown files switch focus through the safety gate. **What a non-markdown entry does depends on the platform**: on the desktop it opens with the OS default app, and in the browser it is present but inert — no pointer, no hover, no response to a click — because nothing there can hand a file to the host system, with the reason on demand in its tooltip. **What the desktop opens is the extensions the shell scope lists, and `svg` is deliberately not one of them** (#249): the handler for an `.svg` on Windows is a browser, so open would mean executing whatever script the document carries — measured on 2026-09-07 — and a click on one now does what a click on any unlisted extension does, which is nothing. A document opened **from the tree** keeps that tree, unless it has an `assets/` folder of its own, in which case the panel moves there; opened any other way it re-derives the root, and what makes the panel appear in the first place is unchanged. **After #402 that descent needs an `assets/` folder inside an `assets/` tree**, which is not an arrangement anyone writes by hand, so a click now almost always keeps the tree it came from. **The panel opens and closes from the last control of the header, and that control is lit while it is open** (#347), so which of the two the next press will do is readable without opening anything - the shape the header magnifier already has in R-C4, and the reason the menu entry it replaces has gone along with the View section it was the only occupant of. `Ctrl+Shift+E` is the same command, so the panel keeps a route the keyboard reaches; the chord was picked by the owner on 2026-09-17 from the combinations measured free on the shipped build. **It sits on the right and takes its own room rather than covering the document** - owner decision of the same day, taken because the editor is where the person was typing and a panel over it hides the work to show the neighbourhood. The cost is measured rather than implied: the editor narrows to 372 px at the 600x400 minimum, and a table wider than the narrowed editor scrolls sideways where it did not before. It is drawn as a card - rounded, clear of the window edges, with a discreet shadow - and **its fill is the colour of the document** (#358, owner decision of 2026-09-18, the move R-C7 records for the header), so **its edge is the border token alone**: at 3 to 1, measuring 3.19 to 3.94 against the card and the page across the six palettes, while the shadow is **1.000 in `oled`** (#398), where it is absent by arithmetic rather than nearly so — black drawn over pure black — so in that palette the card is its border and nothing else. **A file in the `assets/` folder beside the document that the document does not use is drawn with its name in grey, with the tooltip *Not used in the current document*** (#380, owner decision of 2026-09-19). Grey and not red: a shared folder is the normal convention (R-C12) and the agreement to use it belongs to the folder (R-C5), so the mark describes this document and accuses nothing, since the file may be used by the document beside it. The name goes back to the text colour under the pointer, and the mark follows every change to the document as well as every draw of the panel. **Where the use of a file cannot be established, nothing is marked**: a document never saved, a folder that cannot be read, a browser holding no grant for it. Which files the document uses is the one answer the «Images» popover counts with (R-C12), so the two cannot disagree. **A read the panel started for a document switch draws nothing if the panel was opened or closed by hand, or another document arrived, while it ran** (#380); until then closing the panel during that read opened it again. **A save never opens again a panel closed by hand** (#387, owner decision of 2026-09-19): a save, a Save As and a reload after an external change are not acts that ask for the panel, so they redraw it while it is open and leave it closed once the person closed it. Opening it by hand, accepting the folder offer and a document arriving forget the close; after a Save As into a place with other structure, the new tree is seen by opening the panel.
- **R-C7 Themes.** Light / Dark / Auto mode + curated palettes, persisted across sessions, chosen from the **Appearance** control at the right of the header — a half-filled circle since #330, and **not** the kebab (⋮) beside it, which opens the indicators that collapsed out of the bar. **Paper Warm has no dark version** (#391, owner decision of 2026-09-19): while it is the palette, the Mode section marks Light, the mode the page is actually in, and Dark and Auto are greyed and cannot be chosen, under a line saying No dark version. **The mode the person chose is kept rather than changed**: leaving Paper Warm for a palette with a dark version brings back Dark or Auto, marked again. Which palettes have a dark version is answered by the theme manager that draws them, from the same table that sets the page, so the menu and the page cannot disagree. **OLED Black is the mirror, and has no light version** (#398, owner decision of 2026-09-20): a palette whose page is pure black, `#000000`, for OLED screens, where a black pixel emits no light. While it is the palette the Mode section marks Dark, Light and Auto are greyed under the line No light version, and the mode the person chose is kept in the same way. **It replaces the GitHub palette**, whose label carried a product name and a trademark — the reason Claude Warm became Paper Warm at #379 — and **a stored `github` is not migrated**: the application is not released and nobody holds one, so a build that meets that value reads it as Default in silence, as it does any value it does not know. **Nothing in the palette can be drawn darker than its page**, so a code block and a card are drawn lighter than it, and the shadow under a card is gone entirely, as R-C6 records. The header and the open search panel take the palette's document colour, `--bg`, with no line under the header (#351, owner decision of 2026-09-18). **On Windows the header is the title bar** (#366, owner decision of 2026-09-18): the build turns the native title bar off there, and draws in its place the AgentEd mark at 24 px and the name at 15 px at the left of the header, and the minimize, maximize and close buttons at the right, so the window from its top edge to the text is one surface in the colour of the palette. The mark takes the palette text colour, so it reads on every palette; below 701 px the name hides and the mark stands alone, and below 901 px the Metadata and Images badges move into the overflow list, so the document name keeps its room. The bar drags the window and a double click maximizes it; Alt+Space, resizing from every edge, Win+Z and snapping to a screen edge are the system's own and work unchanged. **Snap Layouts on the maximize button is not offered** - it would need a plugin or native hit-testing, and the owner took neither. The close button asks to close, as Alt+F4 does, so the unsaved-changes gate answers it (R-C3). The drawn buttons are out of the Tab order, as the system ones were. **Linux, macOS and the web build keep what they had**: the system draws its own title bar in its own colours, or a browser tab has none, and nothing is drawn in the header for them. The colour the native frame took from #326 until #366 has nothing left to colour on Windows and was removed with its DWM call.

Badges are purely descriptive: no validation attached, nothing ever blocked. Clicking the «Images» badge opens a small informative popover — how many images this document uses and how many other files the shared `assets/` folder holds (e.g. *"3 images used by this document · assets/ holds 9 more files"*). Information on demand, never a permanent warning: a shared `assets/` folder is the normal markdown convention, not a problem state. **The second number is not always available, and the popover says which of the three it is rather than guessing a count** (#196): the folder may not be there, the document may never have been saved — `assets/` is created by the save and not before (#14) — or nothing could be established about it, because it is there and shut (#58) or because the browser session holds no grant for it (#184). *Nothing could be established* is never reported as an empty folder, which is the one wrong answer available here. **Which files the document uses is decided by path, not by name** (#380): a reference is read against the folder of the document, with `%20` read as the space it spells and, on Windows, capitals ignored, so a file of the same name in another folder or at a web address is not counted as used, and a used file referenced in either of those spellings is. They are offered in the kebab list whenever they are out of the bar, as R-C7 records, which is why they are taken out of it rather than withdrawn from it. **The search button, the tokens unit and the two badges keep the widths they have**, including the #366 rule that moves the badges into the list below 901 px.
- **R-C13 Predictable paste.** Pasting inserts what the user means: plain text is read as markdown, so content copied from another editor or an AI chat arrives formatted rather than as escaped source; `Ctrl+Shift+V` inserts the characters literally instead. **AgentEd never writes link syntax the user did not ask for**: a bare URL stays text whether it was pasted, typed, or opened from a file — the editor does not autolink, at any moment, so the artifact cannot reappear one keystroke after the paste. The single paste that produces a link is a URL dropped **over a selection**, which is an authoring act rather than an inference: the user chose the text and supplied the destination. It requires the clipboard to hold a URL and nothing else, and `Ctrl+Shift+V` never links. Rich HTML from the clipboard converts to clean markdown with no artifacts (no stray `http` fragments, no leftover markup) — a link the copied content genuinely had is preserved, which is not the same as inventing one.
- **R-C14 Concurrent & external change safety.** AgentEd never silently overwrites a file that changed on disk since it was opened: before every save, the file is read and compared with the text AgentEd last read from it or wrote to it; if it differs — another program, a sync service, or a second AgentEd window — the user chooses reload / overwrite / save-as. **The comparison is the file's whole text, not its timestamp** (#55): that misses no change made by a tool which preserves `mtime`, and — the half the user meets daily — invents none for a sync client that rewrote identical bytes or merely touched the file. The cost is one read of a document the editor already holds in memory and this very save is about to rewrite in full. **The dialog is itself the informed choice**: reload discards the document in the editor and says so in as many words, and does not route through the unsaved-changes gate (R-C3) a second time — that gate's own Save leads straight back into the conflict which raised the dialog, and its Discard asks the same question in vaguer words. A file that is **absent** is not a conflict — nothing is there to overwrite, and the save recreates the document — while a file AgentEd could not **read** is never reported as unchanged: it asks the same three questions, saying plainly that it could not check. A Save As destination has no recorded state to compare against and is not asked about; that path is protected by the save picker's own replace question. No lock file is ever written next to the user's documents (see §9, decision 2).
- **R-C15 Code & text block affordances.** Fenced blocks show, on hover, a **Copy** button (top-right) copying the raw contents to the clipboard. Blocks with a language show a **language label** (top-left), clickable to set or change it; the language lives in the standard markdown fence info string (e.g. ```` ```python ````). A fence with **no language** is a **plain text box** — the same bordered block with the same hover Copy button, no language label (the picker offers *Text*), and soft-wrapped lines instead of horizontal scrolling: the "prompt box" pattern familiar from AI chat interfaces, expressed as plain standard markdown. Pure editor chrome — nothing non-standard is ever written into the file. The **hover Copy button ships** (#235, owner decision of 2026-09-06, moved here from the §8 candidates): every fenced block, with a language or without, carries a small clipboard icon in its top-right corner, hidden until the block is hovered, and a click puts the **raw text of the block as the document model holds it** on the clipboard — never the rendered DOM, which carries the language label inside the same element. The icon is a ProseMirror widget decoration and an inline SVG, so it adds no dependency and has no path to the file. Two limits are part of the commitment rather than defects against it: it is a **pointer affordance**, so a keyboard user does not reach it and a touch surface would need a different one; and it **scrolls with the code**, so on a block wider than the editor it leaves the view after 685px of horizontal scroll (measured at the 720px editor width). Pinning it to the box would need a node view, which would pin the language label too and change how every fence is drawn. The **clickable language label ships** (#238, owner decision of 2026-09-07, moved here from the §8 candidates, which now hold no R-C15 chrome at all): clicking the label opens a small field holding the language the block carries, where Enter sets it, Escape leaves the block exactly as it was, and an empty field clears the language and leaves a plain text box. **A block with no language now carries a mark in that same corner** — an icon rather than a word, drawn only while the pointer is over the block, so a plain text box stays plain until it is asked; that is the owner decision, taken with both shapes built and measured in Chromium against the stylesheet, and it is what keeps the sentence above true. Two facts are the commitment rather than incidental: **what the field accepts is exactly what the typed fence accepts** (#237) — any run of characters that is neither whitespace nor a backtick — enforced by one pattern both routes are built from, because a language holding a backtick writes a fence that reopens as a paragraph and takes the block out of the file, and one holding a space is truncated to its first word; and **a change is one entry in the undo stack** (R-C16), which `closeHistory` makes a count rather than an intention. It carries the Copy button's first limit and not its second: it is a **pointer affordance**, opened only by a click, though once open its own field holds focus so Enter and Escape finish the gesture at the keyboard — a route that *starts* at the keyboard would be a menu entry rather than a second widget and is not built. The control is a plain element outside the editable tree, so nothing of it reaches the document: the widget is a decoration and the field is appended to the body. **The label draws the info string as the file spells it** (owner decision of 2026-09-07): it carried `text-transform: lowercase` from #202, which showed `python` for a file holding `Python` — the one surface still normalising a language after #237 settled that none does, found while writing the manual steps rather than by a test, because until a capital could reach the attribute the two could not differ. The markdown half of this requirement already holds: a fence with no content is written back as the fence it was, language and all (#94) — including one that is the **only** content of a blockquote or a list item, which used to take its container out of the file with it (#104). That is what makes the plain text box survive the save it used to vanish in, wherever the user put it.
- **R-C16 Undo is over the user's own edits.** Undo and redo cover the changes the user made to the document. **Undo and redo act on the document only while the document has focus: pressed in a field, on a button or with nothing focused, they never take a step out of it or put one back** (#306). Measured before it held, on Chromium and on WebView2: with focus outside the editor, Ctrl+Z first spent the steps of the focused field and then took a step out of the body, where the user was not looking — the very first press after Metadata under Insert did it. A field's own undo is untouched. Pinned by `src/editor/history-focus.test.ts`. Loading a document is not one of them: undo bottoms out at the document as it was loaded, however many times it is pressed, and no document's history survives into the next one. Measured on `cd777cd`, where neither half held: the load of a document was an ordinary transaction in the undo stack, so undoing past the beginning of one's own edits emptied the document — recoverable with redo — and undoing after a switch to another document put the *previous* document's text on screen under the *new* document's path, where the next save wrote it to that file and redo could not walk it back. The routes are deliberately not listed here: every way of putting a document on screen is one, and a list would go stale silently the day a ninth is added. `src/editor/document-load.ts` is the single place they all reach, and the routes are enumerated one by one in `src/app/document-load-routes.test.ts`.
- **R-C17 Footnotes are preserved.** A document holding footnotes in the bracket form GitHub documents — `[^label]` where one is referenced, `[^label]: text` where it is defined — **opens and saves byte-identically**, and a second save moves nothing (#408, owner decision of 2026-09-21 on the #404 spike). **The editing surface stands on it** (#409, owner decisions of 2026-09-22): a footnote is **made** from a control on the floating toolbar, from **Insert → Footnote** or with **Ctrl+Alt+F** — the reference lands after the selection, which stays where it is, the definition goes at the **end of the document**, and the label is the **smallest free number**, the next one where that is taken. GitHub collects every definition into one section at the end whatever the file does, measured through `gh api markdown`, so where the definition sits costs the reader nothing. **Both halves are one transaction, so one press of undo takes the pair back** (R-C16), and **deleting one half leaves the other**, which is the pair of orphan shapes this requirement already preserves. **A reference shows the note it points at under the pointer**, from a bounded walk of the document on each change of it, drawn as a decoration — so it exists in the view and nowhere in the document model, and nothing of it can reach a file. It is a **pointer affordance** and says so, the limit R-C15 records for the Copy button on a fenced block; what a keyboard reaches is the definition itself, which is drawn as the markdown the file holds, where the file holds it, and is edited there. **The editor shows labels, never numbers**: a number would have to be computed from the order of the references and would take the label off the screen, which is the only thing tying a reference to the definition a person may be editing by hand. **Where a footnote cannot be made the route says so rather than doing nothing**: inside a fenced block, inside a definition, over a whole-document selection and over a cell selection, the toolbar does not draw the control — the shape the image description took — and the menu entry is greyed. The last two were driven rather than reasoned (#409, second head): after Ctrl+A the reference was written at the end of the document and fitted into **a paragraph of its own**, referring to none of what was selected, and over a cell selection it wrote **raw HTML into the cell**, `| one | two<p>[^1]</p> |`, which held still on the second save rather than healing. The toolbar is hidden at a bare caret, measured at 0 px wide, so **the menu entry and the chord are the routes with nothing selected**. **What it repairs is damage rather than an absence**, measured on `7cd4984` and again on `651bb40`: `marked` read a definition as a link reference definition, so `[^a]: https://example.com` was consumed at parse and the reference came back as `[^a](https://example.com)` — **a working link to a destination the file never linked to** — while a definition whose body did not parse as a destination came back escaped, `\[^a\]: …`, and two definitions on consecutive lines were joined into one escaped line. The rows this names, each with its before: a definition whose body is a URL, one word or several words; **a definition continued on indented lines, which keeps its indentation**; **two definitions on consecutive lines, which stay two lines**; the label kept exactly as written and never renumbered, so `[^margin-standard]` stays itself; the definition kept where the file put it, the middle of a document included; a reference in a paragraph, a list item and a table cell; and all of it after an unrelated edit elsewhere. **Four shapes GitHub does not render as footnotes are preserved too, because this is about the file rather than the rendering**: a reference with no definition, which GitHub draws as literal text; a definition nobody references, which GitHub draws not at all; and two definitions sharing a label, or labels differing only in case, which GitHub collapses onto one — **both of those lose a definition's text from the file today**, which is content loss rather than respelling. **The construct is called a footnote**, the familiar word over the typographically exact *endnote*, the line CLAUDE.md already draws with «Metadata» over frontmatter. **No new runtime dependency**: the tokenizer is written here, where `parse.ts` already extends `marked`, and `marked-footnote` at 68 394 bytes was declined. **Two things are deliberately unchanged and pinned as regression rows**: the Obsidian inline form `^[text]`, which is escaped today, loses nothing and renders identically on GitHub; and **reference-style links, byte for byte**, which the owner put in a later stage — the tokenizer sits beside the code path that consumes them and must not move them in either direction. **The gap between two definitions is the file's to spell** (#418, owner decision of 2026-09-23): a run written a blank line apart comes back a blank line apart, one written consecutively stays consecutive, and a run spelled both ways keeps both — before this, two definitions a blank line apart came back one newline apart and a mixed run was levelled to the tighter spelling, losing the distinction rather than a blank line. The spelling travels on the definition above the gap, read from the trailing blank line `marked` leaves in its `raw`, the way the continuation indentation already travels. **Two or more blank lines between definitions come back as none at all**, which is the same cause as the run exception recorded under R-C2 above (#424) reaching a different outcome, and both figures were measured rather than carried across: between two ordinary blocks a run collapses to **one** blank line, between two definitions to **none**. The gap is read from the definition's own raw, and with two or more blank lines `marked` ends that raw at a single newline and puts the rest in a token of its own, so the gap reads as absent. **One difference is recorded rather than repaired**: a reference the file spelled escaped, `\[^a\]`, comes back unescaped **where it sits inside a sentence**, because after a load it is the same text node as a bare one and only one of the two can be written back — the R-C2 exception above says why, and why keeping the escaped spelling would break the orphan reference this requirement promises. **At the start of a line followed by a colon the escape is kept**, since there the unescaped spelling would be a definition rather than the text the file wrote, and the line is no longer torn into a stray backslash paragraph plus a definition the way it was on `297874c`. **The start of a line is exactly that since #409, and it used to mean the start of a text node**: after bold, italic, a code span or a link, a text node still begins at offset 0, so a reference to a defined footnote written there was escaped and stopped being a footnote — measured through `gh api markdown`, the escaped spelling renders as literal text with no footnote section at all. A heading and a table cell were escaped for the same reason and neither can hold a definition. The escape now **marks** such a reference and the answer is given where the assembled line is readable, in `htmlToMarkdown`: at the start of a line, allowing the markers a list item or a blockquote writes in front of its content, since a definition is read back inside both. Held by `src/editor/footnote-round-trip.test.ts`, `src/editor/markdown/footnote-escaped-line.test.ts`, `src/editor/markdown/footnote-reference-position.test.ts`, `src/editor/footnote-insert.test.ts` and `src/editor/footnote-hover.test.ts`.
- **R-C18 New from Template.** Two plain markdown seeds, offered in a gallery: **Blank Document**, which creates an empty document, and **Document with Metadata**, the same with a block at the top for title, description, author, date and tags, and a `# Untitled` heading. **Recorded as R-A3 until #403**, and moved here because a gallery of plain markdown seeds is not an AI-era layer and a blank document least of all. **README, project document and meeting note left at #403**, owner decision of 2026-09-21 - **a product decision rather than the removal of machinery**, since none of the three came from the Skills concept: three seeds that each guessed at a shape gave way to two that say what a markdown file can be. **The explanation lives on the gallery card and nowhere else**, which is the whole of the change to what the person reads: the document created holds what they asked for and not a sentence about itself, so the metadata seed writes its block and its heading with no explanatory lines under them. Measured in Chromium at the 600x400 minimum window: the two cards, whose texts are longer, **do not scroll**, where the four shorter ones scrolled by 80 px, and no card text is cut or lost to a wrap at that size or at 1200x800. The card texts are owner-approved word for word and are read by the gallery from `src/templates/index.ts`, the one address they live at. **Blank Document leaves the document unmarked, as File then New does**, because a seed with nothing in it has nothing unsaved to warn about; a seed with content marks it. **Insert Metadata (R-C9) writes the same block, read from this template rather than restated**, so the two routes cannot drift apart. Skill and llms.txt templates left with their profiles at the reset.

## 6. Quality requirements

- **Q1 Size**: Windows installer stays in the ~3 MB class (expected to shrink after the cut).
- **Q2 Startup**: opens in under ~2 s on typical hardware; usable as a fast viewer.
- **Q3 Offline**: AgentEd makes no network calls of its own. No telemetry, no update check, no account, nothing sent anywhere; every feature works with the machine offline. What the application cannot speak for is the embedded web runtime the platform gives it — the system component that draws its window. On Windows that runtime is Microsoft WebView2, and two of its behaviours have been measured. **At every launch it contacts Microsoft on its own schedule**, with the application open and untouched: two destinations, reached by three connections, alongside four loopback sockets that leave no machine — the unit is written out because the earlier record gave the figure without one. **And it speculatively looks up the links in the open document**: when the pointer enters a link, the hostname of that link reaches a resolver before any click, and a connection to it follows at mousedown. An ordinary gesture over an ordinary document therefore tells a resolver which links the document holds, with nothing clicked. That is the Chromium network predictor inside the runtime; nothing in this repository asks for it, there is no `preconnect`, `prefetch` or `dns-prefetch` anywhere in it, and the precondition is simply that links are real anchor elements, which is what R-C1 describes. **Neither is something this application can turn off**, and the second was measured rather than assumed: the candidate remedy, a browser argument disabling the predictor, was built and run and changed nothing, because the behaviour hangs on a browser preference rather than on a feature name a command line reaches. All of it belongs to the runtime rather than to AgentEd, and the headline above is unaffected — the lookup is the runtime speculating over a document AgentEd rendered, not a call AgentEd makes. Measured on `3f47f20`, and the lookup reproduced in two sessions on `8aa2731` and `35353a7` with the instrument named there (#218). The runtimes of the other targets §7 builds have not been measured.
- **Q4 Stability**: no data loss — the safety-gate invariant (R-C3) and the no-silent-overwrite invariant (R-C14) are non-negotiable, **and what a person saved is what the next open shows: a construct the editor lets a person make is one the file can hold** (#300).
- **Q5 Supportability**: the application states its own version and build commit, reachable in at most two clicks and copyable in one, so that any report can be tied to the exact build it came from. A build produced outside CI says so plainly rather than showing a commit it cannot know. This is stated *to* the user, never sent anywhere — Q3 stands.

## 7. Platforms & delivery

- **Repository**: `github.com/catge/AgentEd` (born clean at the reset). Prior history lives in the private `agented-archive`.
- **Primary target: Windows** (`.exe` installer).
- **The web build is a development and CI surface and a PWA precursor, rather than a shipped target** (owner decision, 2026-08-30). It stays in the repository with four roles and nothing beyond them: it is **the CI and test surface**, over which the suite runs and goes on running; it is **the editor core running in a browser**; it is what holds the `src/platform` discipline to account, and that discipline is what keeps future targets feasible; and it is **a PWA precursor**, mobile being the parked phase in §8 and mobile being web. One root decided this rather than a list of complaints: **a browser does not treat a path as an identity, and does not treat a permission as durable.** The first of those is closed, with a boundary in code (#126, #141, #144, #149). The second — the **lifecycle of a folder grant** — is structural rather than repairable: a grant is acquired by a gesture, evaporates without notice, does not reach a document already open, and cannot be renewed without another gesture. Permission friction on desktop-web is a property of the platform, not a defect in this build. Alternatives were weighed rather than dismissed: a foreign cloud such as Drive costs an account, a network dependency and a different product from the one §1 and §5 describe; an own server is clean technically and gated on demand nobody has validated; and a mobile PWA does not carry the desktop-web grant model in the same shape — see the measurement in §8, which is narrower than it first looked. **What the rest of this section therefore is**: a description of that surface and of what the build does on it, rather than a commitment to the user of a shipped one.
- **The web build requires a browser with the File System Access API**, which today means a Chromium-based browser (#46). Opening a document, choosing where to save one, and everything that writes beside it all rest on that API, so this is a property of the **whole web build** rather than of any one feature — Firefox has neither `showOpenFilePicker` nor `showSaveFilePicker`, and the build then loads and edits but cannot reach the disk at all. It also needs a **secure context**: `https://` or `localhost`, never a bare host or IP, or the pickers are absent exactly as they are in Firefox. The desktop build depends on none of this and remains the primary target. Since the re-framing above, which browsers the surface runs in is a development note rather than a statement the README owes its readers before publication; it stays on the #20 checklist as the former.
- **On the web a folder grant is a separate act, and most of the build does not need one.** `showOpenFilePicker` hands the session a handle on the picked **file** and nothing else, so the core loop — open a `.md`, edit it, save it back — works with no folder granted at all, as does the external-change check for that document. What needs a folder is what looks *beside* it: the sidebar (R-C6) and **resolving a document's images** (R-C5), whose `assets/` references live in that folder. **Only Save As grants one**, since it is the one flow that calls the directory picker, and R-C6's panel offers the picker where it would otherwise be silently absent. **A save also costs a browser permission prompt**, once per file, the first time AgentEd writes through a handle the user picked — the browser's own, not AgentEd's. Measured on `eff353c` (#184).
- **Platform abstraction**: file access and OS integration stay behind the existing platform layer (`src/platform`), so future targets (PWA, mobile) remain feasible without re-architecture.
- **Linux is a contributor lane, not a shipped target** (owner decision, 2026-09-06, on #8). It exists so that someone arriving with a Linux machine finds a build that runs and an artifact to check against — not so that a Linux user is handed a product. The distinction is load-bearing rather than cautious: **the owner has no Linux machine**, and this project ships what its owner has tested. Two consequences are recorded rather than repaired, and both become defects on the day Linux turns user-facing. The packaged desktop entry declares `MimeType=text/markdown` while its `Exec=` carries no field code, so a file manager cannot hand a document to the application and **R-C11's file association is not honoured on this target** — the CLI half is, `src-tauri/src/main.rs` reading `argv` at startup. And the deb declares `libwebkit2gtk-4.1-0` and `libgtk-3-0` and nothing about libc, while the binary requires the glibc of whatever built it, so an install on too old a distribution succeeds and the launch fails on a missing symbol. Both measured on #8, on `468cd05`.
- **CI on push/PR**: lint + unit tests on Linux runner (covers the web app) + Windows build. **No Linux bundle here, deliberately**: the Rust job already compiles the whole crate graph for Linux on every code change, so what a bundle job would add is packaging failure — which arrives with a runner image or an upstream tool rather than with a commit, and is therefore nightly's to catch. Measured on #8: a full run is 16 billable minutes and a per-pull-request Linux bundle was estimated at 5 to 8 more, on every code change, for a class of defect that does not come from code.
- **Nightly**: **Windows and Linux**, skipped when there are no new commits since the last successful run; artifact retention 7 days. macOS is available here on explicit manual request only. This is the only place Linux is built on a schedule, and before #8 it was built nowhere — both the nightly and release entries existed for weeks and neither had ever executed.
- **Release (`v*` tags)**: **Windows alone.** Linux is **nightly only until it turns user-facing** — a release hands a user a product, and the lane bullet above says this is not one yet. macOS is deferred for its own reason: nothing here can test it, an unsigned build reaches a user through Gatekeeper as a file that cannot be opened, and the bundle identifier ends with `.app`, which collides with the macOS application bundle extension. Each returns when it becomes a shipped target — for Linux, what that takes is the list in the lane bullet: a machine to test on, R-C11 honoured, and a distribution floor declared.

## 8. Roadmap after reset

- **Pre-public, committed**: empty — everything this column carried is done.
- **Pre-public, candidates** (owner-prioritized): copy-any-block on hover (copy any paragraph/table/section as markdown or as formatted rich text — pure UI, file untouched); performance/polish pass, first-run experience. **R-C15 chrome has left this list entirely**: the hover **Copy** button on 2026-09-06 (#235) and the **clickable** language picker on 2026-09-07 (#238), the last of it, which had been carried here since 2026-08-24. Both ship in R-C15.
- **Post-public phases (parked)**: **PWA / installable mobile web app** — strategic rationale worth preserving: foldable phones make real document editing on mobile viable for the first time, and a few-MB offline WYSIWYG editor is the right shape for that segment, standing in for heavyweight document formats on text-first documents; kept feasible by the platform-abstraction rule in §7. **PWA distribution is also the only free route for a solo developer** — no store accounts, no native builds. The browser file-access limits, iOS especially, were the open question here and are now measured rather than owed. On mobile the file model differs by platform rather than being absent. Chrome for Android has had the File System Access pickers since v151, with documented gaps — MIME filters ignored, save-as unable to create a new file — while iOS has none in any browser, every iOS browser being WebKit. So a PWA phase decides its file model per platform: grants where they exist, share-in and share-out or an OPFS space where they do not. Measured 2026-08-30, and the aggregated compatibility entry disagreed with the per-method data; the second was taken, the first being a lagging summary of it. **An OPFS space is a vault in all but name** — files invisible in the user's own filesystem, which §5 lists as a non-goal — so the phase would have to choose explicitly between *one file at a time, no vault* and *its own space, with the changed promise acknowledged on that platform*, and the measurement makes that choice sharper rather than softer: if iOS pushes toward OPFS and Android does not, it is decided per platform rather than once. None of this schedules the phase — parked is what it stays, and what is written here is the rationale it would begin from rather than a plan. **Sealed document archive (export)** — a single-file, zip-based container bundling the markdown + its `assets/`, optionally signed: one-file sharing plus PDF-like finality through signing; if ever pursued, strictly an *export* format — the working format stays plain `.md` (naming note: `.mdx` is already taken by MDX = Markdown + JSX). Also parked: skill profiles reintroduction, OKF profile, Agent View, visual frontmatter editor, native mobile.
- **Multi-tab editing — no longer promised, and deliberately not scheduled** (owner decision, 2026-08-24). It was *Pre-public, committed* until this amendment. It is not moved to a later phase, because a phase is still a promise: it is removed from the roadmap entirely and from the README in the same amendment, so it can be built on a branch, tried, and kept or discarded without anyone having been told to expect it. Three reasons, in the order they weighed. **R-C8 already answers the underlying need** — multiple isolated windows, one file each — so tabs would be a second mechanism for a question that has an answer, which is the opposite of the simplicity this product is built on. **Three of its four open questions cannot be answered on paper**: whether the unsaved-changes gate is per tab or global, what a session is and whether tabs reopen on launch — which would persist which documents were open and reopen them, touching the *no vault, no account* promise further than the one state of that kind AgentEd keeps, the recent files list of R-C3 (#381), which reopens nothing — and whether the sidebar follows the active tab. Those are settled by use, not by argument, and deciding them under the pressure of a gate is deciding them at the worst moment. **And the asymmetry decides it**: building it and disliking it costs the build; promising it and disliking it costs either a feature nobody wanted or a broken promise, and after publication a removal is a regression with a deprecation story attached. Nothing promised, nothing to take back.

## 9. Decision log (reset iteration, August 2026)

1. **Discrete document badges.** Statusbar badges («Metadata», «Images») are descriptive, not modes; silent on plain documents; plain-language wording for non-specialists.
2. **Detection over lock file** for concurrent-change safety: a lock file would pollute user folders, contradict the no-ownership promise, and misbehave in synced folders. Owner-approved.
3. **"Reading mode" toggle rejected** — it adds a mode, and modes cost simplicity. The related "sealed archive" idea was parked as an export format instead (§8).
4. **No "image mode"** — images insertable in any document at any time; `assets/` created on first use with confirmation, existing folders used silently; human-readable file names, never hashes.
5. **Text boxes are plain fences** — the "prompt box with Copy" pattern is a language-less code fence, standard markdown; no new syntax invented.
6. **History reset**: new repository born clean; complete prior history, PRs and ADR-001..034 preserved in the private `agented-archive`. License stays MIT; monetization via donations (Ko-fi + GitHub Sponsors).
7. **Paste reads markdown (R-C13, revised).** The original wording required plain text to be inserted literally, which turned pasted markdown source into escaped text (`\*\*foo\*\*`) in the file — syntax appearing because of how content arrived, the same failure class the requirement exists to prevent. `Ctrl+V` now parses; `Ctrl+Shift+V` is the literal escape hatch.
8. **The tree survives its own click (R-C6, revised).** The original wording described a panel rooted per document, which is what the code did: opening a file from the tree re-derived the root from that file, and since a clicked document rarely carries a folder of its own the panel dissolved on the only action it offered. Opening two files from one folder was therefore impossible from the panel. Owner decision, 2026-08-29: keep the root when the opened document has no adjacent structure of its own, and descend into that structure when it does — better than the old behaviour in both cases rather than better in one and worse in the other. A root the user sets deliberately was weighed and rejected as new surface, and recent files or a back affordance as a feature rather than a repair. The kept root is in-memory and per window (R-C8); nothing about it reaches disk.
