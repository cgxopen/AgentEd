# AgentEd — Product Requirements

**Version**: 1.0 — approved by the owner on 2026-08-14. This document defines the simplified AgentEd after the August 2026 reset; any future change goes through a PR on this file.
**Supersedes**: all prior requirement documents, ADR-001..034 (archived in the private `agented-archive` repository).

---

## 1. Product statement

AgentEd is an **easy-to-use WYSIWYG markdown editor**. Open any `.md` file and edit it the way you'd expect in 2026 — no syntax in your face, no vault, no account, no cloud. A small, fast, native binary that respects your files and never claims ownership of your folders.

Quietly, in the background, AgentEd also acknowledges that a growing share of markdown is read by AI models before it is read by people — and offers lightweight instrumentation for that: a live token count.

**Priority order when requirements conflict**: (1) ease of use → (2) speed & lightness → (3) AI-era instrumentation.

## 2. Core requirements — the editor

- **R-C1 WYSIWYG editing.** Inline formatting with no visible markdown syntax; floating toolbar on selection; markdown input rules (`#`+space → heading, `-`+space → list, ``` followed by a space or Enter → code block — optionally with a language between them, `[ ]` → task list, etc.); tables, task lists, code blocks and images edited visually. Numbered lists must number correctly across the document (see D1 in §10). **Links are made explicitly** — floating-toolbar button, `Ctrl+K`, **Link** under Insert, or pasting a URL over a selection — with the same dialog changing or removing an existing one; a link the file wrote as a reference, given a new address there, is written inline with it, and the definition it named and the other links of that definition are left as they were (#570, owner decision E2); `Ctrl`/`Cmd`+click follows a link in the system browser, while a plain click places the caret, because clicking inside a document you are editing must stay safe. **A link address is a web address (`http`, `https`, `mailto`) or a relative path to a neighbouring file (`./notes.md`, `docs/guide.md`, `#section`), and it is written exactly as typed** (#42) — no scheme is ever implied, because a bare host and a neighbouring file are indistinguishable by shape and the common case in a markdown editor is the file; a relative link is never handed to the operating system. **An inline mark and a code span coexist** (#84): a mark may span a code span, cover one exactly, or cover part of one — a file may spell all three, so the editor holds all three. Covering *part* of a span is the one shape CommonMark cannot write as a single span, so it is written as adjacent spans instead (`` `c`**`od`**`e` ``): nothing is lost, re-reading gives the same document, and the file holds still afterwards. **Owner decision, 2026-08-24**, taken on the #84 branch build with the gesture in front of him: the gesture stays available rather than being refused in the editor — it is reachable only by selecting inside a span deliberately, and refusing it would cost a rule to explain for a case that already behaves. Pinned by `NAMED CASE` in `src/editor/mark-nesting.test.ts`. **The shape of a table is edited from the Table section of the menu** (#292): a row is added above or below the caret or deleted, a column is added before or after it or deleted, and the whole table is removed — seven routes, and which seven was decided by what a GFM table can spell and read back rather than by what the extension offers. **A column takes its alignment and its padded width with it**, so a column inserted or deleted no longer changes what the columns beside it mean — measured before it: `addColumnBefore` at the first column of a table written `| :--- | :---: | ---: |` wrote `| :--- | :---: | ---: | --- |`, the file holding still while it rendered differently. The one table this does not reach is one that has **no spelling of its own** and inherits a neighbour's, where the alignment still shifts; it is recorded on #292 rather than repaired here, because moving it means writing an attribute onto a table the file never spelled. **A row is not added above the header row and the header row is not deleted**, and both entries are greyed there: GFM requires a header, so the file would otherwise be given the new row *as* its header, or promote the first body row — in both cases a document the editor never showed. Inside a table in a cell that refusal is stricter than it needs to be, which is accepted rather than special-cased (**owner decision, 2026-09-17**). **Merging and splitting cells, turning a header row, column or cell on and off, and column widths are not offered at all**: GFM spells none of them, and the three header toggles were measured being discarded in silence — the editor shows the change, the file keeps what was removed. **An entry with nothing to do is greyed rather than silent**, and which ones are is computed from the document rather than from `editor.can()`, which answers `true` on the last row and the last column where the command then refuses. **A selection can be a node rather than a stretch of text** — an image or a horizontal rule, the two a click can select — **and two commands refuse one**: inline code and the fenced block (#427, owner decision of 2026-09-23). Measured on `8934c82`, each took a selected image out of the document in one press: inline code wrote the image markdown as literal text inside a code span and the fenced block left an empty fence, by five routes between them — the two toolbar buttons, `Ctrl+E`, `Ctrl+Shift+K` and **Edit** → **Insert Code Block**. So the refusal is at the two commands rather than at the bar, since hiding the buttons alone would have left the chords and the menu entry doing it with no visible control left to connect the loss to. The bar then **does not draw those two for a node selection** and the menu entry greys, the rule it already keeps for a control that cannot act — cosmetic agreement once the commands refuse, rather than the repair. Every other control stays drawn: what they write around an image is a legitimate change, and nothing else was measured taking the picture out.
- **R-C2 Clean round-trip.** Bidirectional serialization: the file saved is plain, portable markdown; open→save with no edits must not alter the file. **A round trip is the document, not only the file: a save followed by an open gives back the same constructs in the same places. A file that holds still while a construct turns into its own text breaks this promise as much as a file that moves** (#300). **A file's line conventions are part of that promise** (#79): how its lines end (`\r\n` or `\n`) and whether the last line is terminated are properties of the file, read when AgentEd opens it and re-applied to the whole text when AgentEd writes it — a document written on Windows stays a Windows file, and a file that ended with a newline still does. **A byte order mark is a property of the file in exactly the same way** (#259): a file that began with one is written back with it, a file that did not is never given one, and neither is a choice the user is asked to make. It is carried rather than recorded as an exception below, because it is read and re-applied at the same boundary the line conventions are and it never enters the document model — so it costs none of what the exceptions cost. A document that was never read from disk — **New**, or **New from Template** — is written with `\n` and a final newline. **A list keeps the spacing the file gave it** (#28): a loose list — blank lines between its items, bullet, ordered or task alike — is written back loose, and a tight one tight, per list rather than per document. The spelling is read from the raw markdown on open, because `marked` answers CommonMark's question rather than the file's — it wraps an item body in `<p>` both when blank lines separate the items and when any one item holds more than one block — and it rides on the list node, so it survives editing, Save As and copy-paste. A list created in the editor is tight. **A block a blank line under the one above it in a list item keeps that blank line** (#601, owner decision F of #573): `- a`, a blank line and `- b` indented by two come back as the file wrote them, where the nested list used to be written directly under its paragraph, so that GitHub, which read the outer list loose, read it tight after the save and `a` lost its paragraph. In a task item the same holds for every block, a nested list, a second paragraph, a heading or a fence under an empty marker line. The gap is read where the adjacency of #568 reads it, from the tokens of the item, and rides on the block below as the count of #590, 1 for one blank line, a line of spaces written as the blank line it reads as; a nested list made with Tab, a block a paste or an edit puts in an item and the second half of a split carry none, and are written as before. A nested list keeps its count when an edit moves it, by Enter in the paragraph above it or Shift+Tab on its first item, as the flag of #568 follows its block. Measured on the corpus snapshot of 8361 files at `3d91ed0`: an unedited save writes 3960 files byte for byte where it wrote 3952, 92 files write back the blank lines they held and nothing else changes, GitHub reads 21 files (14 distinct) as the file where it did not and 18 (14) closer to it, and no file moves on the second save that did not; CommonMark example 109 keeps its blank line. Pinned by `src/editor/item-spacing.test.ts`. **A list also keeps the marker the file wrote it with** (#431): `*`, `+` or `-` for a bullet list, `.` or `)` after the number for an ordered one, carried on the list node the way its spacing is and read from the same token. Before this, every list was written back with `-` or with `.` from one serializer option, so `* one` came back `- one` and `1) one` came back `1. one` on every save, with nothing recorded about either. **For two lists side by side that lost a document rather than a spelling**: a marker change is the one thing in markdown that keeps two adjacent lists of the same kind apart, so writing both with `-` made them one list, and the blank line between them then made it one *loose* list, so the second save wrote four items a blank line apart and the file settled only on the third - which is the one thing every recorded exception here does not do, save one: the raw block that opens with an image alone on its line, recorded below by owner decision 3 of 2026-10-18 on #572, moves on the second save and holds from the third. A list the editor creates carries no marker and is written exactly as it always was. **A task list keeps its marker as well since #601**: `* [ ] a` and `+ [ ] a` came back `- [ ] a`, nested or not, though the task list read the marker already; on the same corpus 6 files (6 distinct) hold 16 such lists. A task list the editor makes is written with `-`. **An ordered list numbered with one number throughout keeps it** (#569): `1.`, `1.`, `1.` is written back so, and so is a list repeating another start, where every item used to be counted up from the start, `1.`, `2.`, `3.`. The style is read from the file with the marker and carried on the list, so an item added with Enter takes the same number, and a list the editor makes, or a rich paste brings, is counted up as before. What is shown is not touched: the editor draws an ordered list from its start, so the reader sees 1, 2, 3 either way, and a list continued after a paragraph still continues on screen (R-C1, D1); written, the continued list keeps the one number it had, from the start it continues at. **Emphasis keeps the delimiter the file wrote** (#566): `_word_` is written back `_word_` and `__word__` as `__word__`, read from the token `marked` hands over and carried on the mark, the way a list carries its marker. Before this every emphasis was written with `*` and every strong one with `**` from two serializer options, so the underscores of 416 of 1985 public files measured by AMP on #566 were respelled on every save. An emphasis made in the editor, by Ctrl+I, Ctrl+B or the toolbar, carries no delimiter and is written with asterisks as before; typing inside an underscore emphasis keeps its underscores; a rich paste writes asterisks. Where an underscore cannot stand, the exception below says so. **A heading keeps its underline or its closing hashes** (#573, owner decisions A and D of 2026-10-16 on the step zero): `Title` over a line of `=` or `-` is written back underlined, with the underline run the file wrote, longer or shorter than the text, and `## Title ##` keeps its closing sequence, the spaces before the closing hashes and the hashes. Read from the token and carried on the heading, the way a list carries its marker; measured on the corpus of 8361 files, 404 files held 4705 underlined headings and 16 files 110 headings with closing hashes, every one written with bare hashes before this, and an unedited save now writes 3906 files byte for byte where it wrote 3829; in the CommonMark suite, examples 59, 72, 80, 83, 96, 102, 103, 215 and 300 come back byte for byte. The spelling is written only where `marked` reads it back as the same heading, and the hash spelling otherwise: a level the underline cannot spell, an edit that leaves text the underline would turn into something else. A heading the editor makes carries none and is written with hashes, and so do a heading turned into a paragraph and back, the second half of a heading split by Enter and a paste. **Not carried**, and written as before: an underlined heading whose text runs over two lines, written with hashes and its line break as a space; the indentation of a heading or of its underline; the spaces after the opening hashes; and the spaces after the text, which an unedited save drops from 15 more files of that corpus; each is recorded below. **A fence keeps the run it was opened with and the gap before its info string** (#573, owner decision C): a fence of four backticks or more, or of tildes, is written back with that run, opening and closing, and ```` ``` js ```` keeps the spaces between the run and its language, read from the token and carried on the code block the same way. Measured on the same corpus, 25 files held a longer run and 57 a gap before the info string, and none a tilde fence, which the CommonMark suite holds; an unedited save now writes 3921 files byte for byte where it wrote 3906, examples 19, 120, 123, 125 and 141 come back byte for byte, and one file stops moving on the second save: a fence of four backticks around a run of three indented inside it, which three backticks written unasked let close early. The run is written only where `marked` reads it back as one code block with the language and the text the editor holds, so a line typed into the code that would close the run writes the fence turndown chooses. A fence the editor makes carries none, and neither does a paste or the second half of a block split in two; a language set from the label keeps the run. **Not carried**, and written as before: the indentation of a fence, a closing fence longer than the opening one, what follows the language in the info string, the run of an empty fence (#94), and a fence inside a table cell, written as HTML (#300); the exceptions below record them. **A link keeps what the file wrote between its parentheses** (#573, owner decision B): `</my uri>`, `wiki/București`, `Rust_(programming_language)`, `/f&ouml;` and the spacing around a destination and before a title are written back as the file wrote them, where the destination used to be written from the href the editor holds: percent-encoded, its parentheses escaped and its character references decoded. The whole of what stands between the parentheses is read from the token and carried on the link, the title with it, since a title is spelled too; the delimiter of #562 is what a link carrying nothing is written with. **Only a link the serializer would respell carries it**: a plain ASCII destination with nothing the serializer escapes or encodes, alone or with a plain title in double quotes, is written as the file wrote it already and carries nothing, so the check below costs only where a spelling is kept, measured on 2000 links at about twice the save time of `main` for links that carry and the same time for links that do not (owner decision of 2026-10-16). Measured on the same corpus, an unedited save now writes 3952 files byte for byte where it wrote 3921, and of the 105 files it writes otherwise, a file holding one or more of these, 64 hold balanced parentheses, 11 an ASCII character the address was percent-encoded for, 10 a character outside ASCII, 8 angle brackets, 5 spacing, 3 a title and 2 an escape. In the CommonMark suite examples 22, 32, 489, 492, 496, 499, 500, 502, 503, 504, 506 and 507 come back byte for byte, and 32, 344 and 503 no longer move on the second save. The spelling is written only where the link it makes, read by the parse the editor uses, has the href and the title the editor holds: a new address or title, from the link dialog or anywhere, writes the link from what the editor holds, as before. An edit of the link text keeps it, and so do Enter inside the link text, which leaves both halves a spelling still true, and a copy and paste inside one window; a link the editor makes, a plain-text paste and a paste from another window carry none. In a table cell a pipe the spelling already escapes is not written, since the cell escapes it again. **Not carried**, and written as before: an image, a reference link, an autolink, a link kept as bytes, and a destination and title written over two lines (example 510); the image and the two lines are recorded below. **The text of a code span reaches the file as written** (#603, owner decision 1 of 2026-10-17 on its step zero): a run of spaces, a tab, the padding and a span of spaces only are written as the file holds them, `x  y` between backticks coming back with both spaces. The editor used to collapse each run to one space, trim the padding and drop a span of spaces only with its spaces, so GitHub read the code otherwise in 109 files (74 distinct) of the corpus snapshot of 8361 files. The parse hands the editor the text of the span as CommonMark reads it from the bytes of the span; the space the ProseMirror parser trims after a span ending in white space, and the trailing padding of a span at the end of a block, are put back from the HTML after the load; and the serializer writes the text as held, with the run and the padding the span needs. Measured on that snapshot at `e9780eb`: an unedited save writes 3974 files byte for byte where it wrote 3966, GitHub reads the code spans otherwise in 39 files (28 distinct) where it did in 109 (74), no file moves on the second save that did not, and every file written otherwise differs only in the text of its spans. What was left is a `code` element holding raw HTML, written as markdown, kept as the bytes of its block since #604 outside a raw `dl`, an escape beside a span (#605), and one raw `dl` whose markdown GitHub read as text, kept as its bytes since #604. In the editor a run inside a span is drawn and typed as a run since the white-space rules TipTap injects are restated in the stylesheet, which the CSP of the app kept from applying: until then the editor drew a run as one space, and the first of two spaces typed reached the file as U+00A0, measured on Windows (owner decision of 2026-10-17 on #613). **The other rules of that tag are restated where they change what is drawn** (#614), measured in Chromium under the CSP of the app: the gap cursor, the caret beside a table or a rule that opens or closes the document, or between two tables after a click, which stood there with nothing drawn and is now a line in the colour of the caret; and ligatures switched off, so a caret between `f` and `i` stands between two letters. **Left out, each measured as changing nothing**: word wrap, which every editable element has from the default stylesheet of Chromium; `position: relative` on the editor, which moved none of 55 elements; and the size of the separator image, 0 px either way. **Not reached**: a paste goes through the parser of ProseMirror and not through the load, so a span ending in a space before a space loses the space after it when pasted as HTML. Pinned by `src/editor/code-span-text.test.ts` and the CommonMark suite. **A `br` in a line keeps the tag the file wrote** (#577): `<br>`, `<br/>`, `<br />` and the same in another case are written back as they were, with the newline after them where the file had one, where each used to become a hard break of two trailing spaces, a break many editors and linters strip as trailing whitespace; measured on 8706 files, `br` in 393 of them, 802 tags inside a line. The spelling is read from the token and carried on the hard break. A hard break the editor makes, by Shift+Enter, or a paste brings is written as two spaces as before; a `br` in a table cell is written `<br>` by the cell rule of #300 whatever the file spelled; **A trailing backslash keeps its spelling the same way since #584**: `one\`, newline, `two` comes back as it was, where it came back with two spaces, the exception *backslash hard breaks* this list used to record; 311 in 62 files of the corpus. **A `br` alone on a line between blank lines is kept too** (#584): CommonMark reads it as an HTML block, which the editor draws as a paragraph holding a hard break, and that paragraph is now written as the tags, each line after the first with its newline and indentation, where it was written as a line of two spaces, a blank line, so the next open dropped it, 566 tags in 93 files; the editor draws it as before. **What still falls back**: the indentation of the first line of such a block, which a paragraph cannot carry, 12 blocks in 12 files; and the spaces at the start of a line after any hard break, which `marked` takes with the break, CommonMark example 637. **A link keeps its title, in the delimiter the file wrote it in** (#562): `[AgentEd](https://agentedapp.com "Home")`, `'Home'` and `(Home)` are written back as they were, where the title used to leave the file on the first save, the loss #230 repaired for an image; measured on 8706 files, 283 inline link titles in 63 files, 280 in double quotes and 3 in single quotes. The title is read from the token and carried on the link, with its delimiter where it is not a double quote; an edit of the link text keeps it, and so does a new address from the link dialog; a link made in the editor has none, and a rich paste of a link with a title writes it in double quotes. The editor renders it on the link, so it shows on hover. A title read from a reference definition stays in the definition, in its delimiter, since the definition is kept (#570). **An autolink keeps its angle brackets while it is untouched** (#567): `<https://example.com>`, `<mailto:a@example.com>` and `<a@example.com>` are written back as the file wrote them, where every one used to come back as an inline link, `[https://example.com](https://example.com)`, in 317 of 1985 public files measured by AMP on #567. The spelling is read from the token and carried on the link, as the delimiter of an emphasis is; the brackets are written only while the link holds plain text that gives its address back, so a link whose text is edited, or whose address is changed in the link dialog, is written as an inline link, and so is every link made in the editor or pasted. This is not R-C13: only a link the file wrote is read this way, and a bare URL stays text. **An autolink inside an emphasis or another mark is written as an inline link**, an unedited save included: the link mark is the outermost one, so the link holds the emphasis rather than text, and the brackets would drop it; measured on 8706 files, 7 files, the same licence copied. **One more shape keeps its loss**, half of it upstream: `[foo<https://example.com/?search=](uri)>` is read by `marked` as an inline link before the autolink is seen, where CommonMark reads the autolink first, CommonMark example 526, and example 538 the same through a reference. The other half is the save: the closing angle bracket after that link is a text node of its own and is written `\>`, and GitHub reads the backslash into its autolink, `%5C`; both halves are recorded under the exception on the reading of `marked` (#605). **An empty heading, quote or list item is kept** (#564): `##`, `>` and `-` alone on their lines are written back as the markers they are, where an unedited save dropped them, and where a dropped item left a blank line in a tight list the list came back loose, `- foo`, `-`, `- bar` as two items a blank line apart. A heading is written as its hashes, with nothing after them; a quote as its marker, bare or with a space as the file spelled its blank quote lines (#199); an item as its marker, in the marker and the number its list carries (#431, #569), and an item emptied in the editor or a heading left empty is written the same way, so it reopens. Measured on 8706 files, an empty heading in 6 and an empty item in 13; in the CommonMark suite, examples 239, 281, 283 and 284 come back byte for byte. **A nested list whose first item is empty is written a blank line under the paragraph of its item** (owner decision D3 on #564): on the line directly under it a lone `-` is read back as the underline of a heading, and GitHub reads a lone asterisk, plus sign or `1.` there as text continuing the paragraph, so the blank line is the one spelling `marked` and GitHub both read as the item; the editor reads the list around it back as tight, so nothing on screen moves, and a file that spelled such a list directly under the paragraph gains the blank line once. In a checklist item the exception below applies. **A link the editor does not make live is kept as the file wrote it** (#564, owner decisions D1 and D2): a link with no text, `[](./target.md)`, rides as its bytes on the inert atom #563 made for raw HTML, not drawn, as it was never drawn; a link with no destination, `[link]()` or `[link](<>)`, and a link or an autolink whose scheme the sanitizer or the link mark does not carry, `<irc://foo.bar>`, `[chat](irc://foo.bar)`, a rustdoc path such as `alloc::borrow::Cow`, is drawn as its plain text, as before, and written back as the file spelled it while that text is unedited, byte for byte where nothing in the same mark touches it: alone in its line or among words, inside an emphasis, a strikethrough or a superscript around it alone, with a text that wraps a line, and twice side by side with the same bytes. **Where a mark around it goes on past it, or holds another link with it, the mark is written inside the brackets**, as a live link in that place is, the case of the exception for two overlapping marks below, and an autolink there is written as an inline link, as #567 writes one inside a mark: an emphasis around an `irc:` link and a letter after it comes back with the emphasis inside the link text and once more around the letter, and holds still from that save, where written around the bytes the delimiters met and the second save escaped them. Swept on the review of #587 over 954 shapes, each kind of such a link crossed with the marks around it and what touches it on each side, and bytes holding the four dollar patterns of a string replacement: every one holds still from the first save and reopens as the same document, the emphasis of a space at the link edge apart, 228 of them byte for byte; none of these shapes is in the 8706 files of the corpus. **No such link is made live**: the destination is data on the text and never an href, so nothing can follow it, and the lists of what is live are unchanged, which is why this costs no security decision. An edit of the text lets the destination go and the text is written, as an edit lets a wrapper go (#468, option i). Not kept, and written as before: a destination of the five schemes the unsafe-destination exception below names, which that exception still drops on open; and anything pasted, as no paste keeps raw HTML as bytes (R-C13). Measured on 8706 files: a link with no text in 4 files, with no destination in 17, of another scheme or a rustdoc path in 34; in the CommonMark suite, examples 484 to 487, 596, 598, 599 and 601 come back byte for byte. **A reference link and its definition are kept** (#570, owner decisions R1 to R4 and E1 to E5 of 2026-10-12 on #570): `[the docs][docs]`, `[docs][]`, `[docs]` and an image written so come back in the spelling the file gave them, and each definition, `[docs]: https://example.com "Title"`, comes back as its lines, where it stood, a definition no link uses, a second definition of one label and one inside a quote included, where every reference link was written inline and every definition removed, in 1188 of 8706 files measured on the step zero. **A definition is drawn as the lines the file holds**, as a footnote definition is (R-C17), and is edited there; it is read by the tokenizer of `marked` itself, so the links resolve as before. **A link is written as its reference whenever its label names a definition in the document at save**, the definitions read again as they then stand, so an address changed in a definition is the address of its links on the next open, while the screen and Ctrl+click keep the old one until then (E4); a link whose label names no definition at save, copied without it, its definition deleted or edited into something else, is written inline with its address, so no reference to nothing reaches the file (R2). A collapsed or shortcut link whose text no longer reads as its label is written as a full reference (E1); a link given a new address in the link dialog is written inline (E2, R-C1); a definition whose last link is deleted stays (E3); a link made in the editor is inline (E5). **A reference link pasted keeps its spelling only where its label names, in the document it lands in, a definition with the address the link holds**, the first definition of that label being the one read, and is otherwise written inline with its own address (review 5491435367 on #589): a copy inside one window carries the spelling, and pasted into a document defining the label to another address it was reopened at that address. A label that wraps a line is written once, as the file wrote it; a collapsed or shortcut link inside an emphasis is written as a full reference with the emphasis inside its brackets, as a live link there is under the exception for two overlapping marks, where it lost the emphasis until the review of #589. A reference to a destination the editor does not make live, `irc:` or a rustdoc path, is kept by the route above for such links (R3). What is still respelled is recorded below. The loose list was the first exception recorded here, and #28 repaired it; what that exception used to hide is recorded below. **Two blocks the file wrote one directly under the other stay that way** (#568, owner decisions of 2026-10-12 on the step zero): a heading over a paragraph, a paragraph over a list, a fence over a paragraph, at the top level, in a quote and in a list item. Every such pair used to be written a blank line apart, in 2667 of the 8706 files the step zero read. The adjacency is read while the file is parsed — no `space` token between the two blocks, and no blank line at the end of the first one's raw, the two places `marked` shows a gap — and rides on the lower block as an attribute, which follows the block through an edit (owner decision D3). A block the editor makes, by Enter, Insert or a paste, carries none and is written a blank line apart, as every block was before; Enter takes the flag off the second half of the block it splits wherever the caret stands, at its start, in its middle or at its end, in a paragraph, a heading, a quote or a list item (#594). At save each flagged pair is written adjacent only where its two blocks, read alone by the same lexer, read back as the same two blocks; then the whole document is read once, and where it does not read the same it is written with every blank line, as before #568 (owner decision D1). So a heading turned into a paragraph is written a blank line from the paragraph under it, which it would otherwise join. **A run of two or more blank lines between two blocks is kept** (#590, D2 of #568, owner decisions E1 to E6 of 2026-10-13): the same attribute carries its count, empty for no blank line, absent for one, a number from 2 up to 1000 for a run, and in a list item 1 for the one blank line the file wrote there (#601), a longer run being written as 1000 blank lines and holding still from there, and the save writes that many blank lines in the spelling the container gives a blank line, at the top level, in a quote and in a list item. The count is read from three places: a `space` token between the two blocks; the end of the raw of the block above, for a heading, an indented code block, a table, an HTML block or a definition; and, after a raw HTML block whose bytes are kept, only the line breaks after its last character, since its bytes already hold the lines of spaces at its end. - **R-C3 File operations & the no-silent-write invariant.** New, Open, Save, Save As, Close — every destructive path routes through the unsaved-changes safety gate, **explicitly including window close and app quit**. The editor **never writes to disk without an explicit user save decision**: closing with unsaved changes always asks (save / discard / cancel). **A save that does not happen says so** (#171): where the document could not be written — the file held open by another program, a read-only file, a full or disconnected volume — AgentEd reports it in a modal that names the operating system's own reason and the steps measured to work from there, and the document stays **modified**, so the unsaved-changes gate stays in front of work that reached no disk. **The mark follows the saved state** (#441, owner decision of 2026-09-26): the document is modified exactly when its content or its metadata differs from what was last saved or opened, or a save left images unwritten. So an undo or a hand edit back to the saved state clears the mark and the gate stops asking, images a save could not write keep it on through any undo, and a keystroke that lands while a save is being written is not counted as saved. **The silence belongs to the save that succeeded**: a save that worked shows nothing at all, which is what lets the report mean something. See D3 in §10 for the currently observed violation. **AgentEd reads and writes UTF-8, and a file that is not valid UTF-8 does not open** (#259): the document is left alone and AgentEd says, in plain words, that it cannot read the file and why. There is no encoding selector, no detection menu and no per-file setting — those are the modes §1 refuses — and no offer to convert anything, because rescuing a legacy encoding is a different product from this one. The refusal is what keeps the no-data-loss promise reachable: measured before it existed, such a file opened with its unreadable characters replaced on screen, and saving wrote those replacements over the original, with opening and saving enough to do it and no edit required. The cost is accepted rather than hidden: a folder of legacy notes is a folder AgentEd will not show, which is a real loss against the fast-viewer promise in Q2 and the reason the message has to explain itself rather than merely refuse. **A file whose raw HTML would cut the document at open is refused the same way** (#455): the R-C2 exception for a raw HTML block that ends inside an attribute value or a comment says when, and the message names the line and the repair. **The File menu remembers the ten documents most recently opened** (#381, owner decision of 2026-09-19), which reverses what AgentEd said about itself until then, that it does not remember which document you had open. **Open Recent**, below Open, shows them as a card beside the menu, newest first, each by its name and as much of its folder as tells it from the others, with the full path on hover; a file opened again moves to the top rather than appearing twice, and a Windows path is compared without regard to capitals, so one file spelled two ways is one entry. Every open enters the list, whether from the picker, the files panel or the command line, and so does a document written with Save As. **Choosing one goes through the unsaved-changes gate like any other open.** A file whose folder is there and which is not leaves the list with a sentence saying so, and is looked for before the gate asks anything, so nobody is asked about their changes for a file that is gone; one that could not be reached for another reason, a disconnected drive, stays. **Clear recent files**, at the end of the card, empties the list where it is stored and not only on screen. The list stays on this machine and is sent nowhere (Q3), and nothing is reopened on launch. **The web build has no list**: there a path names a handle whose grant ends with the session, so a stored one would reach nothing, or a same-named neighbour. Each window is its own process writing the same list, which is read afresh each time it is shown; what two windows open at once do to it is not observable in the test harness.

- **R-C5 Images.** Paste / drop / Insert → Image → `assets/` folder next to the file; standard `![alt](path)` references. **Which images are drawn is named**: the Image picker offers `png`, `jpg`, `jpeg`, `gif`, `webp` and `svg`, and the display gives those six their media type, so they are drawn; another kind a file references is drawn only where the runtime recognises it by itself, which is not promised. Once per document — the point is to explain the silence, not to nag. The question is asked **once per folder**, not once per image: every image inserted before that first save is covered by the same answer, and it is asked again if a Save As moves the document somewhere the user has not agreed to. **The agreement belongs to the folder, not to the document** (#51): once the user has agreed to an `assets/` folder, every document edited in that folder in the same window inserts into it without asking again — the folder is what was agreed to, and re-asking for the file beside it reads as the application forgetting what it was told. It does not outlive the window, since R-C8 gives each window its own state, and nothing about it is written to disk. **One gesture inserts all of its images, up to a budget** (#68, #71): a paste or drop carrying three files asks once — for the destination and for the folder — and lands all three, in the order the gesture carried them. **The budget is counted in bytes, never in files** (#71): an inserted image is held in memory at roughly twice its size until the document is saved, so one gesture may carry up to **128 MB** of images — beyond that, the images that fit land in order and the rest are refused, with a message naming how many landed, how many did not, and the limit. Nothing that landed is taken back, and the user can paste the rest. A count of files was rejected as the unit because it fails in both directions: twenty screenshots refused for nothing, twenty files at the per-file cap allowed through and fatal. The two answers apply to the gesture, not to its first file: a refusal the *application* makes about one image, such as one over the size cap, concerns that image alone and the rest still land, while a cancellation the *user* makes ends the gesture, because asking the files behind it is asking the same question again. **An agreement is remembered for the folder; a refusal is not** (#66) — it cancels the gesture it was asked about, and the next one asks again, exactly as cancelling the destination picker one gesture earlier does. The asymmetry is deliberate: remembering a *yes* spares the user a repeated dialog, while remembering a *no* silently disabled images for the rest of the document, with nothing on screen and no way to change the answer. If the folder cannot be created at save time, the document is still saved and the failure is reported: AgentEd does not discard a written document for the sake of its images. **The document then stays modified until its images land** — not all of it reached the disk, so the unsaved-changes gate (R-C3) stays in front of image data that exists only in memory, and saving again retries it. Relative `assets/` paths are standard portable markdown — GitHub and every mainstream renderer resolve them (e.g. in a repo README) as long as the folder travels with the file; this is a general convention, not an AgentEd-local format. **An address names its file with its percent escapes read** (#454): `assets/my%20diagram.png` is the file `my diagram.png`, the spelling a path with a space takes in markdown and the one other tools write. One rule turns an address into a disk path for drawing the image, for writing it back on a save and for the count of R-C12, so the three cannot disagree. A malformed escape is read as the characters it is, and an escaped `/` or `\` is not read as a folder boundary. **The address itself is never rewritten**, so the file keeps its `%20` through any save (R-C2). Until #454 the loader asked the disk for the file under the escaped name, so such an image drew as missing while the files panel counted it used, and inserting the same picture again wrote a second copy. **On the web build the same flow is offered, and the same flow is what grants it what it needs** (#46): inserting an image into a document with nowhere to live asks where that document should go, and on this platform that question also acquires access to the folder — so the image lands in `assets/` beside it exactly as on the desktop. Where that access is not there, AgentEd **says so, in words that name the step that would give it** — one message per gesture, not one per image — rather than dropping the insert in the silence a user's own cancellation is entitled to. The browser requirement underneath that is stated in §7, because it belongs to the whole web build rather than to images. **A folder that cannot be read is not an empty folder** (#58): where `assets/` exists and AgentEd cannot list it, the insert is refused rather than served with a name that may already be taken — the names on disk are the only thing standing between a new image and one already there, so a failed read is not permission to guess. It speaks once for the gesture, like every cause that belongs to the document and its environment rather than to one file. A folder that does not exist **yet** is not this case: it is the ordinary state of every never-saved document since #14 and #45, and it stays silent and successful. **There is no "image document" mode**: any document can receive images at any time, with no upfront choice at creation. The first insertion triggers the flow above; an already-existing `assets/` folder is simply used — never a warning, never a block. **Naming: human-readable, never hashes.** Files that already have a name (Media under Insert, drag & drop) keep it, sanitized for portability (diacritics → ASCII, spaces → hyphens); clipboard images with no name get one derived from the document (`<document-name>-01.png`, `-02`, …). **Identity is content, never name** (#52): two *different* images that want the same name are both kept, the second gaining a numeric suffix (`diagram-2.png`) — nothing is ever overwritten — while an image whose bytes are already in `assets/` is referenced a second time instead of copied. One file, two references; replacing that file on disk later therefore changes both places it appears, which is what a shared file does. AgentEd never creates `assets/` preemptively and never deletes it — not even when the document no longer references images, **and since #249 that is what the build can do rather than what it undertakes**: the deletion capability the frontend could reach was granted to no caller and has been removed, so the promise is now mechanical. **An image can be resized with the mouse, and that size is written as inline HTML** (#27): selecting an image shows corner handles, dragging one resizes it with the aspect ratio locked — a modifier frees it — and the size is written into the file in pixels, width alone while the ratio is unchanged, so the file carries one number rather than two that can disagree. There is a minimum an image cannot be dragged past and a way back to its natural size, and a resize is **one** entry in the undo stack rather than one per pointer-move (R-C16). What this does to every image the user did **not** resize is R-C2 business and is stated there: nothing. The «Images» badge (R-C12) is derived from content and appears/disappears by itself.

- **R-C13 Predictable paste.** Pasting inserts what the user means: plain text is read as markdown, so content copied from another editor or an AI chat arrives formatted rather than as escaped source; `Ctrl+Shift+V` inserts the characters literally instead, and `Cmd+Shift+V` on macOS, where it is the chord of **Edit, Paste and Match Style** (#558): there a paste reaches the page only through an item of the menu bar carrying the chord, and until #558 none did, so the chord pasted nothing, measured on a macOS runner and by the owner on a Mac. **AgentEd never writes link syntax the user did not ask for**: a bare URL stays text whether it was pasted, typed, or opened from a file — the editor does not autolink, at any moment, so the artifact cannot reappear one keystroke after the paste. **Nor does an unedited save write markup or a link the file held as text** (#565, owner decisions D1 to D5 of 2026-10-12 on #565): a `<` or a `&` that would open markup on the next read is written with a backslash, decided by asking the inline lexer, and the block lexer where the `<` may begin a line, and for a `&` the HTML parser of the platform, so `\<br/>`, `\&ouml;`, an entity-spelled `&lt;name@example.com&gt;` and a tag of the nine of the GFM tag filter stay text, where they came back as a line break, a character, an email link and a live tag, measured on 100 of 8706 files; `a < b`, `R&D` and `&MadeUpEntity;` are written as before. A heading whose text ends with a run of hashes after a space keeps them, with a backslash; a `!` written before a link gains one, so it is not read as an image; and two links side by side with the same destination stay two, where they were joined into one, each carrying the parity of its place among the links of its block. The same escapes reach text typed in the editor and a rich paste, so a tag typed or pasted as text reopens as text. The single paste that produces a link is a URL dropped **over a selection**, which is an authoring act rather than an inference: the user chose the text and supplied the destination. It requires the clipboard to hold a URL and nothing else, and `Ctrl+Shift+V` never links. Rich HTML from the clipboard converts to clean markdown with no artifacts (no stray `http` fragments, no leftover markup) — a link the copied content genuinely had is preserved, which is not the same as inventing one. **An exponent, an index and a key the copied content held stay one** (#563): a `sup`, a `sub` or a `kbd` in rich HTML is drawn as such and written as that tag, so a formula pasted from a web page keeps its exponent in the file. A plain-text paste and `Ctrl+Shift+V` create none from text with no tag in it. **No paste keeps raw HTML as bytes** (#563, the review of #578 and the owner decision of 2026-10-11): what is kept is not drawn, so text that spelled a tag would reach the file as live markup with nothing on screen to show it; a rich or a plain-text paste drops such HTML, as before #563, and kept bytes come from a file alone.
- **R-C14 Concurrent & external change safety.** AgentEd never silently overwrites a file that changed on disk since it was opened: before every save, the file is read and compared with the text AgentEd last read from it or wrote to it; if it differs — another program, a sync service, or a second AgentEd window — the user chooses reload / overwrite / save-as. **The comparison is the file's whole text, not its timestamp** (#55): that misses no change made by a tool which preserves `mtime`, and — the half the user meets daily — invents none for a sync client that rewrote identical bytes or merely touched the file. The cost is one read of a document the editor already holds in memory and this very save is about to rewrite in full. **The dialog is itself the informed choice**: reload discards the document in the editor and says so in as many words, and does not route through the unsaved-changes gate (R-C3) a second time — that gate's own Save leads straight back into the conflict which raised the dialog, and its Discard asks the same question in vaguer words. A file that is **absent** is not a conflict — nothing is there to overwrite, and the save recreates the document — while a file AgentEd could not **read** is never reported as unchanged: it asks the same three questions, saying plainly that it could not check. A Save As destination has no recorded state to compare against and is not asked about; that path is protected by the save picker's own replace question. No lock file is ever written next to the user's documents (see §9, decision 2).

Blocks with a language show a **language label** (top-left), clickable to set or change it; the language lives in the standard markdown fence info string (e.g. ```` ```python ````). A fence with **no language** is a **plain text box** — the same bordered block with the same hover Copy button, no language label (the picker offers *Text*), and soft-wrapped lines instead of horizontal scrolling: the "prompt box" pattern familiar from AI chat interfaces, expressed as plain standard markdown. Pure editor chrome — nothing non-standard is ever written into the file. The **hover Copy button ships** (#235, owner decision of 2026-09-06, moved here from the §8 candidates): every fenced block, with a language or without, carries a small clipboard icon in its top-right corner, hidden until the block is hovered, and a click puts the **raw text of the block as the document model holds it** on the clipboard — never the rendered DOM, which carries the language label inside the same element. The icon is a ProseMirror widget decoration and an inline SVG, so it adds no dependency and has no path to the file. Two limits are part of the commitment rather than defects against it: it is a **pointer affordance**, so a keyboard user does not reach it and a touch surface would need a different one; and it **scrolls with the code**, so on a block wider than the editor it leaves the view after 685px of horizontal scroll (measured at the 720px editor width). Pinning it to the box would need a node view, which would pin the language label too and change how every fence is drawn. The **clickable language label ships** (#238, owner decision of 2026-09-07, moved here from the §8 candidates, which now hold no R-C15 chrome at all): clicking the label opens a small field holding the language the block carries, where Enter sets it, Escape leaves the block exactly as it was, and an empty field clears the language and leaves a plain text box. **A block with no language now carries a mark in that same corner** — an icon rather than a word, drawn only while the pointer is over the block, so a plain text box stays plain until it is asked; that is the owner decision, taken with both shapes built and measured in Chromium against the stylesheet, and it is what keeps the sentence above true. Two facts are the commitment rather than incidental: **what the field accepts is exactly what the typed fence accepts** (#237) — any run of characters that is neither whitespace nor a backtick — enforced by one pattern both routes are built from, because a language holding a backtick writes a fence that reopens as a paragraph and takes the block out of the file, and one holding a space is truncated to its first word; and **a change is one entry in the undo stack** (R-C16), which `closeHistory` makes a count rather than an intention. It carries the Copy button's first limit and not its second: it is a **pointer affordance**, opened only by a click, though once open its own field holds focus so Enter and Escape finish the gesture at the keyboard — a route that *starts* at the keyboard would be a menu entry rather than a second widget and is not built. The control is a plain element outside the editable tree, so nothing of it reaches the document: the widget is a decoration and the field is appended to the body. **The label draws the info string as the file spells it** (owner decision of 2026-09-07): it carried `text-transform: lowercase` from #202, which showed `python` for a file holding `Python` — the one surface still normalising a language after #237 settled that none does, found while writing the manual steps rather than by a test, because until a capital could reach the attribute the two could not differ. The markdown half of this requirement already holds: a fence with no content is written back as the fence it was, language and all (#94) — including one that is the **only** content of a blockquote or a list item, which used to take its container out of the file with it (#104). That is what makes the plain text box survive the save it used to vanish in, wherever the user put it.
- **R-C16 Undo is over the user's own edits.** Undo and redo cover the changes the user made to the document. **Undo and redo act on the document only while the document has focus: pressed in a field, on a button or with nothing focused, they never take a step out of it or put one back** (#306). Measured before it held, on Chromium and on WebView2: with focus outside the editor, Ctrl+Z first spent the steps of the focused field and then took a step out of the body, where the user was not looking — the very first press after Metadata under Insert did it. A field's own undo is untouched. Pinned by `src/editor/history-focus.test.ts`. Loading a document is not an edit the user made: undo bottoms out at the document as it was loaded, however many times it is pressed, and no document's history survives into the next one. Measured on `cd777cd`, where neither half held: the load of a document was an ordinary transaction in the undo stack, so undoing past the beginning of one's own edits emptied the document — recoverable with redo — and undoing after a switch to another document put the *previous* document's text on screen under the *new* document's path, where the next save wrote it to that file and redo could not walk it back. The routes are deliberately not listed here: every way of putting a document on screen is one, and a list would go stale silently the day a ninth is added. `src/editor/document-load.ts` is the single place they all reach, and the routes are enumerated one by one in `src/app/document-load-routes.test.ts`.
- **R-C17 Footnotes are preserved.** A document holding footnotes in the bracket form GitHub documents — `[^label]` where one is referenced, `[^label]: text` where it is defined — **opens and saves byte-identically**, and a second save moves nothing (#408, owner decision of 2026-09-21 on the #404 spike). **The editing surface stands on it** (#409, owner decisions of 2026-09-22): a footnote is **made** from a control on the floating toolbar, from **Insert → Footnote** or with **Ctrl+Alt+F** — the reference lands after the selection, which stays where it is, the definition goes at the **end of the document**, and the label is the **smallest free number**, the next one where that is taken. GitHub collects every definition into one section at the end whatever the file does, measured through `gh api markdown`, so where the definition sits costs the reader nothing. **Both halves are one transaction, so one press of undo takes the pair back** (R-C16), and **deleting one half leaves the other**, which is the pair of orphan shapes this requirement already preserves. **A reference shows the note it points at under the pointer**, from a bounded walk of the document on each change of it, drawn as a decoration — so it exists in the view and nowhere in the document model, and nothing of it can reach a file. It is a **pointer affordance** and says so, the limit R-C15 records for the Copy button on a fenced block; what a keyboard reaches is the definition itself, which is drawn as the markdown the file holds, where the file holds it, and is edited there. **The editor shows labels, never numbers**: a number would have to be computed from the order of the references and would take the label off the screen, which is the only thing tying a reference to the definition a person may be editing by hand. **Where a footnote cannot be made the route says so rather than doing nothing**: inside a fenced block, inside a definition, over a whole-document selection and over a cell selection, the toolbar does not draw the control — the shape the image description took — and the menu entry is greyed. The last two were driven rather than reasoned (#409, second head): after Ctrl+A the reference was written at the end of the document and fitted into **a paragraph of its own**, referring to none of what was selected, and over a cell selection it wrote **raw HTML into the cell**, `| one | two<p>[^1]</p> |`, which held still on the second save rather than healing. The toolbar is hidden at a bare caret, measured at 0 px wide, so **the menu entry and the chord are the routes with nothing selected**. **What it repairs is damage rather than an absence**, measured on `7cd4984` and again on `651bb40`: `marked` read a definition as a link reference definition, so `[^a]: https://example.com` was consumed at parse and the reference came back as `[^a](https://example.com)` — **a working link to a destination the file never linked to** — while a definition whose body did not parse as a destination came back escaped, `\[^a\]: …`, and two definitions on consecutive lines were joined into one escaped line. The rows this names, each with its before: a definition whose body is a URL, one word or several words; **a definition continued on indented lines, which keeps its indentation**; **two definitions on consecutive lines, which stay two lines**; the label kept exactly as written and never renumbered, so `[^margin-standard]` stays itself; the definition kept where the file put it, the middle of a document included; a reference in a paragraph, a list item and a table cell; and all of it after an unrelated edit elsewhere. **Four shapes GitHub does not render as footnotes are preserved too, because this is about the file rather than the rendering**: a reference with no definition, which GitHub draws as literal text; a definition nobody references, which GitHub draws not at all; and two definitions sharing a label, or labels differing only in case, which GitHub collapses onto one — **both of those lose a definition's text from the file today**, which is content loss rather than respelling. **The construct is called a footnote**, the familiar word over the typographically exact *endnote*, the line CLAUDE.md already draws with «Metadata» over frontmatter. **No new runtime dependency**: the tokenizer is written here, where `parse.ts` already extends `marked`, and `marked-footnote` at 68 394 bytes was declined. **One thing is deliberately unchanged and pinned as a regression row**: the Obsidian inline form `^[text]`, which is escaped today, loses nothing and renders identically on GitHub. One case moved with #605: brackets right before and after a bare URL, `^[https://example.com/x]`, are written as the file wrote them, since GitHub took the backslash of `\]` into the address. **Reference-style links**, pinned here as they were written until #570, are kept since #570 as R-C2 says, read beside this tokenizer rather than through it: a label opening with `^` is a footnote's and never a reference definition. **The gap between two definitions is the file's to spell** (#418, owner decision of 2026-09-23): a run written a blank line apart comes back a blank line apart, one written consecutively stays consecutive, and a run spelled both ways keeps both — before this, two definitions a blank line apart came back one newline apart and a mixed run was levelled to the tighter spelling, losing the distinction rather than a blank line. The spelling travels on the definition above the gap, read from the trailing blank line `marked` leaves in its `raw`, the way the continuation indentation already travels. **Two or more blank lines between definitions are kept** (#590, owner decision E5): `marked` ends the raw of the definition above at a single newline and puts the rest of the run in a token of its own, which the adjacency carrier of R-C2 counts; the definition below carries the count, and the definition rule writes the blank line the run is written from. Measured on the 8706 files of the corpus: none holds a run between two footnote definitions. **One difference is recorded rather than repaired**: a reference the file spelled escaped, `\[^a\]`, comes back unescaped **where it sits inside a sentence**, because after a load it is the same text node as a bare one and only one of the two can be written back — the R-C2 exception above says why, and why keeping the escaped spelling would break the orphan reference this requirement promises. **At the start of a line followed by a colon the escape is kept**, since there the unescaped spelling would be a definition rather than the text the file wrote, and the line is no longer torn into a stray backslash paragraph plus a definition the way it was on `297874c`. **The start of a line is exactly that since #409, and it used to mean the start of a text node**: after bold, italic, a code span or a link, a text node still begins at offset 0, so a reference to a defined footnote written there was escaped and stopped being a footnote — measured through `gh api markdown`, the escaped spelling renders as literal text with no footnote section at all. A heading and a table cell were escaped for the same reason and neither can hold a definition. The escape now **marks** such a reference and the answer is given where the assembled line is readable, in `htmlToMarkdown`: at the start of a line, allowing the markers a list item or a blockquote writes in front of its content, since a definition is read back inside both. Held by `src/editor/footnote-round-trip.test.ts`, `src/editor/markdown/footnote-escaped-line.test.ts`, `src/editor/markdown/footnote-reference-position.test.ts`, `src/editor/footnote-insert.test.ts` and `src/editor/footnote-hover.test.ts`.
- **R-C18 New from Template.** Two plain markdown seeds, offered in a gallery: **Blank Document**, which creates an empty document, and **Document with Metadata**, the same with a block at the top for title, description, author, date and tags, and a `# Untitled` heading. **Recorded as R-A3 until #403**, and moved here because a gallery of plain markdown seeds is not an AI-era layer and a blank document least of all. **README, project document and meeting note left at #403**, owner decision of 2026-09-21 - **a product decision rather than the removal of machinery**, since none of the three came from the Skills concept: three seeds that each guessed at a shape gave way to two that say what a markdown file can be. **The explanation lives on the gallery card and nowhere else**, which is the whole of the change to what the person reads: the document created holds what they asked for and not a sentence about itself, so the metadata seed writes its block and its heading with no explanatory lines under them. Measured in Chromium at the 600x400 minimum window: the two cards, whose texts are longer, **do not scroll**, where the four shorter ones scrolled by 80 px, and no card text is cut or lost to a wrap at that size or at 1200x800. The card texts are owner-approved word for word and are read by the gallery from `src/templates/index.ts`, the one address they live at. **Blank Document leaves the document unmarked, as File then New does**, because a seed with nothing in it has nothing unsaved to warn about; a seed with content marks it. **Insert Metadata (R-C10) writes the same block, read from this template rather than restated**, so the two routes cannot drift apart. ## 6. Quality requirements

- **Q1 Size**: Windows installer stays in the ~3 MB class: 2621335 bytes on `9779aac`. Two builds of byte-identical input differ by about 2.5 KB (#309), so a change of a few KB is judged on the embedded figure rather than on the installer.
- **Q2 Startup**: opens in under ~2 s on typical hardware; usable as a fast viewer.
- **Q3 Offline**: AgentEd makes no network calls of its own. No telemetry, no update check, no account, nothing sent anywhere; every feature works with the machine offline. What the application cannot speak for is the embedded web runtime the platform gives it — the system component that draws its window. On Windows that runtime is Microsoft WebView2, and two of its behaviours have been measured. **At every launch it contacts Microsoft on its own schedule**, with the application open and untouched: two destinations, reached by three connections, alongside four loopback sockets that leave no machine — the unit is written out because the earlier record gave the figure without one. **And it speculatively looks up the links in the open document**: when the pointer enters a link, the hostname of that link reaches a resolver before any click, and a connection to it follows at mousedown. An ordinary gesture over an ordinary document therefore tells a resolver the hostname of each link the pointer enters, with nothing clicked. That is the Chromium network predictor inside the runtime; nothing in this repository asks for it, there is no `preconnect`, `prefetch` or `dns-prefetch` anywhere in it, and the precondition is simply that links are real anchor elements, which is what R-C1 describes. **Neither is something this application can turn off**, and the second was measured rather than assumed: the candidate remedy, a browser argument disabling the predictor, was built and run and changed nothing, because the behaviour hangs on a browser preference rather than on a feature name a command line reaches. All of it belongs to the runtime rather than to AgentEd, and the headline above is unaffected — the lookup is the runtime speculating over a document AgentEd rendered, not a call AgentEd makes. **Since #435 the runtime is started with the languages the person set in Windows** (R-C9), which a browser sends as the language it prefers; whether the two launch requests carry them was not measured. Measured on `3f47f20`, and the lookup reproduced in two sessions on `8aa2731` and `35353a7` with the instrument named there (#218). The runtimes of the other targets §7 builds have not been measured.
- **Q4 Stability**: no data loss — the safety-gate invariant (R-C3) and the no-silent-overwrite invariant (R-C14) are non-negotiable, **and what a person saved is what the next open shows: a construct the editor lets a person make is one the file can hold** (#300).
- **Q5 Supportability**: the application states its own version and build commit, reachable in at most two clicks and copyable in one, so that any report can be tied to the exact build it came from. A build produced outside CI says so plainly rather than showing a commit it cannot know. This is stated *to* the user, never sent anywhere — Q3 stands.

## 7. Platforms & delivery

- **Repository**: `github.com/cgxopen/AgentEd` (born clean at the reset). Prior history lives in the private `agented-archive`.
- **Primary target: Windows** (`.exe` installer).
- **The web build is a development and CI surface and a PWA precursor, rather than a shipped target** (owner decision, 2026-08-30). It stays in the repository with four roles and nothing beyond them: it is **the CI and test surface**, over which the suite runs and goes on running; it is **the editor core running in a browser**; it is what holds the `src/platform` discipline to account, and that discipline is what keeps future targets feasible; and it is **a PWA precursor**, mobile being the parked phase in §8 and mobile being web. One root decided this rather than a list of complaints: **a browser does not treat a path as an identity, and does not treat a permission as durable.** The first of those is closed, with a boundary in code (#126, #141, #144, #149). The second — the **lifecycle of a folder grant** — is structural rather than repairable: a grant is acquired by a gesture, evaporates without notice, does not reach a document already open, and cannot be renewed without another gesture. Permission friction on desktop-web is a property of the platform, not a defect in this build. Alternatives were weighed rather than dismissed: a foreign cloud such as Drive costs an account, a network dependency and a different product from the one §1 and §5 describe; an own server is clean technically and gated on demand nobody has validated; and a mobile PWA does not carry the desktop-web grant model in the same shape — see the measurement in §8, which is narrower than it first looked. **What the rest of this section therefore is**: a description of that surface and of what the build does on it, rather than a commitment to the user of a shipped one.
- **The web build requires a browser with the File System Access API**, which today means a Chromium-based browser (#46). Opening a document, choosing where to save one, and everything that writes beside it all rest on that API, so this is a property of the **whole web build** rather than of any one feature — Firefox has neither `showOpenFilePicker` nor `showSaveFilePicker`, and the build then loads and edits but cannot reach the disk at all. It also needs a **secure context**: `https://` or `localhost`, never a bare host or IP, or the pickers are absent exactly as they are in Firefox. The desktop build depends on none of this and remains the primary target. Since the re-framing above, which browsers the surface runs in is a development note rather than a statement the README owes its readers before publication; it stays on the #20 checklist as the former.
- **On the web a folder grant is a separate act, and most of the build does not need one.** `showOpenFilePicker` hands the session a handle on the picked **file** and nothing else, so the core loop — open a `.md`, edit it, save it back — works with no folder granted at all, as does the external-change check for that document. What needs a folder is what looks *beside* it: the sidebar (R-C6) and **resolving a document's images** (R-C5), whose `assets/` references live in that folder. **Only Save As grants one**, since it is the one flow that calls the directory picker, and R-C6's panel offers the picker where it would otherwise be silently absent. **A save also costs a browser permission prompt**, once per file, the first time AgentEd writes through a handle the user picked — the browser's own, not AgentEd's. Measured on `eff353c` (#184).
- **Platform abstraction**: file access and OS integration stay behind the existing platform layer (`src/platform`), so future targets (PWA, mobile) remain feasible without re-architecture.
- **Linux is a contributor lane, not a shipped target** (owner decision, 2026-09-06, on #8). It exists so that someone arriving with a Linux machine finds a build that runs and an artifact to check against — not so that a Linux user is handed a product. The distinction is load-bearing rather than cautious: **this project ships what its owner has tested**, and since 2026-09-30 the owner has tested Linux only under WSL 2 on his Windows laptop (#20), not on a Linux desktop of his own. Two consequences are recorded rather than repaired, and both become defects on the day Linux turns user-facing. The packaged desktop entry declares `MimeType=text/markdown` while its `Exec=` carries no field code, so a file manager cannot hand a document to the application and **R-C11's file association is not honoured on this target** — the CLI half is, `src-tauri/src/main.rs` reading `argv` at startup. And the deb declares `libwebkit2gtk-4.1-0` and `libgtk-3-0` and nothing about libc, while the binary requires the glibc of whatever built it, so an install on too old a distribution succeeds and the launch fails on a missing symbol. Both measured on #8, on `468cd05`.
- **CI on push/PR**: lint + unit tests on Linux runner (covers the web app) + Windows build. **No Linux bundle here, deliberately**: the Rust job already compiles the whole crate graph for Linux on every code change, so what a bundle job would add is packaging failure — which arrives with a runner image or an upstream tool rather than with a commit, and is therefore nightly's to catch. Measured on #8: a full run is 16 billable minutes and a per-pull-request Linux bundle was estimated at 5 to 8 more, on every code change, for a class of defect that does not come from code.
- **Nightly**: **Windows and Linux**, skipped when there are no new commits since the last successful run; artifact retention 7 days. macOS is available here on explicit manual request only. This is the only place Linux is built on a schedule, and before #8 it was built nowhere — both the nightly and release entries existed for weeks and neither had ever executed.
- **Release (`v*` tags)**: **Windows and macOS (Apple Silicon).** **macOS is a preview** (owner decisions of 2026-10-06 on #538). The `.dmg` is built for Apple Silicon alone, since the Macs it is tested on are Apple Silicon and this project ships what its owner has tested. It is **ad-hoc signed over the whole bundle and not notarized**: no certificate is involved, and Gatekeeper is expected to ask the user to allow it once in Privacy & Security before it opens, which was read on #538 and is first seen on the `v0.2.0-preview.4` test. Notarization, which removes that step, needs a paid Apple developer certificate. It is tested on a cloud Mac at a preview rather than on every change, and nightly builds it only on request. Every release checks the `.dmg` it uploads on the runner (#555): `AgentEd.app` copied out of the mounted image, its signature verified over the whole bundle and found ad hoc, and the copy started and found running; Gatekeeper and the first-launch prompt are not covered, since a file built on the runner carries no quarantine attribute, so the test on a Mac stays. Linux is **nightly only until it turns user-facing** — a release hands a user a product, and the lane bullet above says this is not one yet. It returns when it becomes a shipped target, and what that takes is the list in the lane bullet: a Linux desktop to test on, R-C11 honoured, and a distribution floor declared (#550).

## 8. Roadmap after reset

- **Pre-public, committed**: empty — everything this column carried is done.
- **Pre-public, candidates** (owner-prioritized): copy-any-block on hover (copy any paragraph/table/section as markdown or as formatted rich text — pure UI, file untouched); performance/polish pass, first-run experience. **R-C15 chrome has left this list entirely**: the hover **Copy** button on 2026-09-06 (#235) and the **clickable** language picker on 2026-09-07 (#238), the last of it, which had been carried here since 2026-08-24. Both ship in R-C15.
- **Post-public phases (parked)**: **PWA / installable mobile web app** — strategic rationale worth preserving: foldable phones make real document editing on mobile viable for the first time, and a few-MB offline WYSIWYG editor is the right shape for that segment, standing in for heavyweight document formats on text-first documents; kept feasible by the platform-abstraction rule in §7. **PWA distribution is also the only free route for a solo developer** — no store accounts, no native builds. The browser file-access limits, iOS especially, were the open question here and are now measured rather than owed. On mobile the file model differs by platform rather than being absent. Chrome for Android has had the File System Access pickers since v151, with documented gaps — MIME filters ignored, save-as unable to create a new file — while iOS has none in any browser, every iOS browser being WebKit. So a PWA phase decides its file model per platform: grants where they exist, share-in and share-out or an OPFS space where they do not. Measured 2026-08-30, and the aggregated compatibility entry disagreed with the per-method data; the second was taken, the first being a lagging summary of it. **An OPFS space is a vault in all but name** — files invisible in the user's own filesystem, which §5 lists as a non-goal — so the phase would have to choose explicitly between *one file at a time, no vault* and *its own space, with the changed promise acknowledged on that platform*, and the measurement makes that choice sharper rather than softer: if iOS pushes toward OPFS and Android does not, it is decided per platform rather than once. None of this schedules the phase — parked is what it stays, and what is written here is the rationale it would begin from rather than a plan. **Sealed document archive (export)** — a single-file, zip-based container bundling the markdown + its `assets/`, optionally signed: one-file sharing plus PDF-like finality through signing; if ever pursued, strictly an *export* format — the working format stays plain `.md` (naming note: `.mdx` is already taken by MDX = Markdown + JSX). Also parked: native mobile.
- **Multi-tab editing — no longer promised, and deliberately not scheduled** (owner decision, 2026-08-24). It was *Pre-public, committed* until this amendment. It is not moved to a later phase, because a phase is still a promise: it is removed from the roadmap entirely and from the README in the same amendment, so it can be built on a branch, tried, and kept or discarded without anyone having been told to expect it. Three reasons, in the order they weighed. **R-C8 already answers the underlying need** — multiple isolated windows, one file each — so tabs would be a second mechanism for a question that has an answer, which is the opposite of the simplicity this product is built on. **Three of its four open questions cannot be answered on paper**: whether the unsaved-changes gate is per tab or global, what a session is and whether tabs reopen on launch — which would persist which documents were open and reopen them, touching the *no vault, no account* promise further than the one state of that kind AgentEd keeps, the recent files list of R-C3 (#381), which reopens nothing — and whether the sidebar follows the active tab. Those are settled by use, not by argument, and deciding them under the pressure of a gate is deciding them at the worst moment. **And the asymmetry decides it**: building it and disliking it costs the build; promising it and disliking it costs either a feature nobody wanted or a broken promise, and after publication a removal is a regression with a deprecation story attached. Nothing promised, nothing to take back.

## 9. Decision log (reset iteration, August 2026)

1. **Discrete document badges.** Statusbar badges («Metadata», «Images») are descriptive, not modes; silent on plain documents; plain-language wording for non-specialists.
2. **Detection over lock file** for concurrent-change safety: a lock file would pollute user folders, contradict the no-ownership promise, and misbehave in synced folders. Owner-approved.
3. **"Reading mode" toggle rejected** — it adds a mode, and modes cost simplicity. The related "sealed archive" idea was parked as an export format instead (§8).
4. **No "image mode"** — images insertable in any document at any time; `assets/` created on first use with confirmation, existing folders used silently; human-readable file names, never hashes.
5. **Text boxes are plain fences** — the "prompt box with Copy" pattern is a language-less code fence, standard markdown; no new syntax invented.
6. **History reset**: new repository born clean; complete prior history, PRs and ADR-001..034 preserved in the private `agented-archive`. License stays MIT; monetization via donations (Ko-fi + GitHub Sponsors).
7. **Paste reads markdown (R-C13, revised).** The original wording required plain text to be inserted literally, which turned pasted markdown source into escaped text (`\*\*foo\*\*`) in the file — syntax appearing because of how content arrived, the same failure class the requirement exists to prevent. `Ctrl+V` now parses; `Ctrl+Shift+V` is the literal escape hatch.
8. **The tree survives its own click (R-C6, revised).** The original wording described a panel rooted per document, which is what the code did: opening a file from the tree re-derived the root from that file, and since a clicked document rarely carries a folder of its own the panel dissolved on the only action it offered. Opening two files from one folder was therefore impossible from the panel. Owner decision, 2026-08-29: keep the root when the opened document has no adjacent structure of its own, and descend into that structure when it does — better than the old behaviour in both cases rather than better in one and worse in the other. A root the user sets deliberately was weighed and rejected as new surface, and recent files or a back affordance as a feature rather than a repair. The kept root is in-memory and per window (R-C8); nothing about it reaches disk.
