# AgentEd — Product Requirements

**Version**: 1.0 — approved by the owner on 2026-08-14. This document defines the simplified AgentEd after the August 2026 reset; any future change goes through a PR on this file.
**Supersedes**: all prior requirement documents, ADR-001..034 (archived in the private `agented-archive` repository).

---

## 1. Product statement

AgentEd is an **easy-to-use WYSIWYG markdown editor**. Open any `.md` file and edit it the way you'd expect in 2026 — no syntax in your face, no vault, no account, no cloud. A small, fast, native binary that respects your files and never claims ownership of your folders.

Quietly, in the background, AgentEd also acknowledges that a growing share of markdown is read by AI models before it is read by people — and offers lightweight instrumentation for that: a live token count and one-click access to the related context files in your project.

**Priority order when requirements conflict**: (1) ease of use → (2) speed & lightness → (3) AI-era instrumentation.

## 2. Core requirements — the editor

- **R-C1 WYSIWYG editing.** Inline formatting with no visible markdown syntax; floating toolbar on selection; markdown input rules (`#`+space → heading, `-`+space → list, ``` followed by a space or Enter → code block — optionally with a language between them, `[ ]` → task list, etc.); tables, task lists, code blocks and images edited visually. Numbered lists must number correctly across the document (see D1 in §10). **Links are made explicitly** — floating-toolbar button, `Ctrl+K`, or pasting a URL over a selection — with the same dialog changing or removing an existing one; `Ctrl`/`Cmd`+click follows a link in the system browser, while a plain click places the caret, because clicking inside a document you are editing must stay safe. **A link address is a web address (`http`, `https`, `mailto`) or a relative path to a neighbouring file (`./notes.md`, `docs/guide.md`, `#section`), and it is written exactly as typed** (#42) — no scheme is ever implied, because a bare host and a neighbouring file are indistinguishable by shape and the common case in a markdown editor is the file; a relative link is never handed to the operating system. **An inline mark and a code span coexist** (#84): a mark may span a code span, cover one exactly, or cover part of one — a file may spell all three, so the editor holds all three. Covering *part* of a span is the one shape CommonMark cannot write as a single span, so it is written as adjacent spans instead (`` `c`**`od`**`e` ``): nothing is lost, re-reading gives the same document, and the file holds still afterwards. **Owner decision, 2026-08-24**, taken on the #84 branch build with the gesture in front of him: the gesture stays available rather than being refused in the editor — it is reachable only by selecting inside a span deliberately, and refusing it would cost a rule to explain for a case that already behaves. Pinned by `NAMED CASE` in `src/editor/mark-nesting.test.ts`.
- **R-C2 Clean round-trip.** Bidirectional serialization: the file saved is plain, portable markdown; open→save with no edits must not alter the file. **A file's line conventions are part of that promise** (#79): how its lines end (`\r\n` or `\n`) and whether the last line is terminated are properties of the file, read when AgentEd opens it and re-applied to the whole text when AgentEd writes it — a document written on Windows stays a Windows file, and a file that ended with a newline still does. A document that was never read from disk — **New**, or **New from Template** — is written with `\n` and a final newline. **A list keeps the spacing the file gave it** (#28): a loose list — blank lines between its items, bullet, ordered or task alike — is written back loose, and a tight one tight, per list rather than per document. The spelling is read from the raw markdown on open, because `marked` answers CommonMark's question rather than the file's — it wraps an item body in `<p>` both when blank lines separate the items and when any one item holds more than one block — and it rides on the list node, so it survives editing, Save As and copy-paste. A list created in the editor is tight. This was the first exception recorded here and it is now repaired; what it used to hide is recorded below. **An HTML comment is kept as the bytes the file used** (#245): `marked` reads a comment and DOMPurify removes it, so the text left the file on the first save — measured at the editor level, `one <!-- note --> two` written back as `one two` and a document holding only a comment written back as nothing. The bytes now ride on an inert node inside the text, and a comment the file put on its own line keeps that line; a comment inside a fenced block stays what it always was, which is code. **The editor draws a muted mark where each one is, and hovering it shows the note** — owner decision, 2026-09-07: a comment is hidden by every renderer and AgentEd hides it too, but a node that a keystroke can remove with nothing changing on screen is a document surviving as bytes rather than as a document, and one comment in eight of a measured corpus is five lines or more. The mark is drawn by the editing view alone, so it reaches no file. **AgentEd does not offer to write one**, which is why R-C1 says nothing about comments. Any *new* exception to R-C2 must be recorded here in the same PR that introduces it — an undocumented exception is a defect.
  - **Known exception — single-tilde strikethrough.** GFM spells strikethrough with one tilde or two (`~gone~`, `~~gone~~`); `marked` parses both into the same mark, and the mark carries no memory of which delimiter the file used, so a single-tilde strike is written back with two. Same rendering everywhere, different bytes — and nothing non-standard is written. Measured in #85, pinned by tests in `src/editor/markdown/roundtrip.test.ts` and `src/editor/strikethrough.test.ts`. Preserving the single tilde would mean carrying the delimiter on the mark through the editor's document model, which is a change in serialization this exception does not justify; if the owner decides otherwise it is its own issue.
  - **Known exception — unsafe link destinations.** A link whose destination AgentEd will not carry — `javascript:`, `vbscript:`, `file:`, `data:`, `blob:` — loses that destination on open; the link text stays. Deliberate, and not tracked for a fix: such an address is never allowed into the document, so it cannot be written back out of it. Measured in #84; pinned by a test in `src/editor/link-relative.test.ts`. For `data:` and `blob:` the editor's link allow-list is the only layer that drops it — the parser admits both for images — so that allow-list is not to be replaced with a hand-written one.
  - **Known exception — mixed line endings.** A file whose lines do not all end the same way is written back with the terminator its **first** line used, throughout. Measured in #79: preserving a per-line mix would mean carrying a terminator per line through the editor's document model, which is a change in serialization this defect does not justify. Pinned by a test in `src/app/save-line-conventions.test.ts`.
  - **Known exception — a blank line at either end of the document.** A file ending in a run of blank lines is written back with exactly one final newline, and **a blank line between a metadata block and the document body is not kept either**: `---`⏎`title: x`⏎`---`⏎⏎`# Untitled` comes back as `---`⏎`title: x`⏎`---`⏎`# Untitled`. One cause at both ends — **the editor has no node for a blank line**, so the run is gone before the text is assembled; at the top, `splitFrontmatter` hands the body its leading newline and `assembleMarkdown` writes the closing `---` with a single newline after it. The single final newline the file had is preserved; the empty lines above it are not, and neither is the one below the metadata block. Rendering is identical at both ends and the file holds still after the first save. Measured at the end in #79 and at the top in #84, where the editor-level guard reached the templates for the first time; pinned by tests in `src/app/save-line-conventions.test.ts` and by a **positioned** rule in `src/editor/roundtrip.test.ts` — one that claims the blank line only directly below a closing `---` that opens the file, so a blank line lost anywhere else still fails the suite.
  - **Known exception — five table spellings AgentEd cannot hold.** Since #93 a table is written the way the file wrote it: hugged cells (`| a | b |`) or columns padded to the file's own widths — including widths wider than the content needs — with the separator row kept exactly as it was spelled, spaced or tight, three dashes or filled, filled short, alignment colons and all. `README.md` and `docs/internal/WORKFLOW.md` each round-trip with **zero** bytes attributable to tables, where an untouched save used to add 628 and 488. The spelling is read from the raw markdown on open — `marked` trims every cell, so it exists nowhere else — and rides on the table node itself, so it survives editing, Save As and copy-paste, and a table the user creates takes the spelling of the first table in the document, or hugged cells if the document has none. **Five shapes are still normalised, once, and then hold still**, re-measured after review over 1500 files, 377 of which hold a table: a table written **without outer pipes** (`a | b`) gains them; an **indented** table is written at the margin; cells written with **no spaces at all** (`|a|b|`) get one each side; a column whose rows **disagree with each other** — hand-aligned, then edited elsewhere without re-aligning — is hugged (7 files); and a column **aligned by display width rather than character count** — an `✅` or a CJK glyph padded as if it were two columns wide — is hugged (2 files), because a display width depends on the font and on Unicode tables the file does not carry, while a character count is in the file itself. The first three are what the editor's document model can represent at all; the last two are where the file's own measure and this one disagree, and preserving either would mean carrying each row's padding rather than the column's. Together they are **11 of the 377** files with tables (3%), and none of them loses anything a reader can see. Measured in #93; pinned by tests in `src/editor/markdown/table-style.test.ts`, `src/editor/markdown/roundtrip.test.ts`, `src/editor/table-style.test.ts` and `src/app/table-style-flow.test.ts` — including a **property** test, that every style the detector can produce the validator accepts, which is what a case-by-case test missed before review.
  - **Known exception — soft line breaks become spaces.** A line break *inside* a paragraph — the wrap of a hard-wrapped file — is written back as a single space: **a space, never nothing.** CommonMark reads a soft break as a space, so nothing changes when the file is rendered; the bytes do. The editor's document model has no soft-break node that could carry the wrap, and the serializer collapses it as much as the parser does — measured at both levels in #89, pinned by tests in `src/editor/soft-break.test.ts` and `src/editor/markdown/roundtrip.test.ts`. Preserving the wrap would mean carrying a soft break through the whole pipeline; if the owner ever wants wrapped paragraphs kept, that is its own issue.
  - **Known exception — backslash hard breaks.** GFM spells a hard break with two trailing spaces or with a trailing `\`; both parse to the same break, and the node carries no memory of which spelling the file used, so the backslash form is written back as two spaces. Same rendering everywhere, different bytes — the same shape as the single-tilde strikethrough above. Measured on `230b4d7` and unchanged by #89; pinned by a test in `src/editor/soft-break.test.ts`.
  - **Known exception — a blank line at the end of a fenced block.** ```` ```⏎x⏎⏎``` ```` is read by `marked` as `<pre><code>x\n</code></pre>`: the trailing blank line is gone before any AgentEd code runs, so nothing downstream can put it back. This one is **upstream**, not a decision of ours, and cannot be fixed without leaving `marked` — which is why that case is absent from the fence assertions in `src/editor/soft-break.test.ts`. Confirmed on `marked@15` with the options `src/editor/markdown/parse.ts` sets. **The same reading applies when that blank line is the block's whole content**: ```` ```⏎⏎``` ```` and ```` ```⏎``` ```` are both read as `<pre><code>\n</code></pre>`, so they are one block by the time anything of ours runs and the first is written back as the second — the shorter spelling, and then the file holds still. Measured in #94, where it became visible for the first time: until the empty block survived the save at all, there was nothing for the normalisation to show itself in. Telling the two apart would mean reading each block's spelling from the raw markdown on open and carrying it on the node — the shape #93 uses for tables — to preserve a blank line this exception already records as lost on the way in. Pinned by tests in `src/editor/markdown/empty-fence.test.ts` and `src/editor/empty-fence.test.ts`.
  - **Known exception — an escape the file did not have, added because the serializer sees one text node at a time.** A backtick in running text is written back with a backslash — `` ` `` as `` \` ``, a bare ` ``` ` quoted in prose as `` \`\`\` `` — whether or not the document holds a run that could close it. **The mechanism is not about backticks**, and the behaviour is wider than the example: a hyphen that begins a text node gets one too (`` `^` ``-anchored is written `` `^` ``\-anchored), and so does an asterisk run `marked` read as literal rather than as emphasis. **And the boundary is not the whole of it**: `[` and `]` gain a backslash wherever they sit in running text, mid-node as readily as at its start, which is the half of this mechanism the ordered-marker exception below rests on — the title used to name the boundary alone and so described the narrower case as though it were the rule. Rendering is identical in every case — re-parsing gives byte-identical HTML — and the file holds still after the first save; the bytes are what change. The reason is a **vantage point**: whether a run is syntax depends on the rest of the *block*, and the serializer's escaping is handed one text node at a time, anchored at that node's start rather than the line's. A narrowing that guessed from inside one node was measured on #96 to withhold both runs of `` a \` b **x** c \` d ``, because each looked unpaired from where it stood — and re-reading that output paired them and swallowed the bold into a code span. Escaping costs bytes; guessing costs meaning. Anyone revisiting this should change the vantage point, not the rule. Measured for backticks in #90 and for the general shape in #84, in `README.md`, `REQUIREMENTS.md` and `docs/internal/STATUS.md`; pinned by tests in `src/editor/markdown/escape.test.ts`, `src/editor/escape-noise.test.ts` and `src/editor/roundtrip.test.ts`.
  - **Known exception — a code span's delimiter run is written at the shortest width that still closes it.** A span the file wrapped in four backticks comes back wrapped in one, and its padding spaces go with it, whenever the content holds no run that short. Rendering is identical, because CommonMark pairs runs of **equal length**: a one-backtick delimiter is closed by the next one-backtick run, and a three-backtick run inside the content cannot close it. Verified by re-parsing rather than by reading the rule — both spellings give byte-identical HTML — and the file holds still after the first save. Same family as the escaping exception above, and a different mechanism: turndown builds the delimiter from the content it is handed, so the width the file used is carried nowhere and nothing at serialization time could ask for it back. Preserving it would mean carrying the run's width on the mark through the editor's document model — the shape #93 uses for a table's spelling, but per code span. Measured in #84 on `turndown@7.2.4`, in this file; pinned by a normaliser in `src/editor/roundtrip.test.ts`. **This bullet is deliberately written without a nested code span**: the first draft quoted the four-backtick spelling literally, and the editor-level guard failed on this very file because that quotation does not survive its own round trip — the shortest honest demonstration of the exception being described.
  - **Known exception — a redundant escape the file already had is not preserved where AgentEd no longer writes one.** `the foo\_bar name` is written back as `the foo_bar name`, and `## 1\. Product statement` as `## 1. Product statement`. Identical rendering, and **the file changes once and then holds still** — a second save moves nothing further. **It applies to the escapes AgentEd withholds and to no others**: `marked` consumes every backslash on the way in, but every character the serializer still escapes unconditionally — `*`, `` ` ``, `[`, `]` and the rest — gets its backslash back on the way out, so `\*not bold\*` and `` a \` b `` come back unchanged. Two escapes are withheld, each in a place where CommonMark cannot read the character as syntax: an **intraword underscore** (#90), which can neither open nor close emphasis; and the **full stop after a number that opens a heading or a table cell** (#97), since both take inline content only and no list can begin inside them. That second one is withheld *by context, not by character*: in a paragraph, a blockquote body or a list-item body the same escape is load-bearing and is still written, or `1990. It was a good year.` would come back as an ordered list starting at 1990. Losing the redundant ones cannot be avoided: by the time the text is serialized nothing knows the source had a backslash, and preserving them would mean carrying *this character was escaped* through the editor's document model per character — the shape of the line conventions in #79, but per character rather than per document. Owner decision, 2026-08-23: one normalising pass is preferable to noise added on every save, and the files most likely to hold such escapes are the ones AgentEd itself wrote before #90. Measured in #90 and #97; pinned by tests in `src/editor/markdown/roundtrip.test.ts`, `src/editor/escape-noise.test.ts` and `src/editor/numbered-heading.test.ts`.
  - **Known exception — a number that opens an *inline element* at the start of a heading or a table cell keeps its backslash.** `## **1. Bold** thing` is written back as `## **1\. Bold** thing`, and so are `## *1. x* y`, `## [1. x](https://e.com) y` and the same three shapes inside a table cell. Identical rendering, and the file holds still after the first save. The escape is as redundant there as it is in `## 1. Bold` — a heading and a GFM cell take inline content only, so no list can begin in either — but **it can only be withheld at the start of the content**, which is where turndown's rule (`[/^(\d+)\. /g, '$1\\. ']`) puts it; a number that opens an inline element sits further in. Reaching it would mean rewriting `N\.` *anywhere* in the assembled string, and that would corrupt the one place those two characters are the user's own — inside a code span (`` ## `1\. x` ``), whose text never reaches the escaping at all. **That constraint is the thing to start from**, the way the backtick exception above names its vantage point: withholding more would need a vantage point that still knows where each text node began, not a wider regular expression. Measured in #97 on `turndown@7.2.4` and `marked@15`, at both levels and stable on the second save; pinned by tests in `src/editor/markdown/roundtrip.test.ts` and `src/editor/numbered-heading.test.ts`.
  - **Known exception — two overlapping marks have exactly one nesting.** `**[text](https://e.com)**` is written back as `[**text**](https://e.com)`, and so are `*[text](url)*`, `**[t](url) tail**` (as `[**t**](url) **tail**`) and `~~[t](url)~~`; `~~**x**~~` is written back as `**~~x~~**`. Identical rendering — CommonMark spells both nestings the same way and no renderer shows a difference — and the file holds still after the first save. **The constraint is the document model, not a priority number**: ProseMirror's marks are flat and per text node, so a run of text carrying both `strong` and `link` has one HTML spelling, the one the schema ranks outermost, and the file's two spellings of the same CommonMark collapse into it on the way in. Changing the rank does not remove the difference, it **moves** it: lowering `Link`'s priority below the other marks was measured on this branch to make `**[text](url)**` survive and to break `[**text**](url)`, which the file also spells and which survives today. **That is the thing to start from** — preserving both would mean carrying the file's nesting on the marks through the editor's document model, the shape #93 uses for a table's spelling but per inline run; a change of rank is not a fix. **The half of #84 that was a fix has been made**: the `Code` mark no longer excludes every other mark and is ranked innermost, so a mark spanning — or covering — an inline code span keeps the file's own spelling instead of being split around the span or dropped (`` **bold `code` more** ``, `` **`c`** ``, `` [`c`](url) ``). Measured in #84 on `@tiptap/extension-link` and `@tiptap/extension-code` 2.27.2; pinned by tests in `src/editor/roundtrip.test.ts`, `src/editor/mark-nesting.test.ts` and `src/editor/strikethrough.test.ts`.
  - **Known exception — two paragraphs in one task item are written as one.** An item holding two paragraphs is written with its blocks one newline apart, so an item holding `a` and then `b` is saved as `- [ ] a` with `b` on the line below it, indented by two, and read back as the single paragraph `a b`. (Written that way round on purpose: the two-line spelling quoted literally does not survive this file's own round trip, which is the same lesson the backtick exception above records.) **The constraint is GFM's own**: a task item is a list item whose first block is a paragraph opening with the task marker, and the blank line that separates two paragraphs puts that marker inside a paragraph of its own — so the loose spelling that would keep the break is not a task item at all when the file is read again, and writing it would trade the paragraph break for the checkbox. **A file could not reach this shape until #28**, so the only route to it was an edit — Backspace at the start of the second item joins two items into one. That is no longer the whole of it. With the blank line *between* items preserved, the blank line *inside* one is what is left, and a file can now carry it. An item whose paragraph is followed by an indented nested task list, with blank lines on both sides of it, keeps the break before the next item and loses the one before the nested list; the four shapes where an empty task item is followed by a fence behave the same way. (Described rather than quoted, for the reason the paragraph above gives.) The mechanism is unchanged — the item's own blocks are joined one newline apart — and so is the GFM constraint above; what changed is that the shape is now reachable from a file and is therefore pinned by rows in the round-trip table rather than by an edit. Nothing is lost that a reader can see; the words are all there and the break between them is not. Everything else a task item can hold — a heading, a blockquote, a fenced block empty or full, an ordered, bullet or task list, a table, a horizontal rule, as the item's whole body or after its paragraph — round-trips byte-identically since #157, where each of them used to leave the file entirely. Measured in #157 on `@tiptap/extension-task-item` 2.27.2 and `marked@15`; pinned by tests in `src/editor/task-item-block.test.ts` and `src/editor/roundtrip.test.ts`.
  - **Known exception — a blockquote whose blank lines are spelled both ways keeps only the first spelling.** A blank line between two blocks of a quote can be written as a bare marker or as a marker and a space, and both read as the same blank line. A quote keeps whichever its file used (#199), read while the file is being parsed and carried on the quote — but one quote holds one answer, so a quote that spells one blank line bare and another with a space is written throughout the way it opened. Measured: five quoted lines spelled bare, spaced come back spelled bare, bare. Same cause and same shape as the mixed line endings above — carrying a spelling per line would mean carrying it through the document model, which is a change in serialization this does not justify. Pinned by a row in `src/editor/roundtrip.test.ts` and by `src/editor/markdown/blockquote-spacing.test.ts`.
  - **Known exception — two adjacent lists of different kinds are written a line apart.** A list whose items are not all task items cannot be held as one list, so `- [ ] a`⏎⏎`- b` is two lists in the document model and is written back `- [ ] a`⏎`- b`, losing the blank line the file had. **The tight spelling is a fixed point and the loose one is not**, which is why this is not repaired by #28: written with the blank line, the two runs read back as one loose list in which `marked` sees no task marker at all, and the document settles only on the third save — measured in #160, where `- [ ] a`⏎`- b` saved as `- [ ] a`⏎⏎`- b` and then as `- a`⏎`- b`, the checkbox gone. Every other exception here changes the file once and then holds still; that one did not. This difference used to be recorded under the loose-list exception and is stated on its own now that the exception is gone. Pinned by a row in `src/editor/roundtrip.test.ts` and by `adjacentListsOfDifferentKinds` in `src/editor/markdown/serialize.ts`.
  - **Stated position — an image resized with the mouse is written as inline HTML, and an image keeps the form its file used** (#27). This is deliberately *not* recorded as a known exception: an exception records something the pipeline cannot hold, and this is something AgentEd chooses to write. Markdown has no syntax for image dimensions — `![alt](path)` carries a source and an alt text and nothing else — so a size either persists as inline HTML, which CommonMark admits and every mainstream renderer draws, or it does not persist at all; a size that vanished on save would be worse than not offering the handle. **What follows from that is the rule about every other image**: how the file spelled an image is a property of that image, read while the file is being parsed and carried on the node, the way a list keeps its spacing and a table its columns. A reference written as `![alt](path)` is written back that way; one written as inline HTML is written back **as the bytes the file used**, attribute order, quoting, `style`, `title` and all; and a resize moves that one image onto the HTML form. **Nothing the user did not touch changes shape**, which is why this position costs no exception. The bytes are carried rather than the width and the height, and that was measured rather than preferred: of eleven spellings of one image, a canonical `<img src alt width height>` rewrite reproduces three and changes eight, so carrying the size alone would take the quoting, the ordering and every other attribute out of a file nobody edited. A width the editor cannot express — `50%`, `auto` — is spelling rather than size: no handle offers it and no reset removes it. Pinned by rows in `src/editor/roundtrip.test.ts` and by `src/editor/markdown/image-spelling.test.ts`.
  - **Known exception — an image title is written back double-quoted.** CommonMark spells the title of an image three ways — `![alt](img.png "t")`, `'t'` and `(t)` — and measured on this pipeline all three parse to the same `title` on the node, which carries no memory of which the file used; so a title written in single quotes or parentheses comes back in double quotes. Same rendering, different bytes, and the file holds still afterwards. The same shape and the same cause as the single-tilde exception above. **What it replaces was a loss rather than a respelling** (#230): the serializer read `alt` and `src` and never the title, so `![alt](img.png "the title")` was saved as `![alt](img.png)` and text the user wrote left the file on the first save. Inside the double quotes a `"` and a `\` are written with a backslash, which CommonMark reads back as the character, so a title holding either survives; a `'`, a `(` and a `)` need nothing. Removing this exception would mean carrying the delimiter the way #229 carries an image's HTML bytes — the `image` token's raw source is where it would be read — and that is its own change rather than part of repairing the loss. Pinned by rows in `src/editor/roundtrip.test.ts` and by `src/editor/markdown/image-spelling.test.ts`.
  - **Known exception — a task marker inside an ordered list is written escaped.** `1. [ ] a` is written back as `1. \[ \] a`, and `1. [x] a` as `1. \[x\] a`. Identical rendering, and the file holds still after the first save — a document already spelled that way is byte-identical. **A loose ordered list of markers now meets this exception alone** (#28). `1. [ ] a`⏎⏎`2. [ ] b` is written `1. \[ \] a`⏎⏎`2. \[ \] b`: the markers escaped, the blank line kept, and the file holds still afterwards. It used to meet this exception and the loose-list one together, which is what that pair was recorded as; with the blank line preserved there is one difference left rather than two, and it is this one. Measured on the repair rather than reasoned about, and `marked` still does not read a loose list as a task list on the way in, which is why the spelling settles where it does. Until #160 it lost the marker outright, exactly as a loose bullet task list did and for the same reason. **The constraint is the document model.** GFM allows a task marker in an ordered list; AgentEd has no node that can hold one, because `taskList` renders as a `<ul>` and marking an `<ol>` would claim a shape the serializer cannot write back. So the marker is given back as the text it was in the file before `marked` read it, and turndown escapes `[` and `]` wherever they appear. **Withholding those two backslashes is not available**, and that is the part to start from: the escape is applied to one text node at a time, and narrowing it by context was measured to cost meaning in #90 and again in #96. Reaching this one would need a vantage point that knows which brackets came from a marker, not a wider regular expression. **The alternative was worse and is what this replaces**: until #160 a two-item ordered list of markers came back as a single numbered item holding a bullet task list, indented under it — a bullet nobody typed, the second number gone, and two items collapsed into one, which loses what the user typed rather than respelling it. (Written that way round on purpose: the two-line spelling quoted literally does not survive this file's own round trip, which is the lesson the backtick exception above records.) Two other routes were measured and both drop the marker entirely. Ordered task lists as a feature were weighed and rejected as schema work. Measured in #160 on `marked@15` and `turndown@7.2.4`, at both levels and stable on the second and third save; pinned by tests in `src/editor/roundtrip.test.ts`.
- **R-C3 File operations & the no-silent-write invariant.** New, Open, Save, Save As, Close — every destructive path routes through the unsaved-changes safety gate, **explicitly including window close and app quit**. The editor **never writes to disk without an explicit user save decision**: closing with unsaved changes always asks (save / discard / cancel). **A save that does not happen says so** (#171): where the document could not be written — the file held open by another program, a read-only file, a full or disconnected volume — AgentEd reports it in a modal that names the operating system's own reason and the steps measured to work from there, and the document stays **modified**, so the unsaved-changes gate stays in front of work that reached no disk. **The silence belongs to the save that succeeded**: a save that worked shows nothing at all, which is what lets the report mean something. See D3 in §10 for the currently observed violation.
- **R-C4 Find & Replace.** Inline panel (`Ctrl+F`/`Ctrl+H`), match case / whole word / regex with safe-parse, `F3` navigation, Replace All confirmation above 50 matches. Header 🔍 button and Edit-menu entries stay.
- **R-C5 Images.** Paste / drop / Insert Media → `assets/` folder next to the file; standard `![alt](path)` references. **Drop is a route in, and nothing more** (#65): a drag carrying images inserts them exactly as a paste of the same files would — same consent, same naming, same order, same budget — and a drag carrying anything else does nothing at all. *Nothing* is arranged rather than assumed: an unhandled drop never navigates the window away from the document it is holding, whatever was dragged onto it. **Confirmation and creation happen at different moments, deliberately**: the first insertion asks, before the image is placed, and cancelling cancels the insert — but the folder itself is only created when the document is first saved, so an image put into a document that never reaches disk leaves nothing behind (#14). **Because nothing appears on disk at that moment, the document says so** (#48): once the first image lands, AgentEd states plainly that the document and its images are waiting for a save. Once per document — the point is to explain the silence, not to nag. The question is asked **once per folder**, not once per image: every image inserted before that first save is covered by the same answer, and it is asked again if a Save As moves the document somewhere the user has not agreed to. **The agreement belongs to the folder, not to the document** (#51): once the user has agreed to an `assets/` folder, every document edited in that folder in the same window inserts into it without asking again — the folder is what was agreed to, and re-asking for the file beside it reads as the application forgetting what it was told. It does not outlive the window, since R-C8 gives each window its own state, and nothing about it is written to disk. **One gesture inserts all of its images, up to a budget** (#68, #71): a paste or drop carrying three files asks once — for the destination and for the folder — and lands all three, in the order the gesture carried them. **The budget is counted in bytes, never in files** (#71): an inserted image is held in memory at roughly twice its size until the document is saved, so one gesture may carry up to **128 MB** of images — beyond that, the images that fit land in order and the rest are refused, with a message naming how many landed, how many did not, and the limit. Nothing that landed is taken back, and the user can paste the rest. A count of files was rejected as the unit because it fails in both directions: twenty screenshots refused for nothing, twenty files at the per-file cap allowed through and fatal. The two answers apply to the gesture, not to its first file: a refusal the *application* makes about one image, such as one over the size cap, concerns that image alone and the rest still land, while a cancellation the *user* makes ends the gesture, because asking the files behind it is asking the same question again. **An agreement is remembered for the folder; a refusal is not** (#66) — it cancels the gesture it was asked about, and the next one asks again, exactly as cancelling the destination picker one gesture earlier does. The asymmetry is deliberate: remembering a *yes* spares the user a repeated dialog, while remembering a *no* silently disabled images for the rest of the document, with nothing on screen and no way to change the answer. If the folder cannot be created at save time, the document is still saved and the failure is reported: AgentEd does not discard a written document for the sake of its images. **The document then stays modified until its images land** — not all of it reached the disk, so the unsaved-changes gate (R-C3) stays in front of image data that exists only in memory, and saving again retries it. Relative `assets/` paths are standard portable markdown — GitHub and every mainstream renderer resolve them (e.g. in a repo README) as long as the folder travels with the file; this is a general convention, not an AgentEd-local format. **On the web build the same flow is offered, and the same flow is what grants it what it needs** (#46): inserting an image into a document with nowhere to live asks where that document should go, and on this platform that question also acquires access to the folder — so the image lands in `assets/` beside it exactly as on the desktop. Where that access is not there, AgentEd **says so, in words that name the step that would give it** — one message per gesture, not one per image — rather than dropping the insert in the silence a user's own cancellation is entitled to. The browser requirement underneath that is stated in §7, because it belongs to the whole web build rather than to images. **A folder that cannot be read is not an empty folder** (#58): where `assets/` exists and AgentEd cannot list it, the insert is refused rather than served with a name that may already be taken — the names on disk are the only thing standing between a new image and one already there, so a failed read is not permission to guess. It speaks once for the gesture, like every cause that belongs to the document and its environment rather than to one file. A folder that does not exist **yet** is not this case: it is the ordinary state of every never-saved document since #14 and #45, and it stays silent and successful. **There is no "image document" mode**: any document can receive images at any time, with no upfront choice at creation. The first insertion triggers the flow above; an already-existing `assets/` folder is simply used — never a warning, never a block. **Naming: human-readable, never hashes.** Files that already have a name (Insert Media, drag & drop) keep it, sanitized for portability (diacritics → ASCII, spaces → hyphens); clipboard images with no name get one derived from the document (`<document-name>-01.png`, `-02`, …). **Identity is content, never name** (#52): two *different* images that want the same name are both kept, the second gaining a numeric suffix (`diagram-2.png`) — nothing is ever overwritten — while an image whose bytes are already in `assets/` is referenced a second time instead of copied. One file, two references; replacing that file on disk later therefore changes both places it appears, which is what a shared file does. AgentEd never creates `assets/` preemptively and never deletes it — not even when the document no longer references images, **and since #249 that is what the build can do rather than what it undertakes**: the deletion capability the frontend could reach was granted to no caller and has been removed, so the promise is now mechanical. **An image can be resized with the mouse, and that size is written as inline HTML** (#27): selecting an image shows corner handles, dragging one resizes it with the aspect ratio locked — a modifier frees it — and the size is written into the file in pixels, width alone while the ratio is unchanged, so the file carries one number rather than two that can disagree. There is a minimum an image cannot be dragged past and a way back to its natural size, and a resize is **one** entry in the undo stack rather than one per pointer-move (R-C16). What this does to every image the user did **not** resize is R-C2 business and is stated there: nothing. The «Images» badge (R-C12) is derived from content and appears/disappears by itself.
- **R-C6 Sidebar.** Recursive tree when the document has adjacent structure — and **in the browser, only once a folder has been granted**, since without one AgentEd cannot see what sits beside the document at all; where that is why the tree is missing, the panel says so and offers to ask for a folder, and where a granted folder simply holds nothing adjacent it stays silent — unless the user has just asked for that folder, when the answer is given rather than withheld; markdown files switch focus through the safety gate. **What a non-markdown entry does depends on the platform**: on the desktop it opens with the OS default app, and in the browser it is present but inert — no pointer, no hover, no response to a click — because nothing there can hand a file to the host system, with the reason on demand in its tooltip. **What the desktop opens is the extensions the shell scope lists, and `svg` is deliberately not one of them** (#249): the handler for an `.svg` on Windows is a browser, so open would mean executing whatever script the document carries — measured on 2026-09-07 — and a click on one now does what a click on any unlisted extension does, which is nothing. A document opened **from the tree** keeps that tree, unless it carries adjacent structure of its own, in which case the panel moves there; opened any other way it re-derives the root, and what makes the panel appear in the first place is unchanged.
- **R-C7 Themes.** Light / Dark / Auto mode + curated palettes, persisted across sessions, selected from the kebab (⋮) menu.
- **R-C8 Multi-window.** Multiple isolated instances; each with its own file and edit history. Two windows opening the same file fall under R-C14.
- **R-C9 Spell-check off by default**, session toggle in the statusbar.
- **R-C10 Keyboard shortcuts** as currently shipped (README table carries over).
- **R-C11 OS integration.** File association and CLI open.
- **R-C12 Statusbar contents.** Token count, word count, character count, and the spell toggle. **Document-kind badges appear only when the document warrants them**: a **«Metadata»** badge when a frontmatter block is present, an **«Images»** badge when the document references images/assets — combinable, each with a tooltip explaining in plain words (e.g. *"This document starts with a metadata block (YAML frontmatter)"*). A plain document shows **no badge at all** — the statusbar stays clean for the common case. User-facing wording avoids jargon (**"Metadata"**, not "Frontmatter"). Badges are purely descriptive: no validation attached, nothing ever blocked. Clicking the «Images» badge opens a small informative popover — how many images this document uses and how many other files the shared `assets/` folder holds (e.g. *"3 images used by this document · assets/ holds 9 more files"*). Information on demand, never a permanent warning: a shared `assets/` folder is the normal markdown convention, not a problem state. **The second number is not always available, and the popover says which of the three it is rather than guessing a count** (#196): the folder may not be there, the document may never have been saved — `assets/` is created by the save and not before (#14) — or nothing could be established about it, because it is there and shut (#58) or because the browser session holds no grant for it (#184). *Nothing could be established* is never reported as an empty folder, which is the one wrong answer available here.
- **R-C13 Predictable paste.** Pasting inserts what the user means: plain text is read as markdown, so content copied from another editor or an AI chat arrives formatted rather than as escaped source; `Ctrl+Shift+V` inserts the characters literally instead. **AgentEd never writes link syntax the user did not ask for**: a bare URL stays text whether it was pasted, typed, or opened from a file — the editor does not autolink, at any moment, so the artifact cannot reappear one keystroke after the paste. The single paste that produces a link is a URL dropped **over a selection**, which is an authoring act rather than an inference: the user chose the text and supplied the destination. It requires the clipboard to hold a URL and nothing else, and `Ctrl+Shift+V` never links. Rich HTML from the clipboard converts to clean markdown with no artifacts (no stray `http` fragments, no leftover markup) — a link the copied content genuinely had is preserved, which is not the same as inventing one.
- **R-C14 Concurrent & external change safety.** AgentEd never silently overwrites a file that changed on disk since it was opened: before every save, the file is read and compared with the text AgentEd last read from it or wrote to it; if it differs — another program, a sync service, or a second AgentEd window — the user chooses reload / overwrite / save-as. **The comparison is the file's whole text, not its timestamp** (#55): that misses no change made by a tool which preserves `mtime`, and — the half the user meets daily — invents none for a sync client that rewrote identical bytes or merely touched the file. The cost is one read of a document the editor already holds in memory and this very save is about to rewrite in full. **The dialog is itself the informed choice**: reload discards the document in the editor and says so in as many words, and does not route through the unsaved-changes gate (R-C3) a second time — that gate's own Save leads straight back into the conflict which raised the dialog, and its Discard asks the same question in vaguer words. A file that is **absent** is not a conflict — nothing is there to overwrite, and the save recreates the document — while a file AgentEd could not **read** is never reported as unchanged: it asks the same three questions, saying plainly that it could not check. A Save As destination has no recorded state to compare against and is not asked about; that path is protected by the save picker's own replace question. No lock file is ever written next to the user's documents (see §9, decision 2).
- **R-C15 Code & text block affordances.** Fenced blocks show, on hover, a **Copy** button (top-right) copying the raw contents to the clipboard. Blocks with a language show a **language label** (top-left), clickable to set or change it; the language lives in the standard markdown fence info string (e.g. ```` ```python ````). A fence with **no language** is a **plain text box** — the same bordered block with the same hover Copy button, no language label (the picker offers *Text*), and soft-wrapped lines instead of horizontal scrolling: the "prompt box" pattern familiar from AI chat interfaces, expressed as plain standard markdown. Pure editor chrome — nothing non-standard is ever written into the file. The **hover Copy button ships** (#235, owner decision of 2026-09-06, moved here from the §8 candidates): every fenced block, with a language or without, carries a small clipboard icon in its top-right corner, hidden until the block is hovered, and a click puts the **raw text of the block as the document model holds it** on the clipboard — never the rendered DOM, which carries the language label inside the same element. The icon is a ProseMirror widget decoration and an inline SVG, so it adds no dependency and has no path to the file. Two limits are part of the commitment rather than defects against it: it is a **pointer affordance**, so a keyboard user does not reach it and a touch surface would need a different one; and it **scrolls with the code**, so on a block wider than the editor it leaves the view after 685px of horizontal scroll (measured at the 720px editor width). Pinning it to the box would need a node view, which would pin the language label too and change how every fence is drawn. The **clickable language label ships** (#238, owner decision of 2026-09-07, moved here from the §8 candidates, which now hold no R-C15 chrome at all): clicking the label opens a small field holding the language the block carries, where Enter sets it, Escape leaves the block exactly as it was, and an empty field clears the language and leaves a plain text box. **A block with no language now carries a mark in that same corner** — an icon rather than a word, drawn only while the pointer is over the block, so a plain text box stays plain until it is asked; that is the owner decision, taken with both shapes built and measured in Chromium against the stylesheet, and it is what keeps the sentence above true. Two facts are the commitment rather than incidental: **what the field accepts is exactly what the typed fence accepts** (#237) — any run of characters that is neither whitespace nor a backtick — enforced by one pattern both routes are built from, because a language holding a backtick writes a fence that reopens as a paragraph and takes the block out of the file, and one holding a space is truncated to its first word; and **a change is one entry in the undo stack** (R-C16), which `closeHistory` makes a count rather than an intention. It carries the Copy button's first limit and not its second: it is a **pointer affordance**, opened only by a click, though once open its own field holds focus so Enter and Escape finish the gesture at the keyboard — a route that *starts* at the keyboard would be a menu entry rather than a second widget and is not built. The control is a plain element outside the editable tree, so nothing of it reaches the document: the widget is a decoration and the field is appended to the body. **The label draws the info string as the file spells it** (owner decision of 2026-09-07): it carried `text-transform: lowercase` from #202, which showed `python` for a file holding `Python` — the one surface still normalising a language after #237 settled that none does, found while writing the manual steps rather than by a test, because until a capital could reach the attribute the two could not differ. The markdown half of this requirement already holds: a fence with no content is written back as the fence it was, language and all (#94) — including one that is the **only** content of a blockquote or a list item, which used to take its container out of the file with it (#104). That is what makes the plain text box survive the save it used to vanish in, wherever the user put it.
- **R-C16 Undo is over the user's own edits.** Undo and redo cover the changes the user made to the document. Loading a document is not one of them: undo bottoms out at the document as it was loaded, however many times it is pressed, and no document's history survives into the next one. Measured on `cd777cd`, where neither half held: the load of a document was an ordinary transaction in the undo stack, so undoing past the beginning of one's own edits emptied the document — recoverable with redo — and undoing after a switch to another document put the *previous* document's text on screen under the *new* document's path, where the next save wrote it to that file and redo could not walk it back. The routes are deliberately not listed here: every way of putting a document on screen is one, and a list would go stale silently the day a ninth is added. `src/editor/document-load.ts` is the single place they all reach, and the routes are enumerated one by one in `src/app/document-load-routes.test.ts`.

## 3. Kept AI-era layer (secondary)

- **R-A1 Token counter.** Statusbar, `gpt-tokenizer` (cl100k_base), lazily loaded, offline, length-based fallback — alongside word and character count.
- **R-A2 Context awareness.** The 📎 *N related* indicator when opening known context files (`CLAUDE.md`, `AGENTS.md`, `.cursorrules`, …): scan up to 5 levels up plus immediate subdirectories, preview first line, one-click switch through the safety gate. **No validation attached to any of these files.** **A scan that finds nothing withdraws the indicator completely** (#130): the label and the tooltip go with the badge, and the overflow menu does not offer what has been withdrawn. **Whether it says so depends on who asked.** A scan nobody requested — on open, on a document switch — stays silent whatever it finds, because a plain document with no context files beside it was never a question, and speaking would put a message in front of every such document. A **Refresh** is a question, so a Refresh that finds nothing answers: once per press, never once per scan, and it names the way back, since the indicator and its popover are gone by then. Silence belongs to what the user already knows, not to what they asked — the same line R-C5 draws between a cancellation and a refusal.
- **R-A3 New from Template.** Gallery of four plain markdown templates: **README**, **project document**, **meeting note**, **blank + frontmatter**. Skill and llms.txt templates leave with their profiles.

## 5. Non-goals

Not a note-taking or knowledge-management app, not a wiki, not a word processor, not a code editor, not a prompt playground. No vault, no plugin ecosystem, no graph view, no wiki-links, no cloud, no account, no telemetry.

## 6. Quality requirements

- **Q1 Size**: Windows installer stays in the ~3 MB class (expected to shrink after the cut).
- **Q2 Startup**: opens in under ~2 s on typical hardware; usable as a fast viewer.
- **Q3 Offline**: AgentEd makes no network calls of its own. No telemetry, no update check, no account, nothing sent anywhere; every feature works with the machine offline. What the application cannot speak for is the embedded web runtime the platform gives it — the system component that draws its window. On Windows that runtime is Microsoft WebView2: measured on `3f47f20`, it contacts Microsoft twice at every launch, on its own schedule, with the application open and untouched. That traffic belongs to the runtime rather than to AgentEd, and it is not something this application can turn off. The runtimes of the other targets §7 builds have not been measured.
- **Q4 Stability**: no data loss — the safety-gate invariant (R-C3) and the no-silent-overwrite invariant (R-C14) are non-negotiable.
- **Q5 Supportability**: the application states its own version and build commit, reachable in at most two clicks and copyable in one, so that any report can be tied to the exact build it came from. A build produced outside CI says so plainly rather than showing a commit it cannot know. This is stated *to* the user, never sent anywhere — Q3 stands.

## 7. Platforms & delivery

- **Repository**: `github.com/catge/AgentEd` (born clean at the reset). Prior history lives in the private `agented-archive`.
- **Primary target: Windows** (`.exe` installer).
- **The web build is a development and CI surface and a PWA precursor, rather than a shipped target** (owner decision, 2026-08-30). It stays in the repository with four roles and nothing beyond them: it is **the CI and test surface**, over which the suite runs and goes on running; it is **the editor core running in a browser**; it is what holds the `src/platform` discipline to account, and that discipline is what keeps future targets feasible; and it is **a PWA precursor**, mobile being the parked phase in §8 and mobile being web. One root decided this rather than a list of complaints: **a browser does not treat a path as an identity, and does not treat a permission as durable.** The first of those is closed, with a boundary in code (#126, #141, #144, #149). The second — the **lifecycle of a folder grant** — is structural rather than repairable: a grant is acquired by a gesture, evaporates without notice, does not reach a document already open, and cannot be renewed without another gesture. Permission friction on desktop-web is a property of the platform, not a defect in this build. Alternatives were weighed rather than dismissed: a foreign cloud such as Drive costs an account, a network dependency and a different product from the one §1 and §5 describe; an own server is clean technically and gated on demand nobody has validated; and a mobile PWA does not carry the desktop-web grant model in the same shape — see the measurement in §8, which is narrower than it first looked. **What the rest of this section therefore is**: a description of that surface and of what the build does on it, rather than a commitment to the user of a shipped one.
- **The web build requires a browser with the File System Access API**, which today means a Chromium-based browser (#46). Opening a document, choosing where to save one, and everything that writes beside it all rest on that API, so this is a property of the **whole web build** rather than of any one feature — Firefox has neither `showOpenFilePicker` nor `showSaveFilePicker`, and the build then loads and edits but cannot reach the disk at all. It also needs a **secure context**: `https://` or `localhost`, never a bare host or IP, or the pickers are absent exactly as they are in Firefox. The desktop build depends on none of this and remains the primary target. Since the re-framing above, which browsers the surface runs in is a development note rather than a statement the README owes its readers before publication; it stays on the #20 checklist as the former.
- **On the web a folder grant is a separate act, and most of the build does not need one.** `showOpenFilePicker` hands the session a handle on the picked **file** and nothing else, so the core loop — open a `.md`, edit it, save it back — works with no folder granted at all, as does the external-change check for that document. What needs a folder is what looks *beside* it: the sidebar (R-C6), the context indicator (R-A2), and **resolving a document's images** (R-C5), whose `assets/` references live in that folder. **Only Save As grants one**, since it is the one flow that calls the directory picker, and R-C6's panel offers the picker where it would otherwise be silently absent. **A save also costs a browser permission prompt**, once per file, the first time AgentEd writes through a handle the user picked — the browser's own, not AgentEd's. Measured on `eff353c` (#184).
- **Platform abstraction**: file access and OS integration stay behind the existing platform layer (`src/platform`), so future targets (PWA, mobile) remain feasible without re-architecture.
- **Linux is a contributor lane, not a shipped target** (owner decision, 2026-09-06, on #8). It exists so that someone arriving with a Linux machine finds a build that runs and an artifact to check against — not so that a Linux user is handed a product. The distinction is load-bearing rather than cautious: **the owner has no Linux machine**, and this project ships what its owner has tested. Two consequences are recorded rather than repaired, and both become defects on the day Linux turns user-facing. The packaged desktop entry declares `MimeType=text/markdown` while its `Exec=` carries no field code, so a file manager cannot hand a document to the application and **R-C11's file association is not honoured on this target** — the CLI half is, `src-tauri/src/main.rs` reading `argv` at startup. And the deb declares `libwebkit2gtk-4.1-0` and `libgtk-3-0` and nothing about libc, while the binary requires the glibc of whatever built it, so an install on too old a distribution succeeds and the launch fails on a missing symbol. Both measured on #8, on `468cd05`.
- **CI on push/PR**: lint + unit tests on Linux runner (covers the web app) + Windows build. **No Linux bundle here, deliberately**: the Rust job already compiles the whole crate graph for Linux on every code change, so what a bundle job would add is packaging failure — which arrives with a runner image or an upstream tool rather than with a commit, and is therefore nightly's to catch. Measured on #8: a full run is 16 billable minutes and a per-pull-request Linux bundle was estimated at 5 to 8 more, on every code change, for a class of defect that does not come from code.
- **Nightly**: **Windows and Linux**, skipped when there are no new commits since the last successful run; artifact retention 7 days. macOS is available here on explicit manual request only. This is the only place Linux is built on a schedule, and before #8 it was built nowhere — both the nightly and release entries existed for weeks and neither had ever executed.
- **Release (`v*` tags)**: **Windows alone.** Linux is **nightly only until it turns user-facing** — a release hands a user a product, and the lane bullet above says this is not one yet. macOS is deferred for its own reason: nothing here can test it, an unsigned build reaches a user through Gatekeeper as a file that cannot be opened, and the bundle identifier ends with `.app`, which collides with the macOS application bundle extension. Each returns when it becomes a shipped target — for Linux, what that takes is the list in the lane bullet: a machine to test on, R-C11 honoured, and a distribution floor declared.

## 8. Roadmap after reset

- **Pre-public, committed**: empty — everything this column carried is done.
- **Pre-public, candidates** (owner-prioritized): copy-any-block on hover (copy any paragraph/table/section as markdown or as formatted rich text — pure UI, file untouched); performance/polish pass, first-run experience. **R-C15 chrome has left this list entirely**: the hover **Copy** button on 2026-09-06 (#235) and the **clickable** language picker on 2026-09-07 (#238), the last of it, which had been carried here since 2026-08-24. Both ship in R-C15.
- **Post-public phases (parked)**: **PWA / installable mobile web app** — strategic rationale worth preserving: foldable phones make real document editing on mobile viable for the first time, and a few-MB offline WYSIWYG editor is the right shape for that segment, standing in for heavyweight document formats on text-first documents; kept feasible by the platform-abstraction rule in §7. **PWA distribution is also the only free route for a solo developer** — no store accounts, no native builds. The browser file-access limits, iOS especially, were the open question here and are now measured rather than owed. On mobile the file model differs by platform rather than being absent. Chrome for Android has had the File System Access pickers since v151, with documented gaps — MIME filters ignored, save-as unable to create a new file — while iOS has none in any browser, every iOS browser being WebKit. So a PWA phase decides its file model per platform: grants where they exist, share-in and share-out or an OPFS space where they do not. Measured 2026-08-30, and the aggregated compatibility entry disagreed with the per-method data; the second was taken, the first being a lagging summary of it. **An OPFS space is a vault in all but name** — files invisible in the user's own filesystem, which §5 lists as a non-goal — so the phase would have to choose explicitly between *one file at a time, no vault* and *its own space, with the changed promise acknowledged on that platform*, and the measurement makes that choice sharper rather than softer: if iOS pushes toward OPFS and Android does not, it is decided per platform rather than once. None of this schedules the phase — parked is what it stays, and what is written here is the rationale it would begin from rather than a plan. **Sealed document archive (export)** — a single-file, zip-based container bundling the markdown + its `assets/`, optionally signed: one-file sharing plus PDF-like finality through signing; if ever pursued, strictly an *export* format — the working format stays plain `.md` (naming note: `.mdx` is already taken by MDX = Markdown + JSX). Also parked: skill profiles reintroduction, OKF profile, Agent View, visual frontmatter editor, native mobile.
- **Multi-tab editing — no longer promised, and deliberately not scheduled** (owner decision, 2026-08-24). It was *Pre-public, committed* until this amendment. It is not moved to a later phase, because a phase is still a promise: it is removed from the roadmap entirely and from the README in the same amendment, so it can be built on a branch, tried, and kept or discarded without anyone having been told to expect it. Three reasons, in the order they weighed. **R-C8 already answers the underlying need** — multiple isolated windows, one file each — so tabs would be a second mechanism for a question that has an answer, which is the opposite of the simplicity this product is built on. **Three of its four open questions cannot be answered on paper**: whether the unsaved-changes gate is per tab or global, what a session is and whether tabs reopen on launch — the first state AgentEd would persist about the user's work, which touches the *no vault, no account* promise — and whether the sidebar follows the active tab. Those are settled by use, not by argument, and deciding them under the pressure of a gate is deciding them at the worst moment. **And the asymmetry decides it**: building it and disliking it costs the build; promising it and disliking it costs either a feature nobody wanted or a broken promise, and after publication a removal is a regression with a deprecation story attached. Nothing promised, nothing to take back.

## 9. Decision log (reset iteration, August 2026)

1. **Discrete document badges.** Statusbar badges («Metadata», «Images») are descriptive, not modes; silent on plain documents; plain-language wording for non-specialists.
2. **Detection over lock file** for concurrent-change safety: a lock file would pollute user folders, contradict the no-ownership promise, and misbehave in synced folders. Owner-approved.
3. **"Reading mode" toggle rejected** — it adds a mode, and modes cost simplicity. The related "sealed archive" idea was parked as an export format instead (§8).
4. **No "image mode"** — images insertable in any document at any time; `assets/` created on first use with confirmation, existing folders used silently; human-readable file names, never hashes.
5. **Text boxes are plain fences** — the "prompt box with Copy" pattern is a language-less code fence, standard markdown; no new syntax invented.
6. **History reset**: new repository born clean; complete prior history, PRs and ADR-001..034 preserved in the private `agented-archive`. License stays MIT; monetization via donations (Ko-fi + GitHub Sponsors).
7. **Paste reads markdown (R-C13, revised).** The original wording required plain text to be inserted literally, which turned pasted markdown source into escaped text (`\*\*foo\*\*`) in the file — syntax appearing because of how content arrived, the same failure class the requirement exists to prevent. `Ctrl+V` now parses; `Ctrl+Shift+V` is the literal escape hatch.
8. **The tree survives its own click (R-C6, revised).** The original wording described a panel rooted per document, which is what the code did: opening a file from the tree re-derived the root from that file, and since a clicked document rarely carries a folder of its own the panel dissolved on the only action it offered. Opening two files from one folder was therefore impossible from the panel. Owner decision, 2026-08-29: keep the root when the opened document has no adjacent structure of its own, and descend into that structure when it does — better than the old behaviour in both cases rather than better in one and worse in the other. A root the user sets deliberately was weighed and rejected as new surface, and recent files or a back affordance as a feature rather than a repair. The kept root is in-memory and per window (R-C8); nothing about it reaches disk.
